## 1. 形状の表し方

### 1.1 符号つき距離関数と切り詰め

- 符号つき距離関数(SDF): 各点に、最も近い物体表面までの距離を割り当てる。何もない空間なら正、
  物体の内側なら負、表面で0。
- 測距からの統合には、**切り詰め符号つき距離関数**(TSDF: 表面の近く ±μ の帯の中だけで距離を
  持ち、帯の外は ±μ に切り詰める表し方。KinectFusion(2011)などの距離カメラの統合で標準)を使う。
  μ は切り詰め幅(提案の既定: 格子の刻み h の3倍 = 15cm)。
- 帯の外(遠くの点)の距離は、距離関数が満たす方程式 |∇φ| = 1(勾配の大きさが1)を、隣の点から
  埋める反復で求める(§1.3)。

### 1.2 格子点ごとの状態

- `d` … 統合した切り詰め距離(−μ〜+μ)
- `w` … 統合の重み(何本の光線で確かめたか。上限 w_max で頭打ちにして、古い観測も少しずつ
  入れ替わるようにする。提案の既定 w_max = 50)
- `φ` … 距離の場(界面で交換するのはこれだけ)

格子点の分類:

- **表面の近く**(w > 0 かつ |d| < μ): φ = d(観測そのもの。反復の起点になる)
- **観測済みの空き**(w > 0 かつ d = +μ): φ は反復で求める(μ 以上になるはず)
- **観測済みの裏側**(w > 0 かつ d = −μ): 物体の内側。φ は反復で求めた距離に負号を付ける
- **未観測**(w = 0): φ は反復で求める(「最も近い既知の表面までの距離」の意味になる)。
  未観測であることは w = 0 で区別でき、採点と書き出しではこの印を使う。

### 1.3 距離の反復(アイコナール方程式 |∇φ| = 1 の Jacobi 反復)

- 表面の近くの点を固定し、それ以外の点を、上下左右の隣の値から Godunov 型の風上差分
  (隣のうち小さい方の値から距離を伸ばす式)で更新する:
  - a = min(|φ_W|, |φ_E|)、b = min(|φ_S|, |φ_N|)
  - |a − b| ≥ h なら u = min(a, b) + h、そうでなければ u = (a + b + √(2h² − (a − b)²)) / 2
  - 符号は観測済みの裏側なら負、それ以外は正
- **全点を前回の値だけから同時に更新する**(Jacobi反復)。熱拡散と同じく、界面の枠に隣の
  前回の値が入るので、分割解と単一ノード解がビット一致する。
- 1ステップ=1反復。部屋の差し渡し(81点)を伝わるのに約81ステップかかる。形状は静止しているので
  実時間の制約はない(上位設計書 §4)。
- 前回の値の大小によらず更新し直すので(古い値との最小値はとらない)、観測が変わって表面が
  動いても、過大・過小どちらの古い値も反復で正しい値へ移っていく。
- 平方根は libm(純Rust)で計算する(OS間のビット一致のため)。

### 1.4 光線の統合

- 測距の1区画は1本の光線: 原点 o(センサの位置)、向き v(単位ベクトル)、測った距離 r。
- 光線上に一定間隔 δ = h/2 で標本点 s_k = k·δ(k = 0, 1, …)を取り、各標本点の**最寄りの格子点**
  p に観測値 d_obs = clamp(r − (p − o)·v, −μ, +μ) を重み1で加える(重み付き平均。w は w_max で
  頭打ち)。標本点は r + μ まで(表面の裏側の帯まで)。
  - (実装時の変更、2026-10-10)初版は d_obs = clamp(r − s_k) と**標本点の位置**で測っていたが、
    最寄りの格子点とのずれ(最大 h/√2 ≈ 3.5cm)がそのまま誤差になるため、**格子点そのものを光線へ
    投影した位置**で測るように改めた。同じ光線の続く標本点が同じ格子点に落ちた場合は1回だけ
    統合する(重みの二重計上を防ぐ)。空の部屋・雑音1cmで、表面の近くの誤差の平均が
    1.46cm → 0.89cm に下がった。
- 標本点は**光線の原点から通し番号で取る**ので、どのノードが処理しても同じ点が同じ値になる。
  各ノードは、最寄りの格子点が自分の区画にある標本点だけを処理する。
- 同じ格子点に同じステップで複数の光線が当たる場合、重み付き平均の結果は加える順序に依存する。
  そこで**統合の順序を固定する**: (取得ステップ, センサID, 区画番号, 標本番号) の昇順。
- 「対象なし」(最大距離の内側に何も無かった)の区画は、この段では**統合しない**(暗い物や
  透明な物を空きと誤る危険を避ける保守的な既定。設定で「最大距離まで空きとして刻む」に
  切り替えられるようにする)。
- 斜めの区画が返す距離が「斜めの距離」か「正面への垂直距離」か(センサ評価 E2)は未確認なので、
  アクターの設定で選べるようにし、模擬のセンサも同じ設定を持つ(既定は斜めの距離)。

### 1.5 1ステップの中の順序(ビット一致の要)

1. (ステップの頭)送信メールボックスを取り出す: 界面ごとに、φ の界面サンプル列と、
   その面へ中継する光線束。
2. 隣から届いた界面ごとのメッセージを受信メールボックスへ書く(ゴースト値と中継の光線)。
   センサのあるノードには、ホスト(実機ではファーム)が測距フレームも書く。
3. 計算:
   1. 距離の反復を1回(前回の φ と枠のゴースト値だけを使う)
   2. 今ステップに受け取った光線(隣から届いたもの、測距フレームから作ったもの)を取り込む:
      自分の区画に標本点があれば統合待ちに、区画を出ていくなら出ていく面の送信待ちに積む
   3. 統合の期限が今ステップの光線を、固定の順序で統合する
   - (実装時の変更、2026-10-10)初版は「統合→取り込み」の順だったが、それでは期限ちょうどの
     ステップに届いた光線を統合できない。「取り込み→統合」に改めた。

反復を統合より先に行うのは、隣から届くゴースト値が「隣の前ステップの値」(隣の統合前)
だからである。単一ノード解も「反復→統合」の順で計算すれば、分割解と同じ式・同じ順序になる。

## 2. 観測の中継(D9 案1 の具体化)

### 2.1 経路

- 光線を受け取った(または自分のセンサで作った)ノードは、自分の区画を
  「格子点の添字で ±0.5 広げた長方形」(最寄りの格子点が自分のものになる範囲)とみなし、
  光線の線分(原点から r + μ まで)がこの長方形を**出ていく面**を求める。
- 出ていく面の隣がいれば、その面の送信待ちに光線を積む。隣がいなければ(外周)捨てる。
- 角をちょうど通る場合(出ていく面が2つ同時)は、**x方向の面を優先**する。受けた隣の長方形に
  線分がかからない場合は、その隣はy方向の面へそのまま渡す。この取り決めで、どの長方形を
  通る光線も、通る長方形の全ノードに必ず届く(単体テストで確かめる)。

### 2.2 統合の期限(遅れの規則)

- ステップ s に届いた測距フレームから作った光線は、1区画またぐごとに1ステップ遅れて届く
  (ステップ s に作り、s+1 の送信で隣へ、隣は s+1 に受けて s+2 の送信でさらに隣へ…)。
- そこで、光線には取得ステップ s を書いておき、**全ノードがステップ s + L で統合する**。
  L は設定値(統合の遅れ)。区画が横 px × 縦 py なら、またぐ回数は最大 px + py − 2 なので、
  L = px + py − 1 を既定にする(作ったノード自身もステップ s+1 以降に統合する形にそろえる)。
- 期限を過ぎて届いた光線(L が足りない)は統合せずに数える(遅着の計数)。シミュレータでは
  遅着0を合格条件に含める。
- 単一ノード解も、同じ光線をステップ s + L で統合する。

### 2.3 損失への強さ

- 光線束は、同じ界面・同じステップの界面サンプル列と**ひとまとまり**にして運ぶ。ホストの
  再送・控えの単位は「(界面ID, ステップ) のまとまり」で、これは 10a のプロトコルそのまま。
  界面サンプル列が届けば光線束も届いている。

## 3. メッセージ形式(dyne-wire への追加。提案)

### 3.1 測距フレーム(KIND_RANGE_FRAME = 4)

ファーム(シミュレータではホスト)→センサのあるノードのアクター。

- ヘッダ: src = センサID、step = 届けたステップ、t_us = 取得時刻、quantity = 指定なし
- ペイロード: count u32(区画数。8×8なら64)、cols u32(1行の区画数)、
  続けて count 個 × (距離 f64 [m]、状態値 u32、予備 u32) = 16バイト/区画
- 状態値は VL53L5CX の値をそのまま入れる(5 と 9 が有効)。行の選び方・有効の判定は
  アクターがする(D7)。
- 大きさ: 64区画で 24 + 8 + 1024 = 1056バイト。

### 3.2 光線束(KIND_RAYS = 5)

ノード→隣のノード(界面ごと)。

- ヘッダ: src = 界面ID、step = 送信ステップ
- ペイロード: count u32(光線の数)、予備 u32、続けて count 個 × 40バイト:
  原点 x, y(f64)、終点 x, y(f64。原点 + 向き × 測った距離)、取得ステップ u32、
  識別 u32(センサID 16ビット | 区画番号 8ビット | 予備 8ビット)
- 原点と終点はセンサのあるノードが一度だけ計算し、以降は誰も計算し直さない(全ノードが
  ビット単位で同じ光線を使うため)。
- 大きさの見積もり: 4ノードとも8本/ステップのとき、1つの面を通る光線は多くて十数本 →
  24 + 8 + 16 × 40 = 672バイト。界面サンプル列(41点で 360バイト)と合わせて約1,030バイトで、
  UDPの1通(約1,472バイト)に収まる。シミュレータは「まとまりの最大バイト数」を報告し、
  1,472を超えたら警告する(実機の段で効いてくる)。

### 3.3 ホストの変更

- 送信メールボックスのメッセージを、ヘッダの (界面ID, ステップ) ごとにまとめて1つの配送単位に
  する(10a では1界面1通だったものが、1界面1まとまりになる)。中身は見ない。
- 界面IDで運ぶ種別は IFACE_SCALAR / IFACE_BAND / RAYS。この区別は dyne-wire に関数として置く
  (ホストとファームが別々に書かない)。

## 4. 模擬の部屋(シミュレータ専用)

### 4.1 場面ファイルの書式(提案)

テキストファイル、1行1要素、単位はメートル、`#` 以降は注釈:

```text
# 外壁: 多角形(内側が部屋)。長方形なら room x0 y0 x1 y1 でもよい
room 0 0 4 4
# 遮蔽物: 長方形・多角形・円
box 0.0 3.2 1.8 4.0          # 本棚
poly 2.5 0.0 4.0 0.0 4.0 0.6 # 机
circle 1.20 1.50 0.02        # 椅子の脚
# センサ: ID 位置x 位置y 向き(度、x軸から反時計回り) 高さ(m、記録のみ)
sensor 0 0.3 0.3 45 0.8
```

- センサはそれを含む区画のノードに割り当てる(区画の外に置いたら起動時にエラー)。
- 用意する場面: (1) 空の部屋、(2) 雑多な部屋(家の部屋を想定: 細い脚・入り組んだ家具・死角を
  含む)、(3) 実際の部屋に寄せた場面(後日、手描きの間取りか2次元LiDARの測定から起こす)。

### 4.2 模擬のセンサ

- 水平1行・8区画、視野45°(区画の中心方向を光線にする。1区画の円錐の幅は無視)、最大距離4m。
- 距離の雑音: 正規分布 σ(提案の既定 1cm)。乱数は derive_seed(大域シード, センサID) で分離。
- 1ステップに1フレームを渡す(実機で1ステップの間に複数フレームが来る場合の扱い=平均か
  最新かは 10b で決める)。

### 4.3 正解と採点

- 正解の符号つき距離は、場面の線分と円から厳密に計算する(シミュレータ内のみ。アクターには
  渡さない)。
- 採点の項目:
  1. **分割解と単一ノード解のビット一致**(φ・d・w の全格子点。故障注入込み)
  2. 表面の近くの点(w > 0, |d| < μ)の距離の誤差: 平均と最大(正解の距離との差)
  3. 表面の覆い率: 正解の表面上に h 間隔で取った点のうち、近く(h 以内)に表面の近くの
     格子点がある割合
  4. 観測済みの空きの点で、φ と正解の距離の差(遠くの距離の場の質)
  5. 未観測の割合(部屋の内側の格子点のうち w = 0 の割合)
  6. 遅着の数(0であること)
- 格子の刻みより細い物(椅子の脚)は格子型では表しきれない。これは限界として報告し、
  学習型アクターとの比較の材料にする。

## 5. 合格基準

- 全場面・全分割・故障注入(損失・遅延・一時停止・分断)で、分割解と単一ノード解が
  **ビット一致**し、遅着が0。
- 空の部屋で、壁の位置の誤差(採点2の平均)が雑音の大きさ程度(σ=1cm なら約1cm)に収まり、
  距離の場(採点4)が刻み h 程度の誤差に収まる。数値の目標は空の部屋の結果を見てから決める。
- 雑多な部屋の数値は合否ではなく報告(限界を調べる材料)。

## 6. メモリと実機への見通し

- 1点あたり φ・φの次の値・d・w の4つ × 8バイト = 32バイト。1ページ64KBの縮小版では
  約1,500点(約39×39)が上限の目安で、4m四方を5cm刻み・2×2(41×41点)には少し足りない。
  実機の段(10b)で、d と w を f32 にする・刻みを粗くする等を検討する。シミュレータ段では
  フル版(f64)で作る。

## 7. 確認してほしい点(提案のまま実装してよいか)

   まとまりで運ぶ。
2. 統合の期限 L = px + py − 1 の既定(§2.2)。
3. 1ステップの順序「反復→統合」(§1.5)。
4. 「対象なし」の区画は統合しない既定(§1.4)。
5. 場面ファイルの書式(§4.1)と、用意する3つの場面。
6. 既定値: 刻み h = 5cm、切り詰め幅 μ = 3h、重みの上限 50、雑音 σ = 1cm。

## 8. 実装と検証の結果(2026-10-10)

実装したもの:

- crates/sdf2d-grid-actor(格子型アクター。WASMは32KB、線形メモリ25ページ=1.6MB のフル版)。
  中継の経路の判定は純粋関数に切り出し、ネイティブの単体テストで「2×2・3×3・4×2・1×3の分割で、
  無作為な光線2,000本×4と、区画の角をちょうど通る光線が、標本点を持つ全ノードに中継で届き、
  持たないノードでは統合されない」ことを確かめた。
- dyne-wire: KIND_RANGE_FRAME=4(測距フレーム)、KIND_RAYS=5(光線束)、routed_by_iface、
  zone_angle_offset(区画の向きの単一定義)、abi::sdf2d(設定のキー)。単体テスト8件。
- dyne-sim2d: アクターの種類をWASMのエクスポートで見分け、格子型なら --scene の模擬の部屋と
  模擬のセンサから測距フレームを作る(scene.rs)。送信メールボックスのメッセージを
  (界面ID, ステップ) の配送単位にまとめて運ぶ。熱拡散の検証もすべて従来どおり合格。
- 場面ファイル: crates/dyne-sim2d/scenes/empty.txt(空の部屋。各センサは隣の区画の壁を向く=
  中継を必ず通す)、cluttered.txt(雑多な部屋: 本棚・ベッド・机・収納箱・椅子の脚4本(直径3cm)・
  洗濯かご・段ボール箱・三角の棚。寸法は典型的な家具からの仮のもの)。実際の部屋に寄せた場面は未作成。
- 確認スクリプト: scripts/check-sim2d.ps1 の [5][6]。

結果:

- **ビット一致**: 空の部屋・雑多な部屋 × 分割(2×2/3×3/4×1/3×2)× 故障注入(損失10〜20%・
  遅延とゆらぎ・一時停止・分断)× 対象なしを刻む設定 × 距離の定義(斜め/垂直)の8シナリオで、
  φ・d・w の全6,561格子点がビット一致。遅着0・あふれ0。同じ引数の2回実行で出力がバイト一致。
- **対照実験**: 3×3 で統合の遅れを L=1(必要なのは最大4)にすると、遅着6,336本で FAIL。
  遅れの規則が破れたことを判定が検出できる。
- **配送単位の大きさ**: 最大1,200バイト(4×1 分割、細長い区画の長い界面)。2×2 では760バイト。
  UDPの1通(1,472バイト)に収まった。
- **形状の精度**(2×2、300〜400ステップ、雑音 σ=1cm):
  - 空の部屋: 表面の近くの点の誤差 平均0.89cm・95%点5.3cm・最大9.8cm、表面の覆い率23.8%、
    部屋の空きのうち未観測70.8%。雑音0でも平均0.67cm・最大5.6cm残る(下記の限界1)。
  - 雑多な部屋: 誤差 平均2.1cm・95%点6.5cm・最大29cm、覆い率9.9%、未観測69.8%。
- 観測済みの空きの点の距離の誤差(採点4)は空の部屋で平均7.3cm・最大61cm。φ は
  「観測できた表面までの距離」なので、見えていない近くの壁までの正解の距離より大きくなる。
  この採点は「見えていない壁がある限り大きく出る」性質を持つ(観測量の不足の指標として読む)。

分かった限界(格子型の性質として記録する):

1. 斜めに当たる光線の帯の中の距離は、光線に沿った距離なので真の距離より大きく出る
   (切り詰め距離関数の統合で知られた性質)。部屋の角の近くと、光線から横にずれた格子点で
   数cmの誤差になる。
2. 覆い率が低い: 4個のセンサ × 水平1行8区画の細い光線では、壁の2〜4割しか見えない。
   1区画の円錐の幅(約5.6°)を無視して中心の1本だけにしていることも効いている。
   改善の候補: 8×8の複数の行を使う、センサを増やす(ESP32はI2Cが2系統あるので1ノード2個まで可能)、
   1区画を複数本の光線にする。実機で何ができるかはセンサ評価の結果で決める。
3. 格子の刻み(5cm)より細い物(椅子の脚、直径3cm)は表しきれない。雑多な部屋の最大誤差の原因の
   候補(未確認)。学習型アクターとの比較の材料にする。
