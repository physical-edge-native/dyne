# 2026-07-09-開発者PCで動く可視化レイヤー(docs\2026-07-09-plan-viz.md)

## 決定事項
### (新)可視化レイヤーの開発計画

#### Step 1：CLIツールの開発

**実装するもの**
```
各マイコン：
  - 軽量APIサーバー
      GET  /health
      GET  /status
      POST /config
      POST /deploy
  - Pub/Subクライアント（MQTTパブリッシャー）
  - ブローカー選出ロジック（mDNS + リーダー選出）
  - データのローカルキューイング
    （ブローカー不在時にデータを貯めて後で流す）

ブローカー兼任マイコン（選出されたノード）：
  - MQTTブローカー（Mosquitto / NanoMQ）

開発者PC：
  - dyneコマンド
      MQTTクライアント（Subscriber）
      各マイコンAPIへのHTTPクライアント
```

**実現できる機能**
```
監視：
  - マイコン群のヘルス確認        （dyne status）
  - データ収集状況のテキスト出力   （dyne logs）
  - 推論結果の購読・表示          （dyne subscribe）

操作：
  - マイコン単位の設定変更        （dyne config）
  - サブモデルのデプロイ指示      （dyne deploy）
  - ブローカーノードの強制再選出   （dyne rebalance）

データ：
  - 収集済みデータのダウンロード   （dyne pull）
```

---

#### Step 2：Physical Cluster Orchestratorの開発

**実装するもの**
```
開発者PC（dyneコマンドに追加）：
  - 障害検知エージェント
  - 物理トポロジーグラフの管理
  - モデル依存グラフの管理
  - 再分割計画生成エンジン
  - 再デプロイオーケストレータ

各マイコン・ブローカー兼任マイコン：
  - 変更なし
```

**実現できる機能**
```
Physical Cluster Orchestrator：
  - 障害ノードの検知・特定        （dyne status --watch）
  - 再分割計画の自動生成・表示    （dyne rebalance --plan）
  - 再分割後の推定精度の提示      （dyne rebalance --dry-run）
  - 再デプロイの実行              （dyne rebalance --execute）
  - モデルのバージョン管理        （dyne model list / rollback）
```

---

#### Step 3：UI付与（dyne ui）

**実装するもの**
```
開発者PC（dyneコマンドに追加）：
  - dyne uiコマンド
      localhostでWebサーバーを起動
      ブラウザを自動的に開く
  - ブラウザUI（HTML/JS）
      Step 1・2のCLI機能をすべてGUIで提供
      ※ Step 5のWebレイヤーにそのまま流用する

各マイコン・ブローカー兼任マイコン：
  - 変更なし
```

**実現できる機能**
```
Step 1・2の全機能をGUIで提供：

監視：
  - マイコン群のヘルス・ハートビートのリアルタイム表示
  - データ収集状況のグラフ
  - 推論結果の可視化

操作：
  - マイコン単位の設定変更
  - サブモデルのデプロイ指示
  - ブローカーノードの強制再選出
  - モデルのバージョン管理・ロールバック

Physical Cluster Orchestrator：
  - 障害検知の可視化
  - 再分割計画の表示・承認・実行
  - 再分割後の推定精度の表示
  - 再デプロイ中のデータフロー移行状況の可視化

データ：
  - 収集済みデータのブラウザからのダウンロード
```

---

#### Step 4：ブローカー兼任マイコンへのWebサーバー追加

**実装するもの**
```
ブローカー兼任マイコン：
  - 軽量Webサーバーの追加
  - Step 3で作成したUI資産（HTML/JS）の配置・配信
  - MQTTブローカーからのデータ取得・ブラウザへの転送
  - 各マイコンAPIの中継

開発者PC：
  - 変更なし
```

**実現できる機能**
```
開発者PCへのインストールなしに
ブラウザだけでStep 3の監視機能を利用可能：

  - マイコン群のヘルス・ハートビートの表示
  - データ収集状況のリアルタイム表示
  - 推論結果の可視化
  - 収集済みデータのダウンロード

※ 操作系をWebレイヤーに含めるかどうかは
  ユーザー反応を見て Step 5 で判断する
```

---

#### Step 5：Webレイヤーの開発

**実装するもの**
```
ブローカー兼任マイコンのWebサーバー（Step 4に追加）：
  - ユーザー反応に応じて操作系APIを追加実装
      設定変更・デプロイ指示・再選出など
  - 認証・アクセス制御（複数ユーザーが使う場合）

開発者PC：
  - 変更なし（CLIツールは引き続き使用可能）
```

**実現できる機能**
```
Step 4の全機能 ＋ ユーザー反応次第で：

操作（追加する場合）：
  - ブラウザからのマイコン設定変更
  - ブラウザからのデプロイ指示
  - ブラウザからのブローカー再選出

※ 操作系を追加しない場合は
  CLIとWebレイヤーの役割分担を維持する
  （Webレイヤー = 読み取り専用）
```

---

#### Step 6：Webレイヤーへのトンネル追加

**実装するもの**
```
ブローカー兼任マイコン：
  - トンネルクライアントの追加
    （frp自己ホスト or Cloudflare Tunnel）
  - トンネル経由でStep 5のWebサーバーを外部公開

開発者PC：
  - CLIツールのリモート実行設定（SSH経由）
```

**実現できる機能**
```
Step 5の全機能 ＋

- インターネット越しのリモートダッシュボードアクセス
- 複数拠点のマイコン群への同時アクセス
- CLIツールのリモート操作（SSH経由）
```
