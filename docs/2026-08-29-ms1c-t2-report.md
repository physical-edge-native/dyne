# 2026-08-29 発注1報告: 界面残差による自動GROW(M-S1cのT2トリガー)とダッシュボード

方針転換文書 docs/2026-08-29-pivot.md の「発注1(タスク1向け)」の実装・検証報告(下書き)。
用語: GROW=ニューラルネットワーク(以下NN)の隠れ層の幅を実行中に広げる操作。
界面残差=隣り合う2ノードが境目で計算した温度勾配の差 |grad_A − grad_B|(小さいほど
両者の解がつながっている)。T2=仕様書B-16で定義した「界面残差の閾値超過で
隣接ノードのサイズ変更を発火する」自動トリガー。

## 1. 実装(crates/dyne-sim/src/main.rs)

- `--auto-grow on | ratio=4,window=10,base=100,cooldown=100,step=8,max=32,min=20`
  - 各界面の残差を毎ステップ監視(界面の左側ノードが計算開始直前に記録する既存の
    仕組みを流用)。**現在値**=直近 window ステップの中央値、**移動ベースライン**=
    現在窓の直前 base ステップの中央値。現在値 > ratio × ベースラインで発火し、
    界面を挟む両ノードの幅を step だけ広げる(max まで)。
  - ヒステリシス(抑制条件): 発火後 cooldown ステップは再評価しない。さらに、現在値が
    ratio/2 × ベースラインを下回って「再武装」するまで再発火しない。幅が max なら見送り。
  - 参加直後の新界面はベースラインを持たないため、履歴が min 未満の間は**隣の界面**
    (j−1, j+1)のベースラインの中央値で代用する。使う情報は自分の界面と隣の界面の
    残差だけ=界面の両側ノードが自分で持てる局所情報(大域情報は使わない)。
- `--event-csv`(参加・手動/自動の幅変更・handoverの時系列)、`--field-csv [--field-every k]`
  (温度場のスナップショット)を追加。既存の `--residual-csv` `--error-csv` と合わせて
  ダッシュボードの入力になる。
- ノードごとの現在幅をシミュレータが保持し、handover復帰(新インスタンス)時にも
  GROW済みの幅を引き継ぐようにした(事後報告の小さな設計判断。従来はcfg既定幅に戻っていた)。
- 手動 `--resize` と自動GROWは同じ `do_resize` を通り、前後のモデル出力のビット一致点数
  (機能保存)を従来どおり記録する。

## 2. ダッシュボード(scripts/dashboard.py)

CSV4本とログから外部依存なしの1枚HTMLを生成。パネル: (1)温度場アニメ(担当ノード色分け、
不在ノードは空白)、(2)担当区間と幅(帯の高さ=幅)、(3)界面残差の時系列(対数軸、
▲=参加、●=自動GROW発火)、(4)GROW発火タイムライン(ノードごとの幅の推移)、
(5)参照解との誤差。再生・停止・スライダー・速度。Chromeで表示確認済み。

再現: `scripts\demo_task1.ps1`(約4分)。生成済みの成果物: docs/demo/2026-08-29-task1-dashboard.html、
docs/demo/2026-08-29-task1-dashboard-lower.jpg(下半分のスクリーンショット)。

## 3. 検証(8ノード、65点、1200ステップ、学習型アクター既定構成 幅16×1層、sub=1)

| ケース | 発火数 | 結果 |
|---|---|---|
| A. 平常(ADDなし) | **0** | 解析解との最大誤差 1.1e-4。全界面で現在値/ベースラインの最大値 0.99(閾値4に対し余裕4倍) |
| B. ノード4が step 400 で参加(解釈β)+自動GROW | **8**(界面2,3,4,5、step 407〜415) | 最終幅 [16,16,24,32,32,32,24,16]。複合参照解との最大誤差 1.196e-1 |
| C. カオス注入(損失5%、遅延揺らぎ20ms)、ADDなし | **0** | Aと全出力一致(通信の乱れは値を変えない) |
| D. Bと同条件で自動GROWなし(比較) | — | 最大誤差 1.215e-1、乱れピーク 4.9/9.0、回復 14/9 ステップ |
| B'. Bの再実行 | 8 | 全出力・イベントCSVともBと**完全一致**(決定論維持) |

- 「発火しないことが正解」(A, C)は成立。ADD後は参加界面(3, 4)だけでなく1つ外側の
  界面(2, 5)も4〜5倍に達して発火した(乱れが隣へ伝播する。2つ外側の界面0,1,6は
  最大1.5〜2.7倍で発火せず)。発火は参加後7〜15ステップ以内に収束し、cooldown後の
  再発火はなかった。
- 差分法アクターの回帰: `--nodes 16 --points 65 --steps 2000` PASS(bit-exact)。差分法+
  `--add`+`--auto-grow` も PASS(dyne_resize を持たないため発火が無視される)。
- **GROWの効果は限定的**: B(1.196e-1)とD(1.215e-1)の差は1.6%。解釈βのADDでは参加時の
  温度段差が誤差を支配する(M-S1bの知見どおり)ため、NNの容量を増やしても誤差は
  ほぼ変わらない。今回の合格基準は「トリガーが正しい界面でだけ発火する」ことで、
  精度改善は求めていない。精度改善には解釈α型ADD(界面で待つ)との併用が必要(残課題)。

## 4. 残課題

- 閾値 ratio=4 は8ノード・sub=1 での余裕(平常最大0.99)から選んだ。16ノードやsub=2では
  未確認(平常時の残差は単調減少なので、比率は1未満に留まる見込み)。
- 発火が1つ外側の界面へ広がるのが望ましいかは設計判断(参加界面だけに限るなら
  ratio を6程度に上げる。B の外側界面は4.0倍と4.5倍)。
- SHRINK側の自動トリガー(残差が長期に低い界面で幅を戻す)は未実装。
- 中央集権型適応(AB-PINN流)との比較は未実施。
