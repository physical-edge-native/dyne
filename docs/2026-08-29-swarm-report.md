# 2026-08-29 発注2報告: 生物の群れの再現(タスク4b: 温度勾配場での協調探索)

方針転換文書 docs/2026-08-29-pivot.md の「発注2(タスク4向け、4bを本命)」の実装・検証報告
(下書き)。思想1「群としてのAI(中央ブローカーなしのP2P)」の検証: **個体は自分の位置の温度
と近傍k個体からのメッセージしか使えない**という制約の下で、群れが最適温度域へ集団移動
できるかを見る。

## 1. 実装(crates/dyne-swarm、ネイティブの単体バイナリ、依存なし)

- **環境**(シミュレータが大域計算): 定義域[0,1]²の温度場。既定 `--field complex` は
  うねる基調(8〜16℃)に温かい丘3つ(A: 左上、B: 右上、D: 左下。いずれも24℃を越えるので
  最適域はその周りの**輪**)と、22℃止まりの丘C(右下。**最も近いが最適域に入らない罠**=
  局所最適)と、中央の冷たい窪み(群れを分断する谷)を重ねたもの。最適温度 `--t-opt 24`、
  最適域 |T−T_opt| < `--tol 1` は面積の2.1%で、互いに離れた3スポットに分かれる(格子解析で
  確認)。初版の「右に行くほど温かい」場(`--field bumps`)は単調すぎるとの指摘
  (2026-08-29ユーザー)で差し替えた。`--field linear|bumps` も残してある。
- **個体**(N=60): 初期配置は**全域に一様ランダム散布**(既定。`--start x,y,r` で固めることも可)。
  知覚=自位置の温度+センサ雑音(正規分布、標準偏差 `--noise 0.3`)。通信=半径 `--radius 0.15`
  内の近い順 `--k 6` 個体からのメッセージ。環境(無線の到達範囲)が相手を決め、個体は
  選べない。場の式・最適位置・他個体の一覧は個体から参照できない(コード上、個体の判断は
  自分の状態と受信箱だけを見る)。散布直後は通信相手が0〜2個体の個体が多く、群れは
  つながっていない。
- **規則** `--mode`(共有する情報を段階的に増やした4段):
  - `solo`: 通信なしの対照群。前の一歩で|T−T_opt|が縮めば同じ向き、広がれば向きを変える。
  - `follow`: 温度だけ共有し、自分より最適に近い隣のうち最良の個体へ寄る最小構成。
  - `consensus`: 位置+温度を共有。自分+近傍の標本に温度の平面を最小二乗で当てはめて
    局所勾配を推定し、近傍が送ってきた勾配推定と平均して**合意**する。寒すぎれば勾配方向、
    暑すぎれば逆方向へ進む。弱い凝集(離れすぎない)と分離(近すぎない)を加える。
    最適域に入ると歩幅を落として留まる。勾配が分からない(隣がいない)時は乱歩で探索。
  - `gossip`(既定・本命): consensus に加え、**「自分が知る最良地点」(位置、|T−T_opt|、
    経過ステップ)を隣へ伝え、より良い地点を聞いたら乗り換える**。伝聞は隣から隣へ多段に
    広がるが、各段は隣とだけ(大域放送ではない)。最適域の外にいる個体は、伝聞で最適域の
    地点を知っていればそこへ向かい、知らなければ勾配に従う。古い伝聞(400ステップ超)は捨てる。
  - 共通: 壁にぶつかって進めなければ向きを変える。
- **決定論**: 乱数はシード固定(xorshift64*)、近傍の並び順は距離→添字で固定。同一入力で
  全出力がビット一致(再実行で traj.csv を cmp、一致を確認)。
- **出力**: traj.csv(step,id,x,y,temp,n_nbr)、metrics.csv(最適域内の割合、平均|T−T_opt|、
  群れの広がり)、field.csv(描画用の格子標本)、summary.txt。
- **アニメーション** scripts/swarm_anim.py: 温度場のヒートマップ+最適域の境界(白い等高線)+
  個体(緑=最適域内、橙=暑すぎ、水色=寒すぎ、大きさ=通信相手数)+軌跡、指標グラフに
  他モードの比較線を重ねる。外部依存なしの1枚HTML。Chromeで表示確認済み。
- **再現** scripts/demo_task4.ps1(数秒、4モードを走らせて `demo_out\swarm\swarm.html` を生成)。
  成果物 docs/demo/2026-08-29-task4-swarm.html、同 -step0.jpg(初期散布の図)。

## 2. 結果(N=60、800ステップ、全域ランダム散布、既定パラメータ、シード42)

| 規則 | 最終的に最適域内の割合 | 平均\|T−T_opt\| | 90%到達ステップ |
|---|---|---|---|
| gossip(勾配合意+最良地点の伝聞) | **93.3%** | 0.85℃ | **346** |
| consensus(勾配合意のみ) | 45.0% | 2.15℃ | 未到達 |
| follow(温度共有のみ) | 53.3% | 1.97℃ | 未到達 |
| solo(通信なし) | 46.7% | 3.12℃ | 未到達 |

シード1〜3: gossip 96.7 / 98.3 / 96.7%(90%到達 178〜229ステップ)、consensus 53〜70%、
follow 55〜75%、solo 45〜58%。gossip だけが安定して9割以上を最適域へ導く。
再実行で traj.csv がビット一致(決定論)。

> **2026-09-06追記**: 上記の gossip 93〜98%(シード42と1〜3)はシード4本の標本の
> 偏りであり、gossip の到達率の真の姿ではない。シードを広げた分布(本実装自身が
> シードにより55〜98%に散らばる)は docs/2026-09-04-swarm-port-report.md §3 を参照。
> 「gossip が4規則中で最良」という定性的結論は分布比較でも変わらない。

初版(単調な場、群れを1か所に固めて開始、N=40)では consensus だけで100%に達していたが、
複雑な場+散布開始では consensus は**罠の丘Cに群れの一部が吸い込まれて**45〜70%に留まる。
罠を抜けるには「自分の周りの勾配」だけでは足りず、「別の個体が見つけた良い場所」の
知識が隣づてに届く必要がある(gossip)。

## 3. 読み取れること

- **局所知覚+近傍通信だけで、散らばった群れが複数の最適スポットへ集団移動できる**
  (大域的推論なし)。2つの仕組みが要る: (1) 1個体では測れない勾配を、隣の位置と温度を
  合わせた最小二乗で推定する(群れ=分散センサアレイ、思想2の萌芽)。(2) 局所最適の罠を
  抜けるため、「良い場所を見つけた」という知識を隣から隣へ伝える(大域放送なしの伝聞)。
- 群れは1か所に集まらず、3つのスポットに**分かれて**落ち着く(通信範囲でつながった
  部分群ごとに最寄りの最適域へ向かう)。中央集権なら1か所に集めることもできるが、
  この分かれ方は「知っている範囲で最善を選ぶ」局所性の帰結であり、欠点ではなく性質。
- 通信なしの solo でも45〜58%が最適域に入るのは、乱歩でも800ステップあれば面積2.1%の
  スポットに行き当たるため。ただし平均|T−T_opt|は3℃前後と大きく、群れとして留まれない。
- 通信の中身(何を共有するか)が群れの性能を決める(solo→follow→consensus→gossip の4段で
  段階的に検証)。これは仕様書A-1.0「界面の一般化」(何を境目で交換するか)と同じ問いの
  群れ版である。

## 4. 残課題・拡張(pivot文書 §3「将来拡張」に接続)

- 4a(流れのある場)は未実装。Field を差し替えれば同じ個体規則で試せる(流れは知覚量を
  温度から流速へ変えるだけ)。
- 個体の知覚を「周囲n×nの場」へ緩和し、群れの部分知識をつなぎ合わせて全体マップを
  描く(pivot §3 将来拡張)。今回の最小二乗の勾配推定は、その「部分知識の合成」の最小例。
- 個体の学習(規則を固定でなくNNにする)、通信の損失・遅延の注入(dyne-simの仮想
  ネットワークと同じ校正値)、個体の参加・離脱。
- 群れが複数スポットに分かれるのを許すか、伝聞で1か所に合流させるか(伝聞に「そこにいる
  個体数」を含めれば多数派へ寄せられる)は設計判断。
- 伝聞の鮮度(400ステップで破棄)は静的な場を前提にした値。場が時間変化する(4aの流れ、
  タスク1の熱伝導)なら短くする必要がある。
- 位置づけ(2026-08-29ユーザー質問への回答): dyne-swarm は**単体の実験コード**であり、
  WASMアクター・界面メッセージ・仮想ネットワーク・離散イベントというDyneの土台には
  まだ載っていない。思想上の制約(局所知覚・近傍通信・大域情報禁止)と決定論の作法だけを
  共有する。Dyneに載せる段階案: (1) 個体規則をWASMアクター化、(2) 通信をdyne-simの
  仮想ネットワーク(損失・遅延)に乗せる、(3) 動く近傍との一時的な界面=界面の動的生成・
  消滅を仕様書A章の「界面の一般化」として設計、(4) 参加・離脱・学習。
