## 0. 要約

- **計算部品**: crates/imu-fusion-actor(no_std の WASMアクター、22KB、線形メモリ1ページ = 64KB)。各ノードが自分の IMU の
  標本を時間窓(以下「区間」。既定 0.2 s)ごとに平均し、**隣との通信だけで全ノードの平均に近づける**(合意平均。
  隣どうしの値の重みつき平均を繰り返す方法。重みはメトロポリスの重み w = 1/(1+max(隣の数の大きい方)))。
  差込口は 2次元の場のアクターと同じ一式に、標本を入れる `dyne_imu_push` と待ち合わせ用の `dyne_imu_need_until_us` を
  足しただけなので、実機の新経路(node_v2.c)で動く(ファーム側は対応済み: feed.imu)。
- **時刻同期の効果を見せる仕組み**: 標本を区間に割り当てる方法を2つ持つ。①**時刻印**(同期した時刻で区間を決める)、
  ②**届いた順**(時刻印を使わない)。さらに、時刻印にノードごとのずれをわざと足す設定(CFG_TS_OFFSET_US)を持つので、
  ファームを書き換えずに「同期がずれた状態」を作れる。
- **シミュレーション**(scripts/imu_sim.py。LSM6DSOX のデータシートの代表値で雑音・ゼロ点のずれ・温度・机の振動・
  時計のずれを合成):
  - 静止、互いに独立な雑音だけのとき、区間の平均の短時間の標準偏差は N = 1, 2, 4, 8 で
    1.06e-3 → 7.65e-4 → 5.40e-4 → 3.83e-4 m/s²(中央の融合。1/√N なら 3.73e-4)。全台に共通の誤差(振動・温度)を
    入れると 8台で 4.39e-4 に止まる(床が出る)。
  - 隣だけの融合は環・格子(2×4)で中央の融合の 3〜5% 増し、直線(8台)では 25% 増し(合意の収束が遅いため)。
  - 板を動かしたとき(8台、格子): 時刻印で融合した誤差 0.0027 m/s² に対し、時計を 0〜140 ms ずらすと 0.234、届いた順では
    0.067(静止中はどれも 0.0004 程度で差が無い)。**同期が要るのは動いているときだけ**という予想どおり。
  - **ビット一致**: 参照モデル(Python)と実物の WASM を、8台・3条件・各 5000ステップで動かし、全出力 87,824 値と
    全メッセージ(約 10MB)がビット単位で一致。
- **設計の途中で分かったこと(2つ)**: ①区間ごとに合意を置き直す方式では、直線の8台で 10反復では収束せず、各ノードが
  自分のゼロ点のずれを 59% 持ち続けた → **動的合意平均**(変化分だけを足し、区間をまたいで混ぜ続ける)を既定にした。
  ②標本数で重みをつけると、区間ごとの標本数の揺れ(20個/21個)とゼロ点のずれの差が掛け合わさって融合値が揺れ、
  8台でも 1/√N まで下がらなかった → **ノードごとに等しい重み**にした(§2.3、§2.4)。
- **E1**: ワイヤ形式の物理量に「変位」(QTY_DISPLACEMENT = 2)と「慣性」(QTY_INERTIAL = 3)を足し、wave2d-actor を
  変位で送るように変えた。実験10の期待ハッシュ(docs/2026-11-11-wave2d.md §7.3)は全 56 値が変わらないことを確認(§6)。
- **解析**: scripts/imu_analyze.py(G14)と記録用の scripts/imu_log.py。合成記録で全項目を通して確認済み(§5)。

## 1. 何を示す実験か(実験9の確認)

docs/2026-11-11-two-week-plan.md の実験9: 同じ板に載せた IMU 付きのノード N 台が、隣との通信だけで値を融合して
ノイズを下げられること(①静止、②既知の傾き)と、その融合に**時刻同期が必要なこと**(③動き)を示す。
合格: ①でノイズがおおよそ 1/√N で下がり、隣だけの融合が中央の融合(PC で全データを平均)に近い、③で同期なしの誤差が
同期ありより大きい。注意: 同じ板の IMU には振動や温度の影響がそろって入るので、平均しても消えない誤差が残る。

## 2. 計算部品の設計(crates/imu-fusion-actor)

### 2.1 1区間の流れ

```
 標本 (104 Hz) ──dyne_imu_push──▶ 区間 e の和 (n, Σa, Σg)          区間 = (t0 + e·E, t0 + (e+1)·E]、E = M·dt
                                     │ 区間 e が閉じる (ステップ (e+1)·M)
                                     ▼
            自分の平均 z_e = [1, 平均 ax..gz]  ─▶ 合意の状態 x に入れる (動的: x += z_e − z_{e−1})
                                     │ M 回の反復 (1反復 = 1ステップ = 隣と1回交換)
                                     ▼ ステップ (e+2)·M
            融合 = x[1..7] / x[0]  ─▶ 相補フィルタで傾き (ロール・ピッチ) を更新 → dyne_get で読める
```

- 1ステップ = 合意の1反復 = 隣との1回の交換。既定 dt = 0.02 s(50 Hz)、M = 10(区間 0.2 s)。
  WAMR のインタプリタでも 1ステップの計算は数十回の浮動小数点演算なので軽い(通信の往復が律速)。
- 区間 e の融合は、区間が閉じてから M ステップ後(既定 0.2 s 後)に確定する。遅れは区間の終わりから 0.2 s。

### 2.2 標本の区間への割り当て(時刻同期の効果を見るための2方式)

| 方式(CFG_TIME_MODE) | 区間の決め方 | 想定 |
|---|---|---|
| TIME_STAMP = 0(既定) | 時刻印 t(+ CFG_TS_OFFSET_US)で決める。区間 e = ⌊(t − t0 − 1)/E⌋。閉じた区間に来た標本は「遅れ」として捨てて数える。4区間より先の標本も捨てて数える | 同期した時刻で揃える(本命) |
| TIME_ARRIVAL = 1 | 時刻印を見ない。前の区間を閉じた後に届いた標本は全て今の区間 | 時刻同期のない素朴な作り方 |

- **時計をわざとずらす**: CFG_TS_OFFSET_US をノードごとに変えて注入する(例: ノード i に 20 ms × i)。アクターは時刻印に
  この値を足してから区間を決める。ファームの時刻同期は動いたままなので、記録される生の標本の時刻印は正しいまま
  (解析の基準が壊れない)。
- 時刻印の方式では、区間が閉じる前にその区間の標本を入れ終える必要がある。`dyne_imu_need_until_us()` が
  「次の dyne_step の前に、どの時刻までの標本を入れ終えるべきか」を返す(次のステップで区間が閉じないときは 0)。
  ファームはこの時刻まで標本が揃うのを待つ(node_v2.c は最大 300 ms 待つ)。

### 2.3 合意平均の始め方(CFG_CONSENSUS)

| 方式 | 区間の境目の処理 | 長所 | 短所 |
|---|---|---|---|
| CONS_DYNAMIC = 1(既定) | x ← x + (z_e − z_{e−1})(動的合意平均) | 全ノードの x の和は常に今の区間の z の総和(重みが対称なため)。変わらない成分(ゼロ点のずれ)の食い違いは区間をまたいで混ざり続けて消える | 速く変わる成分(白色雑音)は M 回の反復でしか混ざらず、収束の遅いつながり方では雑音がやや残る(§4.2)。隣の値が届かなかった反復があると、和の誤差が残り続ける(再初期化で消える) |
| CONS_RESET = 0 | x ← z_e(区間ごとに置き直す) | 誤差が区間をまたがない | M 回で収束しないと、各ノードが自分のゼロ点のずれを持ち続ける(直線の8台で 59%) |

収束の速さ: メトロポリスの重みの行列の2番目に大きい固有値の絶対値 λ₂ が、1反復で食い違いが何倍に縮むかを表す。
M = 10 反復後の倍率 λ₂^10 は、直線4台 0.11、**直線8台 0.59**、環8台 0.11、格子 2×4 0.21(2台は1反復で厳密に平均)。

### 2.4 重み(ノードごとに等しい重み)

合意の状態は x = [重み, 重み × 平均 ax, ay, az, gx, gy, gz]。区間に標本があったノードの重みは 1、無ければ 0
(融合 = 標本のあったノードの平均の単純平均)。当初は標本数で重みをつけた(x = [n, Σa, Σg])が、標本数が区間ごとに
20個/21個と揺れ、そこにノードごとのゼロ点のずれ(±0.05 m/s² 程度)の差が掛け合わさって融合値が区間ごとに揺れた
(8台の短時間の標準偏差 6.7e-4 m/s²、等しい重みにして 3.8e-4)。

### 2.5 傾き(相補フィルタ)と角速度のゼロ点の較正

- 加速度からの角度: ロール = atan2(ay, az)、ピッチ = atan2(−ax, √(ay² + az²))。
- 相補フィルタ(角速度の積分と加速度からの角度を混ぜる): ロール ← α·(ロール + (gx − bx)·E) + (1−α)·加速度からのロール
  (ピッチは gy)。既定 α = 0.9(時定数 ≈ α·E/(1−α) = 1.8 s)。角速度 → オイラー角の変化は小さい角度での近似。
- CFG_GYRO_CAL_EPOCHS = K > 0 なら、最初の K 区間は**板を静止させる前提**で角速度の平均をゼロ点 bx, by として取り、
  以降それを引く(その間の角度は加速度からの角度)。LSM6DSOX の角速度のゼロ点のずれ(±1 dps 程度)は、較正しないと
  相補フィルタの角度に α·b·E/(1−α) ≈ 0.9°(b = 0.5 dps)のずれを作る。
- 融合した値と、比べるための**自分だけの値**(同じ区間の自分の平均と、自分だけの相補フィルタ)の両方を持つ。

### 2.6 ノードごとのゼロ点の除去(2026-11-27 追加、GitHub issue #194)

- 2026-11-21 の実機の記録を再生すると、融合した値は1台より揺れた。原因はノードごとのゼロ点のずれと、標本の無い
  ノードが区間ごとに変わること(119 区間のうち 15)。標本の無いノードは重み0を共有するので平均から外れるが、
  平均に入るノードの組が変わると、ずれの和が変わる。
- CFG_OFFSET_EPOCHS = K > 0 なら、最初の K 区間(静止)で各ノードが自分の平均を取り、区間 K から、共有する前に引く:
  角速度は自分の静止の平均(真の値は0)、加速度は(自分の静止の平均 − 融合した静止の平均)(重力を残すため)。
  融合した区間 K−1 は、区間 K を閉じるのと同じステップで確定するので、そのときにずれを決める。
- 融合した値の相補フィルタは、最初の K 区間は角度を加速度からの角度に保つだけにし、角速度の較正
  (CFG_GYRO_CAL_EPOCHS)は区間 K 以降の補正した区間だけで行う(ずれを2度引かない。単体試験 zero_offsets_two_nodes)。
  自分だけの値(G_LOCAL*)と自分だけの相補フィルタは補正しない。
- CFG_DEVICES = N を入れると、G_FUSED_DEVICES = floor(G_FUSED_N·N + 0.5)(その区間で標本のあったノードの数)を出す。
- 既定(K = 0、N = 0)では、出力 0〜21 は追加前とビット単位で同じ(scripts/imu_record_replay.py の CRC-32 が同じ)。
- 実機の記録の再生(K = 10、7台の環、最初の 120 s): 区間 15 以降の融合の揺れは1台の 1/2.1〜1/2.7(√7 ≈ 2.65)。
  統括の判断(段階1、issue #194 のコメント): キーと出力を `abi::imu` の末尾に足すのは約束ごとを変えない追加として
  dyne で直接進めてよい。`abi.rs` に触れるので、マージはユーザーが行う。

### 3.1 エクスポート関数

| 関数 | 意味 |
|---|---|
| `dyne_cfg(key u32, val f64)` | 設定(§3.2)。dyne_init2d の前に入れる(init をまたいで保持) |
| `dyne_set_face(face u32, kind u32, param u64)` | 隣の設定。kind = 1(界面)の面が隣で、param の下位32ビットが界面ID。面は 0〜3(西・東・南・北)。直線・環・格子とも1ノードの隣は4つまで。界面以外の面は無視 |

| `dyne_len() -> u32`、`dyne_get(k u32) -> f64` | 出力(§3.3)。dyne_len = 23(2026-11-27 までは 22) |
| `dyne_steps_done / dyne_dropped / dyne_rejected / dyne_missing` | 計数 |

`dyne_outbox_read` → 隣へ配送 → `dyne_inbox_write` → `dyne_step`。node_v2.c の feed.imu はこの順で実装済み。

### 3.5 実機で動かすときの注意(ファームと PC 側の取り決め)

1. **t0(CFG_T0_US)は同期した時刻で入れる**。既定の 0 のままだと、同期した時刻(1970年からの µs)の標本は全て
   「先すぎ」になる。PC は開始の数秒先の時刻を t0 として全ノードに同じ値で注入する(JSON の数値で 1.7e15 程度。
   f64 で整数のまま運べる)。
2. **ステップの進み方を実時間に合わせる**: ステップ s の時刻は t0 + s·dt。ステップが実時間より先に進むと、区間の
   境目ごとに最大 300 ms 待ち、それでも足りなければ標本が「遅れ」になる。node_v2.c の step_period_ms を dt と同じ
   20 ms にし、ステップ0を t0 まで待ってから始めるのがよい(**ファームへの依頼**。§9 の U3)。
3. **同期していないノード**: ファームは未同期のとき esp_timer の時刻をそのまま渡す(dyne_imu.c)。時刻印の方式では
   その標本は区間に入らず捨てられ(遅れ・先すぎの計数が増える)、融合はそのノードを「標本なし」(重み0)として続く。
4. **融合の出力の発行**(**ファームへの依頼**): 区間の境目ごと(step が M の倍数のとき)に
   `dyne/node/<id>/imu_fused` へ `{"step":s,"v":[dyne_get(0)..dyne_get(21)]}` を発行してほしい。いまの node_v2.c の
   field2d の発行は CRC と最小・最大だけなので、融合の値が PC に届かない。scripts/imu_log.py はこの形で受ける。
5. **wasm の置き場所**: `cd crates\imu-fusion-actor && cargo build --release --target wasm32-unknown-unknown` →
   target\wasm32-unknown-unknown\release\imu_fusion_actor.wasm(スタック 8KB は crates/imu-fusion-actor/.cargo/config.toml
   で指定。縮小版を分けない)。scripts/build-actor-wasm.ps1 への追加は他の作業との衝突を避けて行っていない(§9 の U5)。
   → 2026-11-15 追記: scripts/build-actor-wasm.ps1 に追加した(1 種類のみ。GitHub issue #5)。

## 4. シミュレーション(scripts/imu_sim.py、scripts/imu_fusion_ref.py)

### 4.1 模型(仮定。実測で置き換える)

| 項目 | 値 | 出所・理由 |
|---|---|---|
| 出力の周期(ODR) | 104 Hz ± 1%(ノードごと) | LSM6DSOX の内部の発振の誤差を想定 |
| 白色雑音 | 加速度 70 µg/√Hz、角速度 3.8 mdps/√Hz(帯域 52 Hz で 4.95e-3 m/s²、4.8e-4 rad/s) | データシートの代表値 |
| ゼロ点のずれ(固定) | 加速度 5 mg、角速度 0.3 dps(標準偏差、ノードごと) | データシートの代表値(±20 mg、±1 dps)より小さめ。要実測 |
| ゼロ点のゆらぎ | 1次のガウス・マルコフ過程(加速度 1e-4 m/s²、角速度 2e-5 rad/s、時定数 200 s) | 仮定 |
| 温度 | 板の温度が 3 ℃ 上がる(時定数 900 s、全台共通)。温度係数は平均 0.05 mg/℃・0.005 dps/℃、個体差も同じ大きさ | 平均の部分が全台共通の誤差になる |
| 机の振動 | 5〜30 Hz の帯域の雑音、加速度 2e-3 m/s²、角速度 5e-5 rad/s(全台共通) | 仮定 |
| 時刻印 | 同期あり: ノードごとのずれ 0.3 ms(標準偏差)+揺らぎ 50 µs | docs/2026-11-11-timesync-ota.md の推定の質より控えめ |
| 届いた順の模型 | FIFO(センサ内のため置き)を 20 ms ごとに読む。ステップを呼ぶ時刻は理想より 0〜60 ms 遅れる(ノードごとに固定)+揺らぎ 5 ms | Wi-Fi の BSP(全ノードが足並みをそろえて進む同期)の遅れ数十 ms |
| 真の動き | 静止 / 傾きの階段 0°→10°→20°(各 20〜30 s、移り変わり 3 s)/ 動き(20〜80 s にロール 15°・0.3 Hz、ピッチ 10°・0.17 Hz、x 方向の揺れ 0.8 m/s²・1.5 Hz) | 手でゆっくり回す・揺らすことを想定 |

剛体の板の上の場所による違い(回転の中心からの距離による遠心・接線方向の加速度)は無視した。

### 4.2 ① 静止: 台数と標準偏差(600 s、区間 0.2 s、図 demo_out/imu/static_std_vs_n.png)

区間の平均の「短時間の標準偏差」(隣の区間との差の標準偏差 / √2。温度やゼロ点のゆらぎのような遅い漂いを除いた
ばらつき)。隣だけの融合はノード0の値ではなく全ノードの平均(ノードごとの標準偏差の平均)。単位 az は m/s²、gx は rad/s。

| 条件 | N | つながり方 | 中央の融合 az | 隣だけの融合 az | 中央 gx | 隣だけ gx | 隣だけ − 中央 (az, RMS) |
|---|---|---|---|---|---|---|---|
| 独立な雑音だけ | 1 | — | 1.055e-3 | 1.055e-3 | 1.051e-4 | 1.051e-4 | 0 |
| | 2 | 直線 | 7.65e-4 | 7.65e-4 | 7.48e-5 | 7.48e-5 | 8e-15 |
| | 4 | 直線 | 5.40e-4 | 5.48e-4 | 5.29e-5 | 5.37e-5 | 8.1e-5 |
| | 8 | 直線 | **3.83e-4** | 4.77e-4 | 3.71e-5 | 4.62e-5 | 2.6e-4 |
| | 8 | 環 | 3.83e-4 | **3.96e-4** | 3.71e-5 | 3.84e-5 | 8.3e-5 |
| | 8 | 格子 2×4 | 3.83e-4 | **4.00e-4** | 3.71e-5 | 3.90e-5 | 9.9e-5 |
| | 8 | 直線、置き直し | 3.83e-4 | 4.47e-4 | 3.71e-5 | 4.33e-5 | 1.8e-3(一定のずれ最大 3.5e-3) |
| | 8 | 格子、置き直し | 3.83e-4 | 3.91e-4 | 3.71e-5 | 3.79e-5 | 1.6e-3(一定のずれ最大 2.1e-3) |
| 共通の誤差あり | 1 | — | 1.075e-3 | 1.075e-3 | 1.051e-4 | 1.051e-4 | 0 |
| | 8 | 直線 | 4.39e-4 | 5.24e-4 | 3.75e-5 | 4.64e-5 | 2.6e-4 |
| | 8 | 格子 2×4 | **4.39e-4** | 4.54e-4 | 3.75e-5 | 3.93e-5 | 9.9e-5 |

- 中央の融合は 1 → 8 台で 1.055e-3 → 3.83e-4(2.76 倍。√8 = 2.83)。**ほぼ 1/√N**。
- 全台に共通の誤差(振動 2e-3 m/s²)を入れると、8台で 4.39e-4 に止まる(1/√N の目安 3.80e-4 より 15% 大きい)。
  加速度の共通の振動は 0.2 s の平均でほとんど消えるので床は浅い。角速度は共通の振動を小さく仮定したので床が見えない。
  **実機で床が深く出るかは振動の実測次第**(机・建物の振動、人の歩行は数 Hz で、0.2 s の平均では消えにくい)。
- 隣だけの融合(動的合意平均)は、環・格子で中央の融合の 3〜5% 増し。直線の8台では 25% 増し(λ₂^10 = 0.59 で、
  1区間の 10反復では白色雑音の食い違いが混ざりきらない)。**つながり方は環か格子がよい**。
- 区間ごとに置き直す方式は白色雑音ではやや良い(格子 3.91e-4)が、各ノードが自分のゼロ点のずれを持ち続け、
  ノードごとに**一定のずれ**(直線で最大 3.5e-3 m/s² = 0.36 mg、傾きで約 0.02°)が残る。動的合意平均ではこれが
  2e-8 まで消える。既定は動的合意平均にした(§9 の U2)。

### 4.3 ① 静止: アラン偏差(2 時間、共通の誤差あり、標本の番号で揃えた中央の平均、図 demo_out/imu/allan.png)

アラン偏差(時間 τ ごとの平均の、隣どうしの差のばらつき。短い τ で傾き −1/2 の部分が白色雑音(角度・速度の
ランダムウォーク)、最小の値がバイアス不安定性(ゼロ点のゆらぎ)の目安)。

| N | ax: τ = 1 s [m/s²] | ax: 最小 (τ) | gx: τ = 1 s [deg/h] | gx: 最小 (τ) [deg/h] |
|---|---|---|---|---|
| 1 | 4.56e-4 | 6.9e-5(355 s) | 9.0 | 1.97(52 s) |
| 2 | 3.25e-4 | 5.3e-5(72 s) | 6.4 | 1.43(38 s) |
| 4 | 2.30e-4 | 4.2e-5(72 s) | 4.5 | 1.05(52 s) |
| 8 | 1.66e-4 | 2.8e-5(52 s) | 3.2 | 0.78(28 s) |

τ = 1 s の値は 1 → 8 台で 2.74 倍(加速度)・2.80 倍(角速度)下がる(√8 = 2.83)。最小の値(ゼロ点のゆらぎ)は 2.4〜2.5 倍で、
長い τ では全台共通の温度の漂いが残るので下がり方が鈍る(最小になる τ も短くなる)。

### 4.4 ② 傾き(0° → 10° → 20°、ノード0の融合の相補フィルタ、32 通りの個体の組の RMS、図 demo_out/imu/tilt.png)

| N | 誤差 (較正なし) [°] | 0° で零点を合わせた後 [°] |
|---|---|---|
| 1 | 0.284 | 0.066 |
| 2 | 0.205 | 0.049 |
| 4 | 0.151 | 0.045 |
| 8 | **0.096** | **0.032** |
| 8(置き直し) | 0.137 | 0.040 |

- 較正なしの誤差は加速度のゼロ点のずれ(5 mg ≈ 0.29°)が支配し、1/√N(1 → 8 台で 2.96 倍)で下がる。
- 0° の水平器の値で零点を合わせた後に残るのは、ゼロ点のずれのうち角度で効き方が変わる成分(sin 20° ≈ 0.34 倍)と雑音で、
  2.06 倍しか下がらない(32 通りでもばらつきが大きい)。
- 置き直しの方式では、ノード0の値に自分のずれが 59% 残るので 0.137° と悪い(全ノードの平均では 0.097° で同じ)。

### 4.5 ③ 動き: 時刻同期あり・なし(8台の格子と1台、図 demo_out/imu/motion_sync.png、motion_bars.png)

誤差 = アクターの融合した区間の平均 − 真の区間の平均(動く前の静止 8〜18 s の平均の誤差を各ノードで引いた後。
引かないとゼロ点のずれが同期の効果を隠す)。「同期した中央との差」は、同期した時刻印で PC が全ノードの標本を平均した
もの(実機で真値の代わりに使える基準。§5.4)との差。単位 m/s²(ay = 横方向の加速度、ロールで ±2.5 m/s² 振れる)。

| N | 割り当て | 静止中 ay | 動いている間 ay | 動いている間、同期した中央との差 | ノード間の食い違い ay |
|---|---|---|---|---|---|
| 1 | 時刻印(同期あり) | 0.0011 | 0.0091 | 0 | — |
| 1 | 届いた順 | 0.0011 | 0.061 | 0.060 | — |
| 8 | **時刻印(同期あり)** | 0.0004 | **0.0027** | 0.0005 | 0.007 |
| 8 | 時刻印 + 時計を 0〜140 ms ずらす | 0.0004 | **0.234** | 0.235 | 0.154 |
| 8 | 届いた順 | 0.0004 | **0.067** | 0.067 | 0.041 |

- **静止中は3条件とも同じ**(0.0004)、**動くと同期なしだけ誤差が 25〜90 倍に増える**。予想どおり。
- 時計を 0〜140 ms ずらした場合が最も悪い(平均で 70 ms ずれた時刻の値を混ぜる)。届いた順は、ステップの遅れ
  (0〜60 ms)の分だけずれ、1台でも 0.06 の誤差になる(全ノードに共通の遅れは「遅れて見える」誤差になる)。
- 1台の同期ありでも動くと 0.009 に増えるのは、0.2 s の区間を約 21 個の標本で平均する際の離散化(1.5 Hz の揺れ)の
  誤差。8台では標本の取得の位相がノードごとに違うので 0.0027 まで下がる。
- 相補フィルタの傾きは、動いている間はフィルタ自身の遅れ(時定数 1.8 s)が支配する(同期あり 1.84°)。時計をずらした
  条件で 0.66° と小さく見えるのは、ずらしで区間が先に進み、フィルタの遅れを偶然打ち消したため。**動きの比較には傾きでなく
  区間の平均の値を使う**。

### 4.6 参照モデルと実物の WASM のビット一致

scripts/imu_fusion_ref.py の ImuFusionRef は Rust と同じ順序で同じ浮動小数点演算をする(atan2 も Rust の libm 0.2.16 と
同じ手順を Python に写した。Python の math.atan2 だと最後の1桁がずれ、当初の照合で角度だけ 206 値が一致しなかった)。
`imu_sim.py wasm` で、動きの場面(8台、格子 2×4、5000ステップ、標本 83,228 個)を3条件で両方に通した。

| 条件 | 比べた値 | 一致しなかった値 | 送信メールボックスのバイト列 |
|---|---|---|---|
| 時刻印(同期あり) | 87,824 | 0 | 全ステップ・全ノードで一致(約 10MB) |
| 時刻印 + ずらす | 87,824 | 0 | 一致 |
| 届いた順 | 87,824 | 0 | 一致 |

Rust の単体試験(cargo test、4件): 1台の区間の割り当てと確定の時点、届いた順、2台の合意(1反復で平均)、
3台の直線で動的合意平均が一定値の食い違いを消す(置き直しでは消えない)。同じ入力なら全出力が同じ(乱数のシード固定)。

## 5. データの形式(実機の記録・解析)

### 5.1 生の標本(ファームの発行。node-esp32/main/dyne_imu.c が定めた形)

`dyne/node/<id>/imu`: `{"seq":バッチの通番,"odr":104,"fs_g":4,"fs_dps":500,"sa":<g/LSB>,"sg":<dps/LSB>,"synced":true,
"us_per_tick":..,"fit_resid_us":..,"ovr":..,"orphan":..,"s":[[t_us, t_loc, ax, ay, az, gx, gy, gz], ...]}`
(t_us = 同期した時刻、未同期は 0。t_loc = esp_timer。ax..gz = 生の整数)。

### 5.2 記録の CSV(scripts/imu_log.py が書く。解析の入力)

1つの条件 = 1つのディレクトリ(例: measured/2026-11-xx-imu/static1/)。

| ファイル | 列 | 備考 |
|---|---|---|
| imu_raw.csv | node, seq, ts_us, local_us, ax, ay, az [m/s²], gx, gy, gz [rad/s], temp_c | seq はノードごとの通し番号(記録側で付ける)。ts_us = 0 は未同期で、解析では使わない |
| imu_batches.csv | pc_time, node, batch, n, synced, ovr, orphan, us_per_tick, fit_resid_us | バッチの抜け(MQTT の取りこぼし)と FIFO のあふれの確認用 |
| imu_fused.csv | node, step, epoch, epoch_end_us, v0..v21 | v = dyne_get(0..21)(§3.3)。ファームが imu_fused を発行したときだけ(§3.5 の 4) |
| level.csv | t_start_us, t_end_us, roll_deg, pitch_deg, label | **手で書く**: 水平器の値と、その角度で静止させた時間(同期した時刻 [µs])。0° の行があれば零点合わせに使う |
| meta.json | epoch_s, dt_s, epoch_steps, t0_us, time_mode, topology, offsets_us | 条件の記録。t0_us はアクターに入れた CFG_T0_US(解析の区間をアクターと揃える) |

### 5.3 解析(scripts/imu_analyze.py)

```
.venv\Scripts\python.exe scripts\imu_analyze.py <記録> [<比べる記録> ...] [--static A,B] [--replay 120] [--topo grid]
```

出すもの(画面に Markdown の表、<記録>/analysis/ に summary.json と図):
- 記録の健全性: ノードごとの標本数・実際の ODR・バッチの抜け・FIFO のあふれ・未同期の標本・時刻印の逆行
- ① 静止の範囲(--static を省くと動きの検出で最も長い静止の範囲)で、先頭 N 台(1, 2, 4, 8)の中央の融合の標準偏差と
  短時間の標準偏差、1/√N の目安
- ① 隣だけの融合: 記録した標本を参照モデル(実物とビット一致)に時刻印の割り当てで入れ直し、N 台の部分集合ごとに
  中央の融合と比べる(実機で N を変えて何度も走らせなくても比べられる)
- ① アラン偏差(10 ms の箱で揃えた中央の平均)
- ② level.csv の各行で、加速度の平均から求めた傾き − 水平器(N ごと、0° の行で零点を合わせた後も)、アクターの相補フィルタの値
- ③ 各記録のアクターの融合 − 同期した時刻印での中央の融合(静止・動きに分けて RMS)

## 7. 実験9の手順(ユーザー向け)

### 7.1 準備

1. **板**: A4〜A3 の板に 8 台を並べて固定する(両面テープ+結束バンド)。**IMU の基板の向きを全台そろえる**(x 軸を板の
   長辺に)。2×4 の格子に並べると、つながり方(格子)と見た目が一致して分かりやすい。ノード番号を板に書く。
   板の中央に水平器を置ける場所を空ける。
2. **配線**: Modulino Movement を Qwiic のケーブルでノードの I2C につなぐ(ファームの説明に従う)。電源は乾電池。
3. **ファーム**: IMU のドライバと feed.imu の入ったファーム(node-esp32)を書き込む。起動後、IMU が見つかったこと、
   時刻同期が synced になったことを確認する。
4. **wasm**: `cd crates\imu-fusion-actor && cargo build --release --target wasm32-unknown-unknown`。積み込みはファームの手順で。
5. **PC**: ブローカー、時刻サーバ(scripts/dyne_ntp_server.py)、記録 `scripts\imu_log.py --out measured\<日付>-imu\<条件>`。

### 7.2 設定注入(node_v2 の形。案)

- 界面: 格子 2×4 の隣どうし(横 3×2 + 縦 4 = 10 本)に界面IDを振り、各ノードの faces(w/e/s/n)と ifaces を設定する。
- field2d.cfg: `[[0,10],[1,0],[2,<t0>],[5,25],[6,1]]`(区間 10 ステップ、時刻印、t0 = 開始の数秒先の同期した時刻、
  角速度の較正 25 区間 = 5 s、動的合意平均)。cluster.dt = 0.02、step_period_ms = 20、feed.imu = true。
- 時計をわざとずらす条件: 上に `[3, 20000*i]` を足す(ノード i に 20 ms × i)。
- 届いた順の条件: `[1,1]`。
- 条件ごとに meta.json を書く(t0_us、time_mode、offsets_us)。

### 7.3 手順と合格基準
