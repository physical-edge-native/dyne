# 形の格子型アクターを ESP32 のインタプリタで速くする(2026-11-11 依頼、2026-11-13 作成)

目的: 形の格子型アクター(crates/sdf2d-grid-actor の縮小版)の1ステップを、素の ESP32(Xtensa、WAMR の
classic インタプリタ)で **5倍以上** 速くし、実験6(箱を動かして形が追従する)の基準
「最も遅いノードの1ステップ ≤ 約190ms」(docs/2026-11-11-esp32-interp-bench.md §3)を満たす。
既定の設定の出力は変えない(バイト一致)。分割解と単一ノード解のビット一致は、どの設定でも保つ。

用語: WAMR = WebAssembly Micro Runtime(マイコン向けの WebAssembly 実行環境)。classic = WAMR の素朴な
インタプリタ。線形メモリ = WebAssembly のアクターが使うメモリ領域(1ページ = 64KB)。燃料 = PC の
WebAssembly 実行環境 wasmi が数える「実行した命令の数」の目安。f64 / f32 = 倍精度 / 単精度の浮動小数点数。
アイコナール方程式の反復 = 観測した表面から離れた格子点へ距離を伝える計算(以下「距離の反復」)。

追加の依頼(2026-11-13、ユーザー承認済み): A2 = 減衰・忘却を視野の中の格子点だけに効かせる設定
(首振りで別の向きを見ている間に壁が消えないように)、A5 = 箱を動かす場面を scripts\check-sim2d.ps1 の
ビット一致の項目に足す。

## 0. 結論

- **依頼の前提の訂正**: 「1ステップに距離の反復が約9回あり、それが支配的」ではなかった。距離の反復は
  1ステップに **1回**(ESP32 で約80ms)で、残りの 650〜910ms は **光線の処理**(取り込み・中継の判定・
  統合)だった。光線1本ごとに、区画に関係のない部分も含めて光線の全長(最大約330標本点)を2回
  たどり、標本点ごとに libm(純Rustの数学関数)の floor を2回(整数演算の長い命令列)呼んでいた。
- **結果を変えない工夫だけで、PC の燃料で 5.1〜5.9倍** 減った(ノード13: 2.03M → 0.40M、ノード5:
  2.77M → 0.47M 命令/ステップ)。出力は工夫の前とバイト一致(§3)。ESP32 の時間の見込みはノード5で
  **170〜260ms**(工夫の前 992ms)。下限なら基準を満たし、上限なら少し足りない(見込みの幅の理由は §4)。
- 基準を確実に満たすための追加の候補(結果は変わるが質への影響は小さい): 距離の反復の間引き(2ステップに
  1回)、単精度(f32)、刻み 5cm。今夜の実機計測(§6)で、どれが要るかを決める。
- **推奨**: まず「結果を変えない工夫 + 標準ライブラリの sqrt」(以下 exact+std)を既定にする。
  実機で ≤190ms に届かなければ「+ 距離の反復の間引き2」、それでも足りなければ「+ f32」の順に足す
  (どちらも追従・壁の誤差への影響は測定誤差程度、§5)。刻み 5cm は精度が落ちる(壁の誤差 4mm → 8mm、
  箱の誤差 5mm → 17mm)ので最後の手段。
- **首振り(PAN4H)についての重要な発見**: 首振りの場面では、従来の「全格子点を毎ステップ減衰」だと
  見ていない間に壁・箱が消え、箱が安定して現れない(追従の時間が測れない = 無限大)。A2(視野の中だけ
  減衰)で壁の覆い率は最小 28% → 43% に上がり、箱は 3.5秒で現れる。ただし、**箱の古い位置の跡が、
  新しい位置の箱に隠れた側で消えない**。視野の外を緩く減衰させる設定(CFG_DECAY_OUT、0.98)で
  約10秒で消える。首振りの一巡(約4.3秒)が追従の時間を決めるので、**首振りの構成で「2秒以内に追従」は、
  計算の速さに関係なく難しい**(§5.3。ユーザーの判断事項)。

## 1. どこが重かったか(工夫の前)

ESP32 の実測(2026-11-11、ESPr Developer 32、240MHz): ノード13 は1ステップ平均 730ms(最小 213ms)、
ノード5 は 992ms。距離の反復だけを測ると 78〜83ms。PC の燃料(bench-c5\tools\recfuel、§7)で同じ記録を
再生すると、ノード13 2.03M・ノード5 2.77M 命令/ステップで、ESP32 の時間との比はどちらも
**約 0.36µs/命令**(よく揃っている)。

| 部分 | 工夫の前の燃料(ノード5) | 中身 |
|---|---|---|
| 距離の反復 | 約 0.29M | 格子点ごとの風上差分。sqrt は libm の整数演算版(1回 約200命令)で、その分が約 0.19M |
| 光線の処理 | 約 2.48M | 受け取った光線ごとに経路の判定(全標本点)、期限の来た光線の統合(全標本点)。標本点ごとに floor 2回 |

## 2. 工夫の一覧

| 記号 | 工夫 | 何が変わるか | 結果 | 設定のしかた |
|---|---|---|---|---|
| E1 | floor の置き換え | 格子点の添字 `floor(x) as i64` を、整数への切り捨て(wasm の1命令)+1回の比較で求める | **同じ**(floor は誤差のない演算。NaN・範囲外の扱いも同じ。単体テスト floor_i_matches_libm) | 常に有効 |
| E2 | 光線の範囲の絞り込み | 区画を格子1点ぶん広げた長方形と光線の交わりから、区画に入りうる標本点の番号の範囲を求め、その範囲だけを調べる(経路の判定は後ろから調べて最後の自分の標本点で止める) | **同じ**(範囲の外の標本点は区画から h 以上離れている。区画に標本点が無いときだけ従来どおり全標本点を調べる。単体テスト route_matches_full) | 常に有効 |
| E3 | 標準ライブラリの sqrt | libm の sqrt(整数演算 約200命令)の代わりに wasm の sqrt 命令1つ | **同じ**(IEEE 754 の sqrt は正しく丸めた値と定められ、libm も正しく丸める) | 機能 `std-math`(縮小版の推奨)。wasm は 38KB → 53KB(標準ライブラリの異常終了の処理の分) |
| E4 | 内訳の計測口 | `dyne_step_part(0/1/2)`(反復/取り込み/減衰と統合)。順に呼べば dyne_step と同じ | 同じ | 常に有効(bench-c5・recfuel が使う) |
| T1 | 距離の反復の間引き | ステップ番号が n の倍数のときだけ反復する。表面の近くの φ は観測そのものなので、遅くなるのは表面から離れた点への距離の伝わり方だけ | 変わる | `CFG_SWEEP_EVERY = n`(dyne-sim2d `--sweep-every n`)。既定 1 |
| T2 | 単精度 | 場(φ・d・w)と光線の幾何を f32 で計算(ワイヤ形式・光線・設定・dyne_get は f64 のまま) | 変わる(f32 の分割解と f32 の単一ノード解はビット一致) | 機能 `f32`(縮小版は `small,f32,std-math`、照合用のフル版は `f32`) |
| T3 | 刻み 5cm | 格子点が 1/4、光線の標本点が 1/2 | 変わる | dyne-sim2d `--h 0.05`(アクターは同じ) |
| A2 | 視野の中だけの減衰 | 減衰・忘却を、そのステップに統合する光線が通る格子点だけに、最初の統合の直前に1回効かせる。視野の外は値を保つ | 変わる | `CFG_DECAY_IN_VIEW = 1`(`--decay-in-view`)。既定 0 |
| A2' | 視野の外の緩い減衰 | A2 のとき、光線が通らなかった格子点を毎ステップ λ_out で減衰・忘却(統合の後) | 変わる | `CFG_DECAY_OUT = λ_out`(`--decay-out`)。既定 1(保つ) |

検討して採らなかったもの:
- 「何も変わらなければ反復を省く」「変わった格子点だけ計算し直す」(結果は同じにできる): 雑音のある観測が
  毎ステップ表面の d を少しずつ変え、その変化が反復で区画全体へ伝わるので、定常状態ではほとんど省けない
  見込み。印の管理(1点1ビット)の手間の方が大きいと判断した。
- 収束の判定での早めの打ち切り: 反復は既に1ステップ1回なので、打ち切る余地がない。
- 標本点の間隔 δ = h/2 を h にする、`/ h` を `* (1/h)` にする: どちらも結果が変わり、得は 2割程度。
  T1・T2 より質の検証が要るので今回は入れていない。

## 4. ESP32 の速さの見込み(PC の燃料から。実機の計測で置き換える)

| 組み合わせ(記録) | 燃料 /ステップ(反復 / 取込 / 統合) | 工夫の前との比 | ESP32 の見込み |
|---|---|---|---|
| base: 工夫の前(ノード5) | 2.77M | 1 | 992ms(実測) |
| base(ノード13) | 2.03M | 1 | 730ms(実測) |
| exact+libm(ノード5) | 0.68M(0.29 / 0.05 / 0.34) | 4.1倍 | 245〜375ms |
| **exact+std(ノード5)** | **0.47M(0.11 / 0.04 / 0.32)** | **5.9倍** | **170〜260ms** |
| exact+std(ノード13) | 0.40M(0.11 / 0.03 / 0.26) | 5.1倍 | 145〜220ms |
| exact+std+間引き2(ノード5) | 0.42M(反復 0.055) | 6.6倍 | 150〜230ms |
| exact+std+f32(ノード5) | 0.46M(0.10 / 0.04 / 0.32) | 6.0倍 | 140〜210ms(単精度の演算器が効く分を見込む) |
| exact+std、刻み 5cm(ノード5、区画 18×14点) | 0.30M(0.04 / 0.04 / 0.22) | 9.3倍 | 105〜165ms |
| exact+std+f32、刻み 5cm | 0.29M | 9.4倍 | 90〜135ms |
| exact+std、PAN4H + A2(ノード15、最も重い) | 平均 0.26M、最大 0.42M | — | 平均 95〜145ms、最大 150〜230ms |

見込みの幅の理由: 工夫の前の比 0.36µs/命令は、整数演算が多い命令の組(libm の floor・sqrt)で測った値。
工夫の後は残る命令に占める f64 の演算(ESP32 ではソフトウェアの関数呼び出し、1回 数十〜百数十サイクル)の
割合が上がるので、1命令あたりは重くなる。下限は 0.36µs/命令、上限は 0.55µs/命令(推定)で計算した。
f32 は燃料がほとんど変わらない(命令の数は同じ)が、ESP32 は単精度の演算器を持つので 1命令あたりが軽くなる
見込み(0.30〜0.45µs/命令で計算。**推定**)。

統合(光線を格子点に足す部分)が最大の部分として残る。ノード5は1ステップに約64本の光線が通り、1本あたり
区画の中の約100標本点を調べる(標本点ごとに割り算2回・floor 2回)。

## 5. シミュレータでの形の質(scripts\shape_speedup_sweep.py)

条件: 6畳(3.6m×2.7m)、4×4 分割、雑音 8mm、推奨の忘れる仕組み(食い違い 0.1m + 減衰 0.9 + 忘却 0.3)、
15Hz、600ステップ(箱の移動は 300ステップ目、room6_carry は 300〜330 で運ぶ)。採点の尺度は刻みに
よらず **5cm に固定**(幻の表面 = 正解から 10cm より遠い推定表面、覆い率 = 5cm 以内に推定表面がある
正解の表面の割合。dyne-sim2d の新しい引数 `--track-scale-m`)。追従の時間 = max(古い位置の跡が消える
まで, 新しい位置の覆い率が最終値の 8割を保つまで)。∞ = 600ステップまでに満たさない。
全 42 実行で分割解と単一ノード解は **PASS (bit-exact)**。

- 間引き2・f32 は、追従・壁の誤差とも基準と同じか測定の揺れの範囲(f32 の壁の 95% 誤差が +1.6mm)。
- room6_move の刻み 2.5cm で追従が 2.67秒なのは、古い位置の跡の一部が 10cm より遠い幻の表面として残る
  時間(新しい位置は 0.6秒で出る)。刻み 5cm では 0.53秒で消える(docs/2026-11-11-dynamic-shape.md の
  0.67秒はこの刻み 5cm の値)。**刻み 2.5cm は追従が遅く、刻み 5cm は精度が粗い**、という別の選択がある。
- A2 は、固定のセンサでは新しい箱に隠れた側の古い跡が消えない(move で ∞)。箱の誤差も大きくなる
  (古い観測が平均に残る)。固定のセンサの構成では A2 は使わない方がよい。

## 6. 実機の計測(今夜/明日、ESPr Developer 32 1台)

PowerShell で、リポジトリ直下(`C:\Users\koyab\Documents\dyne`)から。ファームはビルド済み
(bench-c5\build-esp32-classic\、3.5MB。アプリの領域を 3.9MB に広げた)。

1. ESPr を USB でつなぎ、ポート名を確かめる(以下 COM3 を置き換える):
   ```powershell
   Get-CimInstance Win32_PnPEntity | Where-Object { $_.Name -match '\(COM\d+\)' } | Select-Object Name
   ```
2. **基板の FLASH(BOOT、IO0)ボタンを押したまま** 書き込みを始める(書き込みが始まったら離してよい):
   ```powershell
   powershell -ExecutionPolicy Bypass -File bench-c5\build.ps1 -Target esp32 -Mode classic -Flash COM3
   ```
   - 書き込み後にモニタが開く。`#BENCH bench=done mode=classic` で完了(目安 **8〜12分**: 工夫の前の
     版の再生だけで約3分半かかる)。Ctrl+] でモニタを閉じる。もう一度測るときは EN(リセット)ボタン。
   - 計測中は Wi-Fi を使わない。
3. `#BENCH` で始まる行を**すべて**コピーし、メモ帳で bench-c5\esp32-log-speedup.txt に保存して:
   ```powershell
   .venv\Scripts\python.exe bench-c5\tools\interp_bench.py verdict bench-c5\esp32-log-speedup.txt
   ```

## 7. 線形メモリ 64KB の制約と PSRAM

- 縮小版はどの組み合わせも **線形メモリ1ページ(64KB)**。スタックを 6KB → 4KB にした(再生で測った
  スタックの使用は約1.2KB。A2 の印 136バイトを足すと 6KB では2ページになるため)。スタックはメモリの先頭に
  あるので、あふれた場合は範囲外の書き込みとして止まる(静的領域は壊れない)。
- f32 版は場の配列が半分(約14KB 空く)なので、同じ1ページで大きな区画(例: 3×3 分割の 49×37点 =
  1,813点)が入る。分割を粗くしてノードを減らす選択肢になる(統合の遅れ L が短くなり追従も速くなる)。
- DevKitC-VE(ESP32-WROVER-E、PSRAM 8MB)での緩め方:
  - ESP-IDF で `CONFIG_SPIRAM=y`、`CONFIG_SPIRAM_USE_MALLOC=y` にすると、`CONFIG_SPIRAM_MALLOC_ALWAYSINTERNAL`
    (既定 16KB)より大きい確保は PSRAM に置かれうる。WAMR の線形メモリはシステムの確保(malloc)なので、
    2ページ以上のアクターも PSRAM に置ける。bench-c5 の `bench=actor … linmem_psram=1` で置き場が分かる。
  - ただし PSRAM はキャッシュ(32KB)越しで内部 RAM より遅い。**速さを優先するなら線形メモリは内部 RAM に
    置き**(閾値を 65KB 以上に上げる、または `CONFIG_SPIRAM_TRY_ALLOCATE_WIFI_LWIP=y` で Wi-Fi・lwIP の
    バッファを PSRAM へ追い出して内部 RAM を空ける)、大きな区画が要るときだけ PSRAM に置く。PSRAM に置いた
    ときの遅さは未計測(WROVER が届いたら bench-c5 に `CONFIG_SPIRAM=y` を重ねて測る)。
  - node-esp32 の設定は今回変えていない(別の担当が作業中)。

## 9. ユーザーの判断事項

1. **刻み 2.5cm か 5cm か**: 2.5cm は壁の誤差 4mm・箱 5mm だが、固定の8台では古い跡が消えるまで 2.7秒。
   5cm は 0.5〜0.7秒で追従するが壁 8mm・箱 17mm、USD の折れ線が粗い。計算は 5cm が約 1.6倍速い。
2. **f32 を使うか**: 質の差は測定の揺れの範囲。ESP32 での効き目は今夜の計測で分かる(燃料はほぼ同じ)。
   使うなら、照合用のフル版も f32 で作る(scripts\build-actor-wasm.ps1 [7][8])。
3. **距離の反復の間引き2 を使うか**: 質の差はほぼ無く、反復の分(ノード5で約1割)が半分になる。
4. **首振りの構成での忘れ方**: A2(視野の中だけ減衰)は首振りでは必須に近い。視野の外の減衰 λ_out を
   いくつにするか(0.98 で隠れた古い跡が約10秒で消える。小さくすると見ていない壁も早く薄れる)。
5. **実験6の基準「2秒以内に追従」**: 首振り(1巡約4.3秒)では、箱を向くまでの待ちで 3〜4秒かかる。
   基準を「首振り1巡 + α」に変えるか、追従の実験だけ首振りを止めて固定の向きで測るか。
6. 文書の名前: 依頼どおり 2026-11-11 の名前にした(作成は 2026-11-13)。日付を作成日に合わせるなら
   名前を変え、コード・スクリプトの参照(`docs/2026-11-11-shape-speedup.md`)も直す。
