# 実験1 当日手順書(docs\2026-09-21-experiment1-runbook.md)

設計書 docs\2026-09-21-experiment1-design.md の§6を、当日に上から順に実行できる
チェックリストへ展開したもの。判定値はリハーサル(exp1-prep-report §2)に基づく。
段階1a(ESPr32×4: センサ付き3台+センサなし1台)を対象とする。
所要目安: 準備1時間+校正30分+本計測3run(各33分+入替)≈ 半日。

## 0. 前提(前日までに)

- [ ] 部品到着: 電池ボックス×6、ターミナルブロック×10、DHT20×3、ジャンパ線、電池20本
- [ ] 発注11反映済みファーム(step_period_ms等対応)を4台へ書き込み済み
      (ID切替は menuconfig。書き込みは2台ずつ)
- [ ] 電池1台テスト合格(§1)を事前に済ませておくと当日が軽い
- [ ] 測る直線の決定(推奨: 窓際→部屋奥、L=3〜4m)とメジャー・養生テープの用意

## 1. 電池駆動の初回テスト(初回のみ。10分)

1. [ ] 電池ボックス赤線→端子台→ジャンパ→**VIN**、黒線→**GND**(USBは挿さない)
2. [ ] スイッチON → 監視モニター(--quiet-obs)に online が出る
3. [ ] もう1台(USB給電で可)と2台で既定号令(--points 65 --steps 2000 --peers auto)
      → done×2、**CRC 0x3CC6AD26 / 0x8AC47DE7 と一致**(電源が変わっても計算不変)
4. [ ] そのまま30分放置 → status/rt が途切れない(電池の自動オフ問題が無いことの確認)

## 2. 組み立て(4台。各10分)

各ブレッドボードに: 電池ボックス+端子台+ESPr32、センサ付き3台は DHT20/BME280。
- [ ] node 0: DHT20(SDA=21, SCL=22, VCC=3V3, GND)
- [ ] node 1: BME280(同配線。**読めなければI2C番地0x76/0x77をmenuconfigで切替**)
- [ ] node 2: **センサなし**(常設評価区間)
- [ ] node 3: DHT20 または BME280(残り)
- [ ] 全台: 電池→端子台→VIN/GND。スイッチONで online になることを1台ずつ確認
※センサ割当を変える場合は号令の --sensor を per-node 指定に(mqtt_config.py --help 参照)

## 3. 校正(30分+集計5分)

1. [ ] センサ付き3台を**同一地点**(机上に寄せて)に置き、電池駆動で30分静置
      (号令は不要。sensorトピックの定期発行だけで足りる)
2. [ ] mqtt_log/sensor.csv の後半15分ぶんから各ノードの平均温度を算出
      (exp1_report.py に校正集計があればそれを使用。なければ表計算で平均)
3. [ ] 全体平均との差 = 各ノードの calib_offset(符号: 実測が高い個体は負のオフセット)
4. [ ] 初期値 init も決める: 校正後の全体平均(=部屋のいまの温度)を1つ控える

## 4. 配置(15分)

1. [ ] 直線上に4台を**等間隔**に固定(養生テープ)。並び順=ノードID順
2. [ ] メジャーで各ノードの位置[m]を測り、**ノード台帳に記録**(ID/位置/センサ種別/
      電池投入時刻)。全長Lも確定
3. [ ] 全台スイッチON → online×4 を確認(IPはpeers autoが解決するので記録不要)

## 5. 本計測(3run。各33分+入替5分)

共通号令(値は当日確定分を差し替え):

```
python scripts\mqtt_config.py --broker localhost --nodes 4 --points 65
  --steps 2000 --step-period-ms 1000 --peers auto --length <L>
  --alpha 1e-3 --outer-bc zero_grad --bc zero_grad
  --sensor <per-node指定> --calib <per-node指定> --init <全体平均>
  --gamma 0.3 --obs-period 10 --holdout <保留ノード> --start
```

- [ ] run1: --holdout 0 → done×4 まで放置(33分)。innov.csv が溜まることを開始5分で確認
- [ ] run2: --holdout 1(stopしてから再号令)
- [ ] run3: --holdout 3
- [ ] 各run間: 電池残(statusのheap相当ではなく動作継続)とセンサ値の妥当性を目視
- [ ] (任意run4) --bc transparent で run1 相当を1本(境界条件比較の実地データ)

## 6. 判定(exp1_report.py)

```
python scripts\exp1_report.py --rotation 0:<run1のinnov> 1:<run2> 3:<run3>
```

- [ ] **主基準**: モデル/ナイーブ比(ローテーション平均)< 1.0 =モデル優位
      (リハーサル参考値: 0.65。中央相当の保留は単独でナイーブ優位になりうる=正常、
       内訳にその構図が出ているかを確認)
- [ ] **副基準**: 保留イノベーション絶対値のローテーション平均 ≤ 1.0℃
      (リハーサル参考値: 0.823℃。端ノードは単独1.3℃台になりうる=原因分析つき記録)
- [ ] センサなし node 2 区間: 温度計かセンサ一時移設で2〜3点スポット実測し、
      場の予測値と照合(数値は台帳に記録。合否対象外)
- [ ] ヒートマップ生成(exp1_report.py の時系列HTML)を保存

## 7. 後段(全run合格時のみ・任意)

- [ ] mqtt_log/ 一式を日付フォルダへ退避(実測の正本。削除しない)
- [ ] 結果・台帳・気づきを設計会話へ共有 → 検収(発注11最終)→ レポート化 → コミット

## トラブル時の早見表

| 症状 | 第一容疑者 | 対処 |
|---|---|---|
| onlineが出ない | ホットスポットOFF/電池向き | 設定確認→電池ボックスの極性・スイッチ |
| 1台だけ沈黙 | 電池切れ・接触 | 電圧順: スイッチ→端子台ねじ→VIN挿し位置 |
| センサ err | 配線・I2C番地 | SDA/SCL確認→BME280は0x76/0x77切替 |
| running直後に停止 | (修正済みのはず) | 再発したらログ保存して報告 |
| step進まず | peersのIP不整合 | --peers auto で再号令(stop→start) |
| 途中で全停止 | どれか1台の電池切れ | statusで最後に消えた個体を特定→電池交換→stop→再号令 |
