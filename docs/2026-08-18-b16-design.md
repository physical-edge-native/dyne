- 2026-08-22: **全面改訂**。ユーザー方針決定を反映: 「実行中のモデルを分割する」

## 0. 前提の転換: 「分割する」から「分割されて生まれる」へ

初版は「動いている1つのモデルをどう切り直すか」を中心に据えていたが、
本プロジェクトの運用像はそうではない。**群は最初から分割されて生まれる**。
各ノードは誕生時から自分の担当領域と自分のモデルを持ち、動的に変わるのは
(a) 群への参加と離脱(領域の追加・消滅)、(b) 各モデルの大きさ、である。

この転換は要件の削減ではなく、技術的に最も厄介だった問題——実行中のNNの
知識を、切り直した領域構成へ引き継ぐ——を**構造的に回避する**設計判断である。
新しく参加するモデルは引き継ぐべき過去を持たず、境界での交換と物理条件から
学び始めればよい。

## 1. 定式化

クラスタの構成を C = (P, {A_i}, {W_i}) とする(P=領域の割当、A_i=ノードiの
NN構造、W_i=重み)。**動的構成**とは、実行中にCへ次のオペレータを適用すること。

### 主役オペレータ(必須要件)

| オペレータ | 意味 | 知識の扱い |
|---|---|---|
| **ADD(Ω_new)** | 新しい領域とその担当モデルの参加 | 引き継ぐ過去なし。境界交換+物理条件から学習開始(任意で隣接モデルからの外挿で温める) |
| **REMOVE(i)** | ノードiの離脱(担当領域の消滅) | 隣接ノードの界面が外部境界に変わる |
| **GROW(i) / SHRINK(i)** | ノードiのモデルサイズの動的変更 | 機能保存変換(変更の瞬間に入出力関係を変えない既存技法。Net2Net系)で乱れゼロ |

### 派生オペレータ(必須ではない。付録として仕様に保持)

SPLIT/MERGE/MOVE(実行中の領域の切り直し)は必須要件から外す。ただし
「場の標本値を共通通貨とする知識の持ち運び」(初版の案1)は道具箱に残す。
用途: ノードの恒久死からの回復(死んだ領域を隣が引き取る=実質MERGE)、
ADD時の初期値の温め。これらは将来の任意拡張とする。

### 機能保存の原則と評価軸(初版から不変)

どのオペレータも、適用の瞬間に群全体が表現する物理場を(近似的に)保存する。
評価軸: **乱れ**(適用直後の誤差の跳ね)、**回復時間**、**コスト**(通信量・計算量)。

## 2. 界面の情報共有フォーマット(標準の確定)

隣接領域の境目(界面)で何を受け渡すかの方式を、次のとおり標準化する。

**標準: 重複なし+境界量の交換。** 領域は重ねずに切り、界面ごとに
値と勾配(現行の40バイト固定長メッセージ、クラスタ一意の界面ID)を
論理ステップ同期で交換する。M0以来の実績方式であり、差分法アクターと
領域分解PINN型アクターの両方をこの1本で賄う。

**別モード(将来のCNN拡張時のみ)**: 重複あり+合成。画像的なセンサー配列を
CNNで扱う場合は境目付近の帯状データの交換が必要になるため、その時点で
プロトコル拡張(可変長ペイロード)として別途設計する。混同を避けるため、
仕様書の用語集に**「定義域分割」(座標入力の関数の担当範囲を切る。MLPでも可能)と
「テンソル分割」(入力配列を切る。CNN向き、全域注意型は原理的に困難)**の
区別を追加する。

**界面の一般化**(思想への追記、A-1.0へ): 界面は物理場の空間的な境目に
限らない。ロボット本体とエンドエフェクタの結合部(力・位置・トルクの交換)、
ロボット同士の連携面も、「独立に推論・学習する主体が、定められたフォーマットで
境界量を交換する界面」として同じ骨格に載る。界面フォーマットの標準化と、
界面残差(交換値の食い違い)を監視して各主体が適応する仕組みは、機器間の
インタフェースのずれを吸収する道具になりうる(Physical AIの社会実装への
本プロジェクトの提案軸。単体ロボットの巨大モデルを割るのではなく、
空間そのもの・機体の部位ごとの知能を界面で繋ぐ「補完」の立ち位置)。

## 3. トリガー(組み替え)

| 段階 | トリガー | 発火するオペレータ |
|---|---|---|
| 第1段階 | T1: 台本(時刻指定の注入) | 全部(実験用) |
| 第2段階 | T2: 界面残差(交換している値・勾配の食い違いの監視。追加通信ゼロ) | GROW(精度不足の検知) |
| 以後 | T4: 資源(メモリ・電池の逼迫) | SHRINK |
| 以後 | T5: 増減(ノードの参加・離脱) | ADD / REMOVE |

## 4. 最初のNN実装の確定

**座標入力の領域分解PINN型**(DD-PINN: 領域ごとに独立した小さなNNが
座標(x,t)→物理量を学習し、界面条件で繋ぐ確立された方式)とする。
理由: 界面の標準フォーマット(値+勾配)がそのまま界面条件になり、
プロトコル変更ゼロで差分法アクターと置換できる。CNN型・テンソル分割は
センサー配列を扱う将来段階で扱う。

## 5. M-S1実験計画(改訂)

- **M-S1a: ADD/REMOVE機構(差分法アクターで)**
  シミュレータに参加・離脱と界面の動的な張り替え(界面IDの払い出し・抹消)を
  実装。合格基準は2本立て:
  (i) 機構の無損失性 = **離脱→同一領域での復帰(状態引き渡しつき)の往復後も、
  中断なしの実行とビット一致**。
  (ii) 新規領域のADD = 問題自体が変わるためビット一致は定義できず、
  解析解(または収束参照解)との誤差が所定水準に達することを基準とする。
- **M-S1b: DD-PINN型アクター**
  シミュレータ用の小さなDD-PINNアクターを用意し、ADD(白紙からの参加学習)と
  GROW/SHRINK(機能保存変換)を実験。評価は乱れ・回復時間の定量基準
  (閾値は実験しながら定める)。
- **M-S1c: 自動トリガー(T2)**
  界面残差の監視と発火を実装し、「粗いモデルの群が、残差の大きい場所だけ
  自動的にGROWする」を観察する。群が自分で形を変える初デモ。

## 8. 新規性検証の結果(2026-08-22)

「学習中に領域分割を適応的に変える領域分解PINN」は**存在し、2025〜2026年の
活発な研究前線である**ことを確認した。主要な先行:

- **AB-PINNs**(arXiv:2510.08924, 2025→IOP MLST 2026): 学習中に部分領域が動的に
  変形し、さらに**残差の大きい場所へ新しい部分領域を追加する**。本設計の
  ADD+T2(界面残差トリガー)に相当する発想が単一計算機・学習時の枠で既出。
- **AS-PINNs**(2025): 敵対的学習で**界面位置を自動調整**(=MOVE相当)。
- **ADD-PINN**(arXiv:2605.08028, 2026): 粗い全域モデルの残差から分割位置を決め、
  **親から子への重み引き継ぎ(温め)**つきで部分ネットを生成(2段階・オフライン)。
- 分散実装の系譜: cPINN/XPINNのMPI並列(2021)、SC'23の分散PDEソルバ等は
  HPCクラスタ上の**静的**分割。

**共通する限定**: いずれも単一プロセス(または信頼できる高速結線のHPC)で、
最適化器が全域を見渡せる**学習時の適応**である。以下は依然として空白:

1. **分散自律**: 各ノードが自分の界面しか見えない条件での、中央調整者なしの
   再構成判断(私たちのT2は各ノードのローカル監視)。
2. **実行時・常時運転**: 有限の学習ジョブではなく、推論・同化・学習が
   続く中でのオペレータ適用(乱れ・回復時間という評価軸自体が新しい)。
3. **物理ノードと資源**: 参加・離脱が物理イベントであり、GROW/SHRINKの
   駆動要因に資源(メモリ・電池)が入ること。損失・分断のある実ネットワーク上の
   ワイヤプロトコルで界面条件を運ぶこと。
4. **アクター抽象**: 差分法とNNが同じ界面フォーマットの背後で交換可能なこと。

**主張の再配置**: 「適応的な領域分解PINN」を名乗ることはできない(既出)。
主張すべきは**「エッジ常駐モデル群の、分散自律・実行時・資源適応の再構成」**という
システム層である。AB-PINNs等は敵ではなく、T2(残差駆動の適応が有効である
こと)の単一計算機版の実証として引用する。M-S1cの比較実験には「全域を見渡せる
中央集権型の適応(AB-PINN型)」を対照群に置き、分散化の代償と利得を測る。
