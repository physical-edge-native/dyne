作成: Claude Code(下書き。ユーザーの編集前)。関連: docs/2026-11-11-two-week-plan.md の P9(拡散方程式以外の問題)・

この文書は内部向け。合意済みの用語(界面・境界・格子型アクター・メールボックス方式)はそのまま使う。

## 0. 要約

- 2次元の波動方程式 ∂²u/∂t² = c²(∂²u/∂x² + ∂²u/∂y²) を解く WASMアクター **crates/wave2d-actor** を作った。
  差込口(エクスポート関数の一式)は heat2d-actor と同じで、dyne-sim2d と実機の新経路(node-esp32/main/node_v2.c)が
  そのまま動かせる形。外周の境界は値固定・ゼロ勾配・吸収境界(1次)の3種。
- **ビット一致**: 分割 2×2 / 3×2(割り切れない)/ 4×4 / 1×4 / 3×3 / 2×3、損失・遅延・一時停止・分断の組み合わせ、
  3種の境界とその混在、安定の限界を超えて発散する場合も含め、**11シナリオすべて PASS (bit-exact)**。
  同じ引数の2回実行は標準出力がバイト一致(決定論)。縮小版(実機用)とフル版、ネイティブとWASMの結果も一致。
- **収束**: 解析解(定在波)との最大誤差が刻み半分で 1/4.002 → 1/4.001 → 1/4.000(2次精度)。
- **エネルギー**: 離散エネルギー(リープフロッグで厳密に保存される量)の相対変動は、2000ステップで
  値固定 1.4e-14・ゼロ勾配 1.8e-14(丸め誤差の水準)。吸収境界では 400ステップで 6e-12 まで減衰。
- **安定性**: フォン・ノイマンの方法でクーラン数(ν = c·Δt/h)の限界 1/√2 = 0.707107。有界な領域の行列の方法では、
  41×41点の値固定で 0.707652(最も細かいモードが領域に収まらない分だけ上がる)、ゼロ勾配と吸収境界で 1/√2。
  **dyne-sim2d で ν を掃引すると、発散はちょうど理論の限界から始まり**(値固定: 0.70765 は有界、0.7077 で発散)、
  1ステップあたりの増幅率の実測が理論のスペクトル半径と5〜6桁一致した(§5)。ただし限界のすぐ上(0.70712)では
  2000ステップでは発散が見えず、ステップ数を増やして確認した(§5.2 の※)。
- **実機の準備**: 必須のエクスポートはすべて揃い、縮小版は線形メモリ1ページ(64KB)。界面の1通は最大 456バイト
  (UDPの1データグラム 1472バイトに収まる)。実験10用に 4・8・16台の各ノードの期待ハッシュを作った(§7)。

## 1. 数値法の選択

### 1.1 更新式

正方格子(刻み h は x, y 共通)、5点ラプラシアン(上下左右の4点を使う2次の中心差分)と、時間の2次の中心差分
(3つの時刻を使う陽解法。リープフロッグ法とも呼ぶ):

    u^{n+1} = 2u^n − u^{n−1} + ν²·((u_W − 2u + u_E) + (u_S − 2u + u_N))、 ν = c·Δt/h

最初の1ステップだけは、初速度0のテイラー展開 u^1 = u^0 + (ν²/2)·(同じラプラシアン)。これは u^{−1} = u^1 と置いた
一般の式と同じ値になる(theory/guarantee/test_wave2d.py で確認)。

**小さな実装判断**: 3時刻の形(u と u^{n−1} を持つ)を選び、速度を別に持つ形(u と v = ∂u/∂t を半ステップずらして
持つ形)は選ばなかった。理由: (1) 数学的には同じ解法で、更新が1行・乗算1回で済む、(2) u^{n+1} を u^{n−1} の配列に
点ごとに上書きでき、状態が2配列で済む(縮小版の線形メモリ64KBに効く)、(3) 初速度0の初期条件しか使わないので
速度を持つ利点が無い。

### 1.2 界面で受け渡すもの(確認済み)

更新式が隣の点を参照するのは**現在の時刻 u^n だけ**で、u^{n−1} は自分の点しか使わない。よって界面で受け渡すのは
熱拡散と同じく「現在の状態の自分の端の値」1列だけで、ゴースト点(区画の外側に1点ぶん広げた枠)は1層で足りる。
実際、メッセージの中身は heat2d-actor と同じ(IFACE_BAND、1点あたり値1つ)で、全シナリオでビット一致した。

### 1.3 外周の境界

| 境界 | 選び方 | 実装 |
|---|---|---|
| 値固定(ディリクレ条件) | 面の種類 BC_DIRICHLET(値つき) | 毎ステップ端の点を値に戻す(heat2d-actor と同じ) |
| ゼロ勾配(ノイマン条件、自由端) | 面の種類 BC_ZERO_GRAD | ゴースト点 = 内側1点の鏡映(heat2d-actor と同じ) |
| 吸収境界(1次) | dyne_cfg の CFG_ABSORB(面ごとのビット。外周の面だけに効く) | 1次のエングクイスト・マイダ条件(外向きに出ていく波だけを通す近似条件 u_t = −c·u_n)をムーアの方法で離散化: 端の点 u_0^{n+1} = u_1^n + k(u_1^{n+1} − u_0^n)、k = (ν−1)/(ν+1)。まずゼロ勾配として全点を更新し、端の点だけ上書きする |

適用順は、吸収境界を面の順 W, E, S, N、その後に値固定(角の点は後の面が勝つ)。分割しても角の点は同じ1ノードが
持ち、同じ順で同じ式を計算するので、単一ノード解と一致する。

**小さな実装判断**: 吸収境界は新しい面の種類(BC_* の値)ではなく dyne_cfg のビットで選ぶ形にした。理由:
ファーム(node_v2.c)の設定注入は面の種類を "interface|dirichlet|zero_grad" の3つしか解釈しないが、dyne_cfg の
[キー, 値] の列はそのまま渡す。この形ならファームを変えずに実機でも吸収境界が使える。

吸収境界の安定性: 1次のムーアの条件は ν ≤ 1/√2 で安定(§4 の行列の方法で確認。限界は値固定のように上がらず、
ちょうど 1/√2)。一定値のモード(全点が同じ値)は吸収されずに残る(スペクトル半径がちょうど1)。斜めに入る波の
反射は残る(1次の条件の性質)。

### 1.4 初期条件(dyne_cfg で選ぶ。初速度はどれも0)

| CFG_IC | 初期条件 | 用途 |
|---|---|---|
| 0(既定) | A·sin(mπx)·sin(nπy) | 値固定0の正方形の定在波。解析解 cos(√(m²+n²)·π·c·t)·(同じ形) |
| 1 | ガウス型の山 A·exp(−((x−gx)²+(y−gy)²)/(2σ²)) | 一般の波の伝わり・安定性の掃引・実機の場面 |

## 5. 安定性: フォン・ノイマンの方法・行列の方法・実測の掃引

### 5.1 理論(theory/guarantee/wave2d.py、test_wave2d.py)

- **フォン・ノイマンの方法**(一様で無限に広い格子): u = gⁿ·exp(i(jξ+kη)) を代入すると
  g² − 2bg + 1 = 0、b = 1 − 2ν²(sin²(ξ/2)+sin²(η/2))。2根の積が1なので |b| ≤ 1 なら |g| = 1(減衰も増幅もしない)、
  |b| > 1 なら片方の根が |g| > 1。b の最小は ξ = η = π で 1 − 4ν² なので、**安定 ⇔ ν ≤ 1/√2**。
  ちょうど 1/√2 では g = −1 の重根になり、振幅が時間に比例して増える(弱い不安定)。
- **行列の方法**(有界な領域・実際の境界処理): 状態 (u^n, u^{n−1}) → (u^{n+1}, u^n) の1ステップの写像
  (2時刻を並べた「コンパニオン形式」の行列)を、アクターと同じ式・同じ境界処理を単位ベクトルに当てて組み立て、
  スペクトル半径(固有値の絶対値の最大)が 1 + 1e-6 を超えるかで判定し、二分法で限界を探す。
  値固定・ゼロ勾配では空間の作用素の固有値 λ から ν* = 2/√|λ|max でも求まり、両者は一致した。
  (許容を 1e-6 にした理由: 一定値のモードが g = 1 の重根になり、計算した固有値が √丸め誤差 ≈ 1e-8 ずれるため。)
- Python の模型(actor_step)がアクターと同じ計算をしていることは、41×41・400ステップで dyne-sim2d の結果との
  差が最大 7.7e-16(初期条件の exp/sin の計算方法の違いによる丸めの差)であることで確かめた。

| 格子 | 値固定 | ゼロ勾配 | 吸収境界 |
|---|---|---|---|
| 無限(フォン・ノイマンの方法) | 0.70710678 | 0.70710678 | − |
| 11×11 | 0.71592096 | 0.70710678 | 0.70710680 |
| 21×21 | 0.70929330 | 0.70710678 | 0.70710679 |
| 41×41 | **0.70765236** | 0.70710678 | (31×31 で ν = 0.7071 は ρ = 1、0.70712 は ρ = 1.0029) |

値固定では、無限格子で限界を決める最も細かいモード(市松模様、ξ = η = π)が値0の外周と両立しないので、限界が
1/(√2·sin((n−2)π/(2(n−1)))) までわずかに上がる。ゼロ勾配・吸収境界では市松模様が許されるので 1/√2 のまま。
41×41 の吸収境界はコンパニオン行列が3362次になり、固有値計算が手元で数十分かかったため打ち切った(31×31 で代用)。

2000ステップでは有界だった(スクリプトの判定は「一致: False」)。原因は判定の感度: 増幅されるのは市松模様の
モードだけで、ガウス型の山にはこの成分がほぼ含まれない(丸め誤差の水準から育つ)ため、1.0123²⁰⁰⁰ ≈ 4e10 倍でも
1 に届かない。ステップ数を増やして確かめた(dyne-sim2d、2×2、損失なし):

| ν = 0.70712 | 5800ステップ | 6000ステップ | 増幅率 実測 | 理論 |
|---|---|---|---|---|
| ゼロ勾配 | 1.76e13 | 2.03e14 | 1.012304 | 1.012304(41×41) |
| 吸収境界 | 7.11e-7 | 8.34e-7 | 1.0008 | (41×41 は未計算。31×31 で 1.0029) |

ゼロ勾配は理論どおり発散し、増幅率も一致した。吸収境界は 0.70712 でも増えてはいるが、6000ステップでもまだ
8e-7 と小さく、41×41 の行列の方法の値が無いので定量的な照合はできていない(限界のすぐ上では吸収で失う分と
競うため増え方が非常に遅い。未解決として残す)。

**結論**: 発散の始まる ν は、値固定で 0.70765 と 0.7077 の間(理論 0.707652)、ゼロ勾配で 0.7071 と 0.70712 の間

## 8. 加速度センサ(IMU)の観測の取り込み(設計メモ、実装なし)

- **観測量**: IMU は加速度 a = ∂²u/∂t² をノードの位置で測る(u が面に垂直な変位の場合)。注意: 机の板の振動は
  曲げ波(4階の方程式)で、本アクターの膜の波動方程式とは別の物理。膜・水面のような対象か、模型として割り切るかの判断が要る。
- **取り込み方(案)**: 観測点の近傍(数点の重み)で、加速度の項を観測へ寄せる(ナッジング = 観測との差に比例して
  モデルを引き寄せる方法):
  u^{n+1} = 2u^n − u^{n−1} + Δt²·[c²L u^n + γ·w(x)·(a_obs − c²L u^n)]、0 ≤ γ ≤ 1。
  γ = 1 の点では観測の加速度で駆動し、0 なら従来の式。変位そのもの(加速度の2回積分)へ寄せる案は、積分のずれ
  (ドリフト)が大きいので勧めない。
- **安定性**: 観測点で c²L の係数が (1−γ) 倍になるだけなので、局所的な実効の速さは下がり、ν の限界は悪化しない
  (観測項は外力として入る)。行列の方法で確かめられる(未実施)。
- **ビット一致**: 観測は格子型アクターの測距フレームと同じく、ステップ番号つきのメッセージで観測するノードの受信箱へ
  入れれば、分割解と単一ノード解の一致を保てる(観測は自分の区画の点にだけ効く)。
- **限界(重要)**: 実時間で取り込むには、シミュレーションの1ステップ Δt が実時間の1ステップと等しい必要がある。
  1ステップ約80ms(1次元の実測)・ν = 0.5・h = 1.25cm なら、扱える波の速さは c = 0.5h/Δt ≈ 0.08 m/s。
  机の振動(数百 m/s)は桁違いに速く、実時間の取り込みは不可能。可能性があるのは、遅い波(浅い水槽の表面波など)、
  または記録した IMU のデータを時間を引き延ばして再生する取り込み。IMU の標本化の速さより、ノードの計算・通信の
  速さが律速になる。

## 9. 未解決の点・ユーザーの決定事項

### ユーザーの決定事項

- **U3 吸収境界の選び方**: dyne_cfg のビット(現状。ファーム無変更で使える)か、面の種類に BC_ABSORB を足すか
  (ファームの設定注入の解釈も変える)。
- **U4 実機に載せる版**: 縮小版(64KB、区画1辺48点まで)か、C5 の PSRAM を使うフル版か。
- **U5 積み込む wasm の切り替え方法**: menuconfig での選択、OTA での配布など(firmware-wire-v2 の文書の未決事項と共通)。
- **U6 実験10の場面**: §7.3 の 81×81・400ステップ・ガウス型の山でよいか。
- **U7 IMU の取り込みを進めるか**: 進めるなら対象(遅い波か、記録の再生か)。

### 未解決・注意

- dyne-sim2d の1行目の表示 `r = …` は熱拡散用の量で、波動方程式では意味が無い(既存の行を変えないため残した。
