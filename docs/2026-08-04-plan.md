# 2026-08-04-開発メモ(docs\2026-08-04-plan.md)

## メモ
ツールチェーンはオーバースペック気味で、ツールチェーンが提供するすべての機能を要求するユースケースは現状少ないという問題がある。ただし、エッジコンピューティングや分散コンピューティングの発展した5年後、10年後の世界に存在する需要を想定して、このプロジェクトではあえて機能を削らずに実装する。
開発を進めながら、以下について考え続けたい。

- エッジコンピューティングや分散コンピューティングの発展した5年後、10年後の世界にはどんな需要があり、そこから逆算して今開発されるべきものは何か。
- 物理モデルやPhysicalAIモデルを分割し、エッジデバイス上で協調推論や分散学習、データ収集が一つのプラットフォーム上で行えるようになったとき、どんなことが実現可能になるのか。

## 目標設定の変更
以下の2つの目標に挑戦する。
- 目標1: マイコンだけで何ができるか
- 目標2: 組込みLinuxを許容すると何ができるか
この整理から、WASMを実行形式に選ぶ意味が明確になります。目標1のチップ(Xtensa/RISC-V)と目標2のボード(Arm)はISAが違うため、普通なら別々にコンパイルし直す必要があります。ところがWASMを共通の配布形式にしておけば、同じ.wasmを配って各ノードのランタイムがそれぞれの機械語にAOTする、という形にできます。実際WAMRはこの用途を想定しており、再書き込みなしで動的にコードを読み込み、AOTでネイティブに近い性能を出し、無線経由でアプリ論理を更新する、といった使い方ができます。目標1と目標2で実行環境(通訳方式とAOT方式)は変えつつ、配布物とソースコードは1本で保てる、という設計上の利点です。
