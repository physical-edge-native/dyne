# 2026-11-21 加速度・角速度センサ 7台の実機の記録(場所A、run2)の解析

作成: 2026-11-21(Claude Code)。GitHub dyne Issue #129(記録の公開と英語の報告)、#121(解析の道具の修正)。
記録: measured/2026-11-21-siteA-imu/。英語の報告: docs-site/results/imu-2026-11-21.md。

## 1. 何をしたか

- ESP32 ×7 に Modulino Movement(LSM6DSOX)を1台ずつ付け、1枚の合板に貼った(向きは目で合わせ、±10° 程度)。
- 7台とも PC の時刻同期のサーバに合わせてから記録(1回目の run1 は3台が未同期だったので使わない)。
- 出力 12.5 Hz、1 秒ごとにまとめて MQTT で送る(1台あたり約1通/秒の上限、Issue #114)。
- 手順: 静止 13分半 → 傾き(角度計の読み 0.00° / 9.00° / 17.70→17.60° / 0.10°)→ 静止 20 秒・手で揺らす 60 秒・静止 20 秒。
- 隣だけの融合のアクター(crates/imu-fusion-actor)は動かしていない。記録を PC で解析した。

## 2. 解析の道具の誤り(Issue #121、PR #128)

最初の解析では「台数を増やすとノイズが増える」(N=2 で ay の標準偏差が 1台の約30倍)と見えていた。原因は道具の側で、
104 Hz を前提にした 0.2 秒の区間に 12.5 Hz の標本が 2〜3 個しか入らず、ある台の標本が無い区間で平均がその台のゼロ点のずれ
(台の間で最大 0.7 m/s²)だけ跳ねていた。区間の長さを記録の周期から決め(1 秒)、台ごとのゼロ点のずれを引いてから統計を取るように直した。

## 4. 読み方と限界

- 角速度は √N どおり。加速度の水平の成分は、取り付けのずれた1台を除けば √N に近い。az は6台でも √6 に届かず、原因は未確認。
- 傾きは約2%小さく出る。ゼロ点のずれが重力の向きに入り、校正なしでは台の傾きと分けられないことが一因(合成の記録で、0.3 m/s² の
  ずれは 10° を約 0.1° ずらす)。角度計自体の精度は確かめていない。
- 揺らしでは、同期した時刻印のほうが台どうしの一致が約2倍よい。残りの 0.037 rad/s は、板の上の向きのずれ ±10° からの見積もり
  (sin 10° × 0.19 ≈ 0.033)と同じ程度。
- 1回・1枚・1部屋の記録。12.5 Hz は速い動きには足りない(#114 で送信を速くする)。
