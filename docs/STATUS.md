## M-S1a(完了、詳細はレポート)

### 前半(完了、2026-08-22)

- アクターに dyne_set(i, value) を追加(状態書き込み。crates/heat1d-actor)
- シミュレータに --handover node@leave_ms:rejoin_ms を実装:
  離脱→温度配列の取り出し→**新インスタンス**をdyne_init→dyne_setで移植→復帰。
  検証: 単体/2箇所同時+ロス10%/全カオス複合、すべてビット一致。決定論維持。
- 得られた設計原則: **状態移送で運ぶのは物理状態のみ。通信状態(受領記録・
  ゴースト値)は運ばず、リセットしてプロトコルの再送・応答再送に治させる**
  (受領記録だけ引き継ぐと部分受領凍結の場合に解が壊れるバグを実際に踏んだ)。

### 後半(完了、2026-08-24): シナリオC=解釈βの領域拡張ADD

意味論(ユーザー決定済み): 既定=解釈α(不在の隣は「まだ来ていない参加者」、
界面で待つ)。**解釈β(不在の隣は「まだ存在しない領域」、その面を外部境界
u=0として計算を止めずに進め、参加時に界面へ切り替える)は明示指定のみ**。

実装(crates/dyne-sim): `--add node@t_ms`(β意味論の新規参加)、
境界条件の切り替え=再init+dyne_set復元(handover機構の再利用)+界面IDの
動的登録、複合参照解(ホスト側純Rust・演算式はアクターと同一)、
界面残差 |grad_A - grad_B| の毎ステップ記録(`--residual-csv`でCSV出力可)。

検証(すべてPASS、詳細はレポートのマトリクス): 複合参照解とのビット一致
(2/3/4/8ノード、右半分・中間・両端の参加、カオス複合・handover併用込み)、
乱れピークと回復時間の計測・報告、既存全検証(M-S0系+handover)の回帰維持、
決定論維持。

主な知見(詳細はレポート): (1) 界面の動的登録は「(界面ID,ステップ)キーの
取り置き」で握手プロトコルなしに成立。(2) 乱れピークは参加直後とは限らない
(端参加で約80ステップ遅発を観測)。(3) 残差の絶対水準は界面ごとに大きく違う
ため、**T2の閾値は各界面の移動ベースラインに対する相対値にすべき**(M-S1cへ)。

残課題(M3以降): 参加ステップの整列 S = 1 + max(隣接の現在ステップ) は
シミュレータ内の大域情報に依存。実システムでは隣接との問い合わせ・応答で
合わせる必要がある。隣接ノード同士の同時ADDは未対応(assertで拒否)。

完了処理: レポート docs/2026-08-24-ms1a-report.md(下書き)作成済み。
仕様書C章にM-S1a完了を反映し、M-S1をM-S1a/b/cに細分化済み(2026-08-24)。

## M-S1b(実装・検証済み、詳細はレポート)

決定(2026-08-25、ユーザー): 1ステップ=時刻離散化PINN / 学習コード=共有Rustクレート+
WASM化 / 合格基準=決定論はビット一致・精度は解析解・動的構成は乱れと回復時間。

- crates/heat1d-pinn-actor(新規): 差分法アクターと同じC ABI+任意エクスポート
  (dyne_cfg / dyne_set_bc / dyne_resize / dyne_eval)。既定 幅16×1層、LM法5反復/ステップ。
  ビルド: `cd crates\heat1d-pinn-actor && cargo test --release && cargo build --release --target wasm32-unknown-unknown`
- crates/dyne-sim: `--pinn key=val,...` / `--add-warm` / `--resize node@t_ms:width` /
  `--error-csv`。学習型では bit-exact を n/a とし誤差で報告。差分法アクターの回帰は不変
  (PASS bit-exact)。学習型の実行には `--ram-cap-kb 4096` が必要(LM法の行列)。
- 主要結果: 1/2/4/8ノードの解析解誤差 2.5e-4/3.3e-4/6.1e-5/8.4e-5、16ノードで 2.1e-2
  (劣化)。GROW 16/16点ビット保存。ADDは解釈βの初期不連続がNNの誤差を支配(機構と分離不能)。
- 実装上の判断(事後報告): 界面条件を「差分法と同じ陽解法の式で端点の新値を作る」方式に
  変更(初版のゴースト点一致は多ノードで誤差蓄積、350倍差)。最適化器はAdam/SGDが不成立で
  LM法。既定構成は幅16×1層(STATUS旧記載の2〜3層はLM法の行列上限と両立せず)。

### 1(b) 16ノード劣化対策(2026-08-26、完了)

方策: 方程式残差の評価点を格子点だけでなく格子間隔の内部点にも置く(設定キー
`sub`=細分数、既定1=従来どおり。`--pinn sub=2`)。内部点の「前ステップの値」は
前ステップ終了時のNNをその点で評価した値(u_prevを「前ステップのNNが表す関数」と
みなす)。アクター内で完結し、通信・仕様は不変。

結果(2000ステップ、解析解との最大誤差):

| sub | N=1 | N=4 | N=8 | N=16 |
|---|---|---|---|---|
| 1(従来) | 2.5e-4 | 6.1e-5 | 8.4e-5 | 2.1e-2 |
| 2 | 1.2e-4 | 8.7e-5 | 8.3e-5 | **3.1e-5** |
| 4 | 2.0e-4 | 2.5e-5 | 8.3e-5 | 7.4e-2 |

- **sub=2 で16ノードの劣化が解消**(2.1e-2 → 3.1e-5、差分法16ノードの8.0e-5より良い)。
  誤差は時間とともに単調減少(sub=1は単調増加だった)。劣化の原因は「1ノード5点では
  残差評価点が不足」で確定。粗い補正(全域を見る粗いモデル)は不要だった。
- **sub=4 は16ノードで逆に悪化**(7.4e-2、単調増加)。N=1〜8では問題なし。原因は未解明
  (5格子点に17評価点、49パラメータの構成で系統的な偏りが増幅する)。既定はsub=1のまま
  (既報の数値の再現性のため)、**16ノード以上では sub=2 を推奨**。
- sub=1 の4本は既報の値と完全一致(変更が既定動作を変えていないことの確認)。
- 計算コスト: sub=2 で約2倍、sub=4 で約4倍のステップ時間。
- sub=2・16ノードでの確認(すべて合格): 決定論=カオス注入(損失5%、遅延揺らぎ20ms)+
  handover(node5)を2回実行して全出力一致、最終誤差1.0e-4。GROW(node7 16→24、step251)=
  機能保存 4/4点ビット一致、最終誤差3.1e-5(無操作と同値)。SHRINK(16→8、温め50)=
  最終誤差3.1e-5(無操作と同値)。
