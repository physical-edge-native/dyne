### 前半(完了、2026-08-22)

- シミュレータに --handover node@leave_ms:rejoin_ms を実装:
  離脱→温度配列の取り出し→**新インスタンス**をdyne_init→dyne_setで移植→復帰。
  検証: 単体/2箇所同時+ロス10%/全カオス複合、すべてビット一致。決定論維持。
- 得られた設計原則: **状態移送で運ぶのは物理状態のみ。通信状態(受領記録・
  ゴースト値)は運ばず、リセットしてプロトコルの再送・応答再送に治させる**
  (受領記録だけ引き継ぐと部分受領凍結の場合に解が壊れるバグを実際に踏んだ)。

### 後半(次の作業): シナリオC=解釈βの領域拡張ADD

意味論(ユーザー決定済み): 既定=解釈α(不在の隣は「まだ来ていない参加者」、
界面で待つ)。**解釈β(不在の隣は「まだ存在しない領域」、その面を外部境界
u=0として計算を止めずに進め、参加時に界面へ切り替える)は明示指定のみ**。

実装内容:
1. CLI: `--add node@t_ms` … 指定ノードはβ意味論で仮想時刻tに新規参加。
   開始時は不在扱い(隣接ノードは当該面をBC_DIRICHLET_ZERO・界面登録なしで初期化)。
2. 参加時の隣接ノードの処理 = **境界条件の切り替え**。アクターのbcは初期化時
   固定なので、再初期化+状態復元で実現する: u[]を読み出し→dyne_init(同じ区間、
   当該面をBC_INTERFACEに変更)→dyne_setで書き戻し(handoverと同じ機構の再利用)。
   あわせて界面IDを動的に登録し、以後は通常の境界交換。
3. 参加ノードのステップ番号は隣接ノードの現在ステップに揃える(シミュレータ内
   では大域情報で可。実システムでの合わせ方はM3以降の課題としてSTATUSに残す)。
4. **複合参照解**: 「同じイベント時系列を単一の配列で再現する逐次計算」を
   ホスト側純Rustで実装(左半分のみ・右端0固定で進め、参加ステップで右半分を
   sin初期値で埋めて全域計算に切替)。演算式・順序をアクターと厳密に同一に
   すること(u[i] + r*(u[i-1] - 2.0*u[i] + u[i+1])、sin_piのテイラー式も同一)。
   → **シナリオCもビット一致で検査できる**。
5. 計測系(初出番): (a) 界面残差=界面両側の勾配の食い違い |grad_A - grad_B| を
   毎ステップ記録(これはM-S1cの自動トリガーT2のセンサーの前倒し実装)。
   (b) 乱れ=参加直後の残差ピーク、回復時間=残差が参加前中央値の2倍を
   下回るまでのステップ数。レポートに数値で出す。

合格基準: (i) 複合参照解とのビット一致、(ii) 残差ピークと回復時間が
計測・報告されること、(iii) 既存全検証(M-S0系+handover)の回帰維持。

完了時: docs/2026-08-XX-ms1a-report.md を書き、仕様書C章のM-S1aを完了化。
