# 2026-09-06-デバイス・センサ計画(docs\2026-09-06-hardware.md)

本書は、デジタルツイン構築実験(実験1〜5)の機材構成と発注計画の確定記録である。
作業順序の正本(docs\2026-09-01-roadmap.md)への反映は保留中(2026-09-06時点)。

用語: **ノード**=マイコンボード1台(必要に応じセンサを接続)を単位とする群の
構成員。**コントロールプレーン**=ユーザーのPC上の管理側(初期設定の注入・
学習済み初期モデルの供給・接続時のみの観測)。**受信信号強度(RSSI)**=無線
電波の強さの実測値。**Wi-Fi測距(FTM)**=Wi-Fiの電波の往復時間から距離を
見積もる機能。**I2C**=2本の信号線でセンサを読み書きする接続方式。

## 1. 実験フェーズの構成

全実験共通: コントロールプレーンはユーザーのPC(MQTTブローカーを含む)。
全ノードは同一ファームウェアで、役割は起動時の設定注入で決まる。

### 実験1: 温度場+電磁場(追加購入センサ最小)

- 温度ノード×5: ESPr Developer 32 Type-C ×4(各台にDHT20温湿度センサ、
  救出失敗時はBME280温湿度気圧センサ)+ Raspberry Pi Pico 2 WH ×1(BME280)。
  各自が担当区間の温度を計測し、区間の温度分布を推定する。
- ESP32-C6搭載ボード ×2(現候補: Seeed Studio XIAO ESP32C6。検証に必須なのは
  チップがESP32-C6であることで、ボードは在庫により選定可): 序盤は無線検証専任(RISC-Vでの事前コンパイル
  可否、Thread通信、zenoh-picoのメモリ実測)。検証完了後、BME280を1台に
  載せて温度ノードに合流。
- ESPr Developer S3 Type-C(USBシリアル変換ICなし・PSRAM 8MB)×1:
  学習型モデルの実機試験ノード。センサ接続なし(USB給電のみ)で、温度場の
  1区間を学習型で担当する。
- **電磁場は追加ハードなし**: 全ノードが互いの受信信号強度(RSSI)を常時測定し、
  電波強度の空間マップを構成する。

### 実験2: 立ち上げ後の位置推定+温度場(機材は実験1と同一)

追加はソフトウェアのみ。受信信号強度とWi-Fi測距(FTM)で各ノードの粗い相対
位置を推定し、担当領域の割り当てを人手設定から自律決定へ切り替える。
Raspberry Pi Pico 2 WH は測距機能の差から、位置既知の基準点(アンカー)役。

### 実験3: 立ち上げ後の位置推定+測距による形状構成(二段構え)

目的: ロボットの強化学習に耐える品質の形状デジタルツイン。品質の基準は
2次元LiDAR(例: RPLIDAR C1級)とし、**分散のセンシングはVL53L5CX**
(8×8=64方向の距離を一度に返す小型測距センサ。可動部なし)が担う。

**第一段(10月)**:
- 2次元LiDAR ×1: **答え合わせ用の基準器**。全域を見る主体ではなく、分散側が
  作る形状の精度を評価する参照解の役割(温度場実験でPC上の単一ノード解を
  参照にするのと同じ構図)。受け皿はLinux機が必要だが、Raspberry Pi Zero 2 W
  欠品のため当面PCに直結して開始。
- VL53L5CX ×4: ESPr Developer 32 Type-C の各台に1個接続。各ノードが自分の
  位置・向きから8×8の深度を取得し、担当領域の形状(符号つき距離関数=各点から
  最寄りの壁面までの距離を表す関数)を局所学習、隣接ノードと境目で整合させる。
  視野約63度・室内有効距離3〜4mという制約は、複数ノードの視点統合という
  本実験の主題とかみ合う(1台では見えないことが分散の価値を際立たせる)。
- 合否: 分散側の形状とLiDAR基準の差、および遮蔽(1視点から見えない領域)を
  複数視点でどれだけ埋められるか。

**第二段(予算確定後)**: 台数拡大(2巡目ノードへのVL53L5CX追加、または
安価な小型LiDARへの置き換え検討)と、ロボット強化学習品質の本評価。

**不採用の記録(2026-09-06)**: VL53L1X+サーボモーターの首振り走査は不採用。
理由=信頼性が機械側(角度誤差・ギアの遊び・電流スパイク・走査2〜5秒)に
律速され、本題(分散測距の融合)の前に機械の較正実験になってしまうため。
可動部のないVL53L5CXが同じ役割をより高い再現性で果たす。
練習台も本番と同一のVL53L5CXとする(今回便で1個先行入手し、I2C接続・
専用ファームウェア読み込み・メモリ消費をESPr Developer 32上で事前確認)。
VL53L1Xの購入は取りやめ(2026-09-06。用途がサーボ案廃止と主役交代で消滅)。

### 実験4: 立ち上げ後の位置推定+流体

FS3000風速センサ ×2〜3 を ESPr Developer 32 に接続し、扇風機で作った
**一方向の流れ**の上流・中流・下流に配置。温度ノードを併用し温風を流せば
温度と流れの同時計測になる。室内の一般気流の推定は難度が高いため、
今年度は一方向流のシナリオに限定する。

### 実験5: 統合+新規センシング

実験1〜4の全機材+2巡目ノード8台(機種は10月末の実測結果で確定)。
任意追加: BH1750照度センサ、3軸磁気センサ(安価に物理量を増やせる)。
年度末デモ=温度+形状+流体の複合デジタルツイン。ロボットの強化学習
そのものはシミュレータ側(目標タスク2)で行い、本実験群のデジタルツインと
接続して示す(実機ロボットの走行は含まない。2026-09-06確認)。

## 4. 設計判断の記録(2026-09-06)

- **XIAO用拡張ボードは不採用**: 本体へのピンヘッダはんだ付けが結局必要で、
  台数ぶん揃えると割高。代替=はんだ付けサービス済みモジュール+ジャンパ線+
  ブレッドボード。
- **ESPr Developer 32(Xtensa)の位置づけ**: 事前コンパイル不成立のため通訳
  実行(実測79.5ミリ秒/ステップ)だが、温度のような遅い物理は時間刻みが
  秒オーダーで足りるため**場ノード・センサノードの主力として有効**。重い
  学習型はESP32-C6/S3側で検証し、重すぎる場合はESPr32を「センサ+
  軽量計算」役へ降格する退避路を持つ。
- **DHT20の救出**: 値が取れない原因の定番はI2Cの初期化待ち(電源投入後
  約100ミリ秒)・番地0x38の確認・SDA/SCL配線の取り違え。ボード到着後、
  I2Cスキャンから切り分ける。救出成功なら温度センサの追加購入は最小で済む。
- **VL53L1Xの購入取りやめ**(2026-09-06): 当初の用途(サーボ走査の部品・
  点測距の予備実験・練習台)がサーボ案廃止とVL53L5CX主役化で消滅または
  弱体化したため。練習台は「本番と同じ機材で」の原則に従いVL53L5CX 1個を
  今回便に前倒し(メモリ制約の先行確認を兼ねる)。
- **実験3の構成**(2026-09-06確定): LiDARは1台のみとし役割を「答え合わせ用の
  基準器」に限定(全域を見る主体を群れに常駐させない思想と整合)。分散の
  センシングはVL53L5CX×4が担い、センシングも処理も分散の完全形を第一段から
  実施する。VL53L1X+サーボ走査は機械的信頼性の低さ(角度誤差・給電・速度)を
  理由に不採用。台数拡大と強化学習品質の本評価は予算確定後の第二段。
