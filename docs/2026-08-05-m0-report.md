# 2026-08-05-M0完了レポート(docs\2026-08-05-m0-report.md)

## 目的と結果

M0の目的: 1次元熱伝導方程式を2分割し、PC上の2つのWASMプロセスで
Boundary Sync Protocol(ステップ同期・P2P/UDP)を検証し、A-3(SDK)と
A-4(境界同期)の仕様を実地で固める。

**結果: 合格。** 2ノード分割の協調推論が、単一ノード(分割なし)の解と
**全65格子点でビット完全一致**(最大差 0.0)。解析解 u(x,t)=sin(πx)e^(-απ²t)
との誤差は L2=5.6e-5 / L∞=8.0e-5 で、空間2次精度の理論値と整合。

## 構成

```
dyne/
  crates/heat1d-actor   … WASMアクター。#![no_std]・ヒープなし・純計算体。
                          DyneSolverトレイト(A-3)をC ABIエクスポートに写像。
  crates/dyne-host      … ホストランタイム。wasmi(通訳方式)でアクターを実行し、
                          通信ロジック(UDP境界同期・BSPループ)を注入する。
  crates/dyne-proto     … BoundaryMsgのワイヤ形式(40バイト固定長・CRC32)。
```

実行条件: 全域[0,1]を65点(h=1/64)。ノードA=[0,0.5]の33点、
ノードB=[0.5+h,1.0]の32点(重複なし分割)。α=1, dt=1e-4, 2000ステップ(t=0.2)。
陽解法(前進オイラー+中心差分)、安定条件 α·dt/h² = 0.41 ≤ 0.5 をホストが検証。

## 実測データ(限界レポート第1号)

- アクターWASMサイズ: **2,184バイト**(opt-level=z, LTO, panic=abort)。
  ESP32のフラッシュ(4MB)に対して無視できる大きさ。ヒープ非使用・静的配列のみで、
  M1でのWAMR移植を阻む要素は現時点でない。
- 実行時間: 2000ステップ・UDPロックステップ込みで約0.7〜2.3秒(PC、通訳方式のwasmi)。
  M0は正しさの検証が目的のため速度は未最適化。実機の速度はM1で計測する。
- ワイヤ: 1境界面×1ステップ = 40バイト固定長。CRC32検証つき。

## プロトコル上の知見(仕様A-4へ反映すべき事項)

M0で3つの問題を実際に踏み、いずれもプロトコル仕様として一般化した。

1. **起動レースと過去ステップ再送応答**。先に起動したノードのstep 0メッセージは、
   相手のソケットbind前に消失する(UDPでは静かに落ちる)。送信側は先へ進んでしまい、
   「現在ステップのみ再送」では相手が永久に待たされるデッドロックになる。
   対策: BSP同期ではノード間のずれが最大1ステップであることを利用し、
   **各ノードは直近2ステップ分の送信済みメッセージを控えとして保持し、
   過去ステップの重複メッセージを受信したら控えを再送して応答する**。
   この一つの機構が、起動レースと走行中のパケット消失の両方を治癒する。
   (実測: 2000ステップ走行でresend=16, replay=1が発生し、自動回復した。)

2. **終了時ドレイン**。先に最終ステップを終えたノードが即座に終了すると、
   相手は最終境界値を受け取れないまま置き去りになる(再送応答する相手が消える)。
   対策: 終了前に一定時間(M0では500ms)受信を続け、再要求に応答してから終了する。

3. **面IDの意味論の曖昧さ(実際に混入したバグ)**。メッセージのface_idを
   「送信者から見た面」と定義したため、受信側で反対面へ変換する必要が生じ、
   変換漏れが2つある受信経路の片方にだけ混入した。症状は「界面の1点が
   ステップ2で4.0e-4ずれ、以後sin形状に拡散して残る」という発見しにくいもので、
   ゴースト値のトレースと単一ノード解との突き合わせで特定した。
   対策(仕様変更提案): face_idをノード視点の相対値ではなく、
   **manifestで規定するクラスタ全体で一意な「界面ID」**にする。
   送受信どちらの視点でも同じIDになり、変換そのものが不要になる。

## 設計上の確認事項

- アクター/ホスト分離(A-3)は機能した。アクターは通信・時刻・同期を一切知らず、
  同一バイナリが「単一ノード全域」と「分割サブドメイン」の両方で動いた。
- 重複なし領域分割では「相手の端点値=自分のゴースト点」が厳密に一致し、
  境界メッセージ(値+勾配)のうち値だけで陽解法の協調推論が完結する。
  勾配はプロトコルに載せたまま(将来のXPINN型界面損失・整合性検査用)。
- ビット一致検証は分割実装の正しさを機械的に保証する強力な手段であり、
  以後のマイルストーンでも回帰テストとして維持する。

## 既知の制約(M0の意図的な簡略化)

- WASMランタイムはwasmi(純Rust・通訳方式)。M0は正しさの検証が目的で、
  ビルドが軽いことを優先した。C ABIはランタイム非依存であり、
  M1で実機はWAMR、PCはwasmtimeまたはwasmiのまま併用する。
- 有界非同期(外挿つき)は未実装。まずステップ同期の正しさを固めた(A-4の段階案通り)。
- ノード数は2固定、面IDの一意化(知見3)は未実装。M1〜M2で反映する。
