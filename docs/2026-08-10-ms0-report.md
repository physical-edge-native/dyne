# 2026-08-10-M-S0完了レポート(docs\2026-08-10-ms0-report.md)

## 目的と結果

M-S0の目的: dyne-hostを2ノード専用の検証道具から、Nノードのクラスタを
1台のPCで動かすシミュレータ基盤に育てる(検証の3層構造・上層)。

**結果: 合格(2026-08-10)。** 合格基準の「N=16でビット一致」「故障注入
(ノード停止・パケロス10%)からの自己回復」をともに達成。加えて複合カオス
(ロス+停止+分断の同時注入)でもビット一致を維持した。

## 設計(crates/dyne-sim)

- **単一プロセス・離散イベント・仮想時刻**。壁時計を使わず、イベントキュー上で
  仮想ネットワーク(遅延平均+ジッタ・パケットロス・一時分断)とノードの一時停止を
  モデル化する。乱数はシード固定のxorshiftで、**同一シードなら出力がバイト単位で
  再現**する(検証済み)。
- **計算は本物**: 実機M1と同一のheat1d_actor.wasm(無改変)をノード数ぶん
  wasmiで実行。計算のエミュレーションは行わない(WASMの同一性による設計)。
- **実機校正値の注入**: 1ステップの仮想計算時間=79.5ms(M1実測既定、変更可)。
  RAM上限(既定250KB)を超える構成は起動前に拒否(実測: 線形メモリ128KB+管理≒
  138KB必要に対し上限100KB指定で正しく拒否、exit=2)。
- **仕様変更の初実装**: (1) M0知見3「クラスタ全体で一意な界面ID」——界面jを
  ノードjとj+1の間と定義し、メッセージはこのIDを運ぶ。M0でバグを生んだ
  送受の面変換は存在しない。(2) M1知見4「再送バックオフ」——タイムアウト再送に
  最小間隔20ms(仮想)を適用。
- 故障モデルの範囲: ノードの**一時停止**まで。恒久死からの回復は状態引き継ぎ
  (Orchestrator、将来)の領分であり対象外と明記。

## 知見

1. **同期オーバーヘッドの定量化が可能になった**。ロス10%・タイムアウト100ms・
   バックオフ20msの設定で、全体完了時間は理想計算時間の+118%。ロス0%なら+0.0%。
   タイムアウト値とステップ時間(79.5ms)の比がオーバーヘッドを支配しており、
   **B-3(時間同期・タイムアウト設計)を実測で詰める道具**がこれで手に入った。
   実機Wi-Fi(M2)でロス率と遅延分布を採取し、ここに注入して最適化する。
2. **BSPの大域結合の可視化**。1ノードの20秒停止が、隣接だけでなくチェーン全体の
   完了を約24秒遅らせた(同期待ちの波及)。有界非同期(A-4の将来項目)の価値を
   定量化する土台になる。
3. **安定条件チェックはツールチェーンの仕事**。257点でdt据え置きのまま実行して
   解がNaN化する事故を自ら踏んだ(シミュレータに検証を追加して解決)。教訓として、
   数値スキームの安定条件はマニフェスト検証(A-3、.dynepkgの検査)に含めるべき。
   実機にデプロイしてから発散に気づくのでは遅い。
4. 統計の二重計上バグ(再送カウント)を検出・修正。プロトコル動作には無関係。

## 使い方

```
dyne-sim --wasm heat1d_actor.wasm --nodes 16 --points 65 --steps 2000 \
  --loss 0.10 --lat-ms 5 --lat-jitter-ms 3 --step-ms 79.5 --seed 42 \
  --pause 7@20000:40000 --partition 8@60000:90000
```
主なオプション: --nodes/--points/--steps/--dt、--loss(0..1)、
--lat-ms/--lat-jitter-ms、--step-ms(実機校正値)、--ram-cap-kb、--seed、
--pause node@開始ms:終了ms、--partition 分断位置k@開始ms:終了ms。
終了コード: 0=ビット一致合格、1=不一致、2=RAM上限拒否。
