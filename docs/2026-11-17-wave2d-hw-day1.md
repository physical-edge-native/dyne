## 1. 最初の USB 書き込み(16台、ESP32-DevKitC-VE)

- 16:42〜18:00 に16台を書き込み(first_flash.csv)。15台が PASS、1台が dup_id(MAC の最後の1バイトが別の基板と同じ 0xC8 で、
  ノード番号 200 が重なった)。その基板は ctl の node_id(NVS に番号を書く)で 201 にし、18:51 の書き直しで PASS
  (起動ログに `node id 201 source=nvs (nvs=201, mac last byte=200)`)。全台で PSRAM 8 MB・メモリ検査 ok・ワイヤ形式v2 の自己検査 PASS。

## 2. 内部 RAM の不足と、WASM の線形メモリの PSRAM への移動

- 18:25 のアクターの OTA(無線での更新)が node 56・172・201 で `"err":"task"`(ota_actor.csv。処理用のタスクを作れない)。
  原因は、Wi-Fi・MQTT などのサービスを起動した後の内部 RAM の空きが約 3.9 KB しかないこと
  (この値は当日の画面での確認で、記録のファイルには無い。最初の書き込みのログは Wi-Fi 接続前の値まで)。
- 対策: WASM の線形メモリを PSRAM に置く(GitHub issue #82、PR #87、未マージ。速度の低下の基準を測っていないので
  PR は Closes でなく Refs)。修正版(elf 117b394e8)の起動ログ: WASM 読み込み後の内部 RAM の空き 106,727 → 175,871〜176,003 バイト、
  サービス起動後 46,951〜47,303 バイト(約 47 KB、4台)。
- 修正後: アクターの OTA は4台(56・201・172・232)で ok(26,202 バイト、4.05〜4.33 秒)。ファームの OTA は3台(56・172・201)で ok
  (1,357,696 バイト、13.75〜18.71 秒、ota_0 → ota_1)。同じ夜(21:14〜21:51)に残りの12台も修正版を USB で書き直し、16台すべて修正版。
