## 2. 全体構成

### 2.1 3つの役割分担(根拠: 仕様書A-3、project-guide 2章)

- **アクター**: 担当区間の計算だけを行うWASM部品。通信・時刻・同期を知らない。
- **ホスト/ランタイム**: アクターを実行し、通信(境界交換・再送・同期)を注入する
  (dyne-sim / dyne-swarm-sim / node-esp32)。
- **プロトコル**: ホスト間メッセージの形式(ワイヤ形式v2=crates/dyne-wireが単一定義)。

この分業により、同一のwasmバイナリがPC・シミュレータ・実機で無改変のまま動き、
同じ答えを出す(M0/M1/M2で実証)。

### 2.2 共通基盤クレート(根拠: swarm-port-design §2、発注6)

- crates/dyne-wire … ワイヤ形式v2の単一定義(no_std)+アクターABI定数(abi.rs)。
- crates/dyne-core … ホスト側共通部品: rng(決定論乱数+derive_seed)/
  event(離散イベント・仮想時刻)/net(損失・遅延・分断)/actor(wasmi実行
  ラッパ+BC定数)/transparent(透過境界係数の単一定義)。
- v1(M0の40バイト形式)は crates/dyne-proto に歴史的定義として残る
  (v2のIFACE_SCALARがその意味論を包含)。

### 2.3 検証の3層構造(根拠: 仕様書C章 2026-08-10追記)

上=シミュレータ(プロトコル論理・規模・故障・研究テーマ)/中=QEMU(ESP-IDF層。
必須ではない)/下=実機(時間・無線・電力・メモリの真実=**校正値の源泉**)。
計算の正しさはWASMの同一性により全層で共有。時間の忠実度は下層が正。

### 2.4 通信は3層で言い分ける(根拠: roadmap v3 3章原則7)

層1=メッセージ規約(自前で確定=ワイヤ形式v2)/層2=配送の仕組み(MQTT・
zenoh-pico・伝聞が同じ席を争う)/層3=搬送路(Wi-Fi+UDP・Thread)。
**層が違うものは代替関係にならない**。「ミドルウェア」はランタイムレイヤーの
軽量ミドルウェアだけを指し、通信の文脈では使わない。

## 3. アクター仕様

### 3.1 共通ABI(根拠: ms1b-report 1.2、m0-report)

| 関数 | 役割 |
|---|---|
| dyne_init(点数, x0, x1, α, dt, 左bc, 右bc) | 初期化(初期温度 sin(πx)) |
| dyne_set_neighbor(面, 値, 勾配) | 隣の端の値・勾配を受け取る |
| dyne_step() | 時間をdtだけ進める |
| dyne_boundary_value/grad(面) | 自分の端の値・勾配を渡す |
| dyne_get(i) / dyne_set(i, 値) | 格子点の読み書き(観測・状態移送) |

任意エクスポート(あれば使う): dyne_cfg(キー,値) / dyne_set_bc(面,種類) /
dyne_resize(幅) / dyne_eval(i) / dyne_set_bc_value(面,値) /
dyne_transparent_coef(j,decay,half,weight) / **dyne_observe(i, y, γ)→d**
(ナッジング。式はアクター内=シミュレータと実機が同一wasmで式を共有。
nudging-report §1)。
群れアクターの差込口(汎用メッセージバッファ方式)は swarm-port-design §5 が正。

### 3.2 状態の原則(根拠: E3、f1-boundary-design §3)

アクターの可搬状態は**格子点上の標本 u[] のみ**(NNの重みは運ばない)。
唯一の例外は transparent の補助変数(境界1つあたり float×M のノード内状態)で、
移送せず担当替え(handover/ADDの再init)時に**リセット**する(透過境界の
再発動として物理的に解釈可能)。

### 3.3 境界条件(根拠: f1-boundary-design §1〜§3、T9)

境界条件はコードに焼き込まず設定情報とする。コードは dyne-core::actor と同一:

| コード | キー | 差分法の離散化 | 学習型の損失 |
|---|---|---|---|
| 0 | dirichlet(値つき) | u_end=境界値 | u(端)=境界値 |
| 1 | interface | ゴースト点交換 | 差分法式で端点の値目標(iface=1) |
| 2 | zero_grad | 鏡映ゴースト u₋₁=u₁ | u'(端)=0 |
| 3 | linear_extrap | u₋₁=2u₀−u₁(端点凍結=T8。選択時警告) | u''(端)=0 |
| 4 | transparent | **半陰的結合**(下記) | 半陰的式による端点の値目標 |

- 適用の区別(発注11で明確化): `--unobserved-bc`(不在隣接の面。既定 zero_grad)と
  `--outer-bc`(全域外縁。既定 dirichlet:0=後方互換、実験1は zero_grad)。
- transparent: 指数和 M=32(構成パラメータ固定 h_soe=0.6・c1=1e9・c2=2e4・
  T_ref=0.2)、係数は libm で計算し総和順固定=決定論。差分法は半陰的結合
  Δ·(1+2rh·S0) = r·(内側ステンシル) − 2rh·K_hist(陽的結合は r=0.41 で振動発散
  した実測による設計判断)。上限 M≤64(DYNE_SOE_MAX)。
- 学習型の値目標化は半陰的流束条件と等価(3条件つき: (i)履歴更新は実出力端点値、
  (ii)係数同一、(iii)離散流束演算子がステンシルと同一。f1-supplement-report)。

### 3.4 学習型アクターの確定構成(根拠: ms1b-report、order5-report §5)

時刻離散化PINN(入力x→出力u、tanh、後退オイラー型残差)+LM法(1ステップ
5反復)。既定=幅16×1層(49パラメータ)。幅上限 W_MAX=32(コンパイル時定数)。
残差評価点の細分 sub(既定1、**16ノード以上は sub=2 を推奨**)。
実機推奨(S3ノード): 幅16・反復5・sub=1、N≥16でsub=2——ただし孤立劣化は
NN初期値依存の確率的現象のため、N=16運用では複数シード(--pinn seed=)の
事前確認を要する(N7予言検証(i))。
実機制約: フル版のLM行列(約1MB)はESP32に載らない。実機用は縮小版wasm
heat1d_actor_small(N_MAX=2048・スタック8KB・線形メモリ1ページ=64KB。
同一クレートのcargo feature「small」、数値経路は完全同一=フル版とバイト一致
検証済み。order7-report §6.6)。

## 4. データ面(境界同期。根拠: 仕様書A-4+M0/M-S0知見)

- 1メッセージ=1界面×1ステップ、40バイト固定長+CRC32。界面IDは
  **クラスタ全体で一意**(界面j=ノードjとj+1の間。M0知見3)。
- **BSP型ステップ同期**(壁時計を使わない)。評価=BSP(ビット一致)、
  運用=有界非同期+外挿(B-3、12月転換予定)の二本立て。
- プロトコルの原則(M0〜M-S0で確立、根拠: project-guide 6.3):
  過去ステップの重複受信には控え(直近2ステップ)を再送して応答/終了時
  ドレイン/再送の最小間隔(バックオフ20ms)/未登録界面宛は(界面ID,ステップ)
  キーで取り置き(ms1a知見1)/安定条件はデプロイ前に検査。
- ワイヤ形式v2(swarm-port-design §3が正): version=2、kind(0=IFACE_SCALAR/
  1=IFACE_BAND/2=POSITION/3=HEARSAY)、quantity(物理量種別)、src、step、
  t_us(時刻印)、payload。受信箱/送信箱は [u32 len][メッセージ] 連結・固定長・
  あふれは破棄+計数。
- 実機の校正値(M2実測): --step-ms 79.5 / --lat-ms 4 --lat-jitter-ms 5 /
  --loss 0(直結)/ --timeout-ms 100(実測最大待ち99msの直下)。

## 5. 制御面(MQTT第1段。根拠: mqtt-control-plane=規約の正本)

本節は要約であり、詳細は規約文書が正。

- ブローカーはユーザーのPC上。ノードのブートストラップは Wi-Fi・ブローカーURI・
  ノードIDの3つだけで、**それ以外の設定はすべて設定注入**(全ノード同一
  ファームウェア、役割は注入で決まる)。
- トピック: dyne/cfg/<id>(retained)+ack / dyne/ctl/all・<id>(retain禁止)/
  dyne/node/<id>/status(retained+LWT)/観測系 field・sensor・rssi・rt・
  innov / dyne/iface/<id>/residual(界面左側のみ発行)。
- cfg の内容: cluster(n_nodes, points, alpha, dt, steps, seed, step_period_ms)/
  node(idx, n, x0, x1, calib_offset, init)/bc(4キー+interface。transparent
  係数はPCが計算して注入)/ifaces(データ面UDPの結線)/mode(role=
  compute|observe, sensor, 観測周期)/assim(gamma, obs_period, obs_point,
  holdout)。
- 鮮度管理(規約§3.6): cfg=宣言型(retainedが正、世代番号genで斉一性照合)、
  ctl=命令型(retain禁止+受信側もretained ctlを無視。startは古いstopを打ち消す)。
- 異常時(規約§3.5): 相手を失った残存ノードはストール。回収は stop→再設定→
  再start。startは全計算ノードのack(ok)確認後に発行。
- 第2段: B-15判定(zenoh-picoのピアモード)次第で移行。MQTT依存はノード側
  1ファイル(dyne_mqtt.c)に閉じる。

## 6. NNの動的構成(B-16。根拠: b16-design)

- 前提: 群は最初から分割されて生まれる。主役オペレータ=ADD/REMOVE/GROW/
  SHRINK。SPLIT/MERGE/MOVEは必須要件外(道具箱に温存)。
- 機能保存の原則。評価軸=乱れ・回復時間・コスト。
- 界面の情報共有=重複なし+値・勾配の交換(標準)。
- トリガー: Trig1(台本)/Trig2(界面残差。閾値は界面ごとの移動ベースライン比、
  ヒステリシスつき=ms1c実装)/Trig4(資源)/Trig5(増減)。
- 解釈α/β(2026-08-26決定): 評価=α(界面で待つ)、運用=β(境界で閉じて
  進める)。実行時切替可能にする。
- F2ウォームスタート: 参加ノードは最初の界面交換(値+勾配)から初期場を構成
  (両隣あり=3次エルミート、片側=線形延長)→学習型は事前学習(既定200反復)
  →参加。参加ステップの界面残差は厳密に0(f1-f2-report §5)。
- 主張の位置づけ(新規性検証2026-08-22): 「エッジ常駐モデル群の、分散自律・
  実行時・資源適応の再構成」というシステム層(b16-design 8章)。

## 7. データ同化(A-7改訂+発注8・11。根拠: nudging-report §1、experiment1-design)

- 中核は逆問題(データ同化)であり、順問題(場の前進)はその内側の道具
  (roadmap 2.5.1)。イベント検知の2信号=界面残差(Trig2)+イノベーション。
- 最小形=観測点ナッジング: u_i ← u_i + γ(y_i − u_i)(観測周期ごと)。
  差込口は dyne_observe(i, y, γ)→d(γは呼び出しごとにホストが渡す)。
  観測点=担当区間の中央格子点(既定)。イノベーションは適用前の値を記録。
- 保留ノード(holdout): γ=0を適用しイノベーションのみ記録(抜き取り検証)。
- 校正: 全センサを同一地点に30分静置→オフセット算出→cfgのcalib_offsetへ注入。
  ファームはセンサ読取に適用した補正後値を同化・発行の正とし、sensorトピックに
  生値も併載。
- 実験1の合否運用(experiment1-design §1運用細則、2026-09-21/22裁定):
  主基準=保留ローテーション平均でモデル|d|がナイーブ基準(他ノード観測の
  単純平均で予測)を下回ること(内訳併記必須)。副基準=±1.0℃も
  ローテーション平均に適用。同化なし対照run(--holdout all)を床として併置。
- 学習型のナッジングは最小形では改善しない(観測1点が損失内で薄まる。
  nudging-report §4・質問リスト①=理論側回答待ち)。当面は差分法のみで運用。

## 8. 物理単位運転(発注11。根拠: exp1-prep-report、experiment1-design §3)

- L[m](--length。格子幅 h=L/(points−1))、Δt[s]、α[m²/s]、℃スケール
  (正規化層なし)。1ステップ=実時間1秒(step_period_ms=1000、起動時刻からの
  絶対目標時刻追従)。
- 初期場=実測平均の一様値(--init-uniform / cfgのnode.init)。
- 合成真値場(リハーサル用): T(x,t)=tc+(tw−tc)·x/L+amp·sin(2πt/period)·x/L
  +σN(0,1)(--truth-grad。モデル誤差込みの検証=意図)。
- 制約: α=3e-3 m²/s ではΔt≤0.5s(r≤1/2)=実機は step_period_ms≤500。
- 既定値はすべて従来動作(無次元・sin初期値)と後方互換=バイト一致。

## 9. 検証規約(根拠: CLAUDE.md、project-guide 6.1、order5-report §9)

- 合格基準は可能な限り**ビット一致**。動的構成は複合参照解でビット一致に延長。
  学習型は決定論=ビット一致・精度=解析解(または参照解)・動的構成=乱れと
  回復時間の3段構え。
- 決定論: シード固定で全出力がOS間でも一致。乱数は用途別に系列を分離
  (通信・観測ノイズ=--seed系、NN初期化=--pinn seed=)。
- 回帰: 基本16ノード PASS (bit-exact) を最小単位に、12シナリオ一括
  (check-baseline12.ps1)・F1一式(check-f1.ps1)。
- 安定条件(r≤1/2)はデプロイ前検査(学習型のみ警告に降格=発注5)。
- 完了報告には根拠実測ファイルの所在(パス・行数・生成時刻)を必須記載。
  実験出力の削除は要約数値の照合後に限る(2026-09-21運用)。
