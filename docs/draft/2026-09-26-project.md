## 1. 主目標(根拠: roadmap v3 1章。2026-09-01にユーザーが再確認)

**PC側のコントロールプレーンで各マイコンに最初の設定を書き込んだ後、マイコンと
センサを任意の空間に撒けば、マイコン群だけで自律的に環境にフィットする学習・
推論を行い、その空間のデジタルツインを構築するツール。**
センシングは多様性を持たせる: 空間の形状(壁・床・天井・障害物の位置)、熱、音、
流体の流れ、電磁場など。タスク2〜4(ロボット強化学習、部品分散、生物の群れ)は
主目標の応用・検証であり、同じ土台の上で進める。

## 2. 思想3本柱(根拠: 仕様書A-1.0、原文は2026-08-08-pivot.md)

1. **群としてのAI**: 独立した多数のAIモデルが通信しながら協調して推論・学習する。
   中央のブローカーは本質ではなく、P2Pで通信できれば群は成立する。
2. **空間をAI化する**: 既存のワールドモデル学習は視覚依存度が高い。人間の感覚に
   基づかない多様な物理量のセンシングからワールドモデルを構成する。空間に
   分散配置されたマイコン群はそのための「感覚器の群」。
3. **NNを動的に構成する**: 協調推論中・分散学習中に、群への参加・離脱と
   モデルサイズの変更ができるシステムは新規性が高い。前提は「群は最初から
   分割されて生まれる」(2026-08-22決定、b16-design)。

補足(仕様書A-1.0への2026-09-02追記): **数の力**(極小モデル+軽量最適化器を
多数並べる。予想A7)、**粗い補正を置かない**(大分割数での劣化対策は「物理の
伝播に委ねる」か「伝聞(gossip)」の2つに限る。2026-09-01ユーザー決定)。

補足(2026-10-10ユーザー確認、実験3の設計の質疑から): **エッジネイティブ** — 各ノードで
センシングと同時にリアルタイムな推論を行い、PCの計算資源に頼らず、設定注入・監視・可視化
(と形状データ等のエクスポート)以外はマイコン群だけでデジタルツインを構成する。ここに
本プロジェクトの意味がある。生データをPCに集めて統合する従来型のセンシングは、品質の
基準として比べることはあっても方式の代替にはしない。なお、この構成がクラウドネイティブ
(あるいは中央集権的)な構成に対して優位を示す具体的な場面は、現時点では想定できていない。
エッジコンピューティングが物理環境に入り混じり、物理AIが物理環境ともっと透過的に関わる
時代を見据えた技術と位置づける。

## 3. 2つの目標と主軸(根拠: 仕様書A-1・B-13)

- 目標1: マイコンだけで(全ノードがマイコンで)どこまでできるか、の限界を知る。
- 目標2: 組込みLinuxを許容すれば何ができるか、の到達点を知る。
- **実装の主軸は目標1(マイコン主軸)**(B-13、2026-08-05決定)。成立しない機能が
  実機で判明した時点で目標2へ移す。各マイルストーンで「限界レポート」
  (RAM・フラッシュ・速度・成立/不成立の判定と理由)を記録し、その蓄積が
  目標1の成果物になる。失敗も一級の成果物。
- 開発方針: 予算制約によりシミュレータ優先。実機は「成立判定」と「校正値の
  採取」に役割を寄せる(検証の3層構造=仕様書C章)。

## 5. 用語集(たたき台。根拠: roadmap v3 11章と project-guide 9章から集約)

- **ノード**: マイコンボード1台(+センサ)を単位とする群の構成員。
- **アクター**: ノード上で走る計算主体。WASMで実装され、通信・時刻・同期を
  知らない。差分法アクター(heat1d-actor)、学習型アクター(heat1d-pinn-actor、
  時刻離散化PINN+LM法)、群れアクター(swarm-agent-actor)の3型。
- **ホスト**: アクターを読み込んで実行し、通信・同期を注入する側
  (dyne-sim、dyne-swarm-sim、node-esp32のmain.c)。
  **メールボックス方式**(2026-10-10命名。旧称「受信箱/送信箱方式」): ホストがメッセージの
  バイト列を中身を見ずにアクターの受信メールボックスへ書き、アクターが送信メールボックスに
  書いたものを取り出して運ぶ受け渡し方(群れアクターで実装済み、2次元の場のアクターも採用)。
  名前はアクターモデルの一般用語「メールボックス」に合わせた。
  **格子型アクター / 学習型アクター**(形状の場合。2026-10-10命名): 符号つき距離関数を格子点の
  値として持つ型 / 座標を入れると距離を返すNNとして持つ型(熱の学習型アクターと同じ型)。
- **界面**: 隣接ノードの担当領域の境目(ノードとノードの境目)。1次元では値+勾配(40バイト)を
  交換する。**境界**(2026-10-10ユーザー決定で区別を明確化): 観測者となるノードがいる領域と、
  いない領域(未観測領域)との境目。境界条件キー(F1)はこの「境界」の扱いを指す。
  **界面サンプル列**(2026-10-10命名。旧称「帯ペイロード」): 2次元以降の界面上の取り決めた点
  での値の並び。1点あたりの量の数はアクターの型ごとに取り決める(order10-design D4)。
  一般化: 「独立に推論・学習する主体どうしが、定められたフォーマットで境界量を
  交換する面」(仕様書A-1.0)。**界面残差** = 界面両側の勾配の食い違い
  |grad_A − grad_B|(Trig2の入力)。
- **BSP**: 全ノードが論理ステップで足並みを揃える同期方式(ビット一致検証の
  土台)。**有界非同期**: 遅れた界面値を外挿して待たずに進む運用方式(B-3、
  12月転換予定)。評価=BSP/運用=有界非同期の二本立て。
- **ビット一致**: 分割解と単一ノード解(または改修前後)の全桁一致。回帰の
  合格基準(PASS (bit-exact))。**複合参照解**: 参加イベントの時系列込みで
  1本の配列上で逐次計算した参照解(M-S1a)。
- **ADD/REMOVE/GROW/SHRINK**: 動的構成の主役オペレータ(B-16)。
  **handover**: 離脱時に状態(格子点標本)を取り出し復帰時に書き戻す機構。
  **ウォームスタート(F2)**: 参加前に両隣の値+勾配から初期場を構成し短い
  事前学習をしてから参加する方式。
- **解釈α/β**: 不在の隣の扱い。α=「まだ来ていない参加者」(界面で待つ)、
  β=「まだ存在しない領域」(境界条件で閉じて計算を止めない)。
  評価はα、運用はβ(2026-08-26決定)。
- **未観測領域**: ノードが存在せず値が得られない領域。境界条件キー
  (dirichlet / zero_grad / linear_extrap / transparent)で閉じる(F1)。
- **transparent(半無限透過境界)**: 「境界の先に同じ材質が無限に続く」想定の
  厳密境界(T10)。**浸透深さ** √(αt) が未観測区間長を超えると仮定が破れる(N10)。
- **データ同化**: センサ実測値を推論・学習に取り込むこと。**ナッジング** =
  u←u+γ(y−u) の最小手法。**イノベーション** = 観測値とモデル予測の食い違い
  d=y−u(適用前)。**保留ノード(ホールドアウト)** = 観測を同化に使わず
  イノベーションのみ記録する抜き取り検証(発注11)。**ナイーブ基準** =
  保留ノードの温度を他ノード観測値の単純平均で予測したときの誤差
  (実験1の旧主基準の比較相手。2026-10-08に合格基準は「ファームが全runを完走すること」へ
  改訂され、この比較は記録・考察用の指標になった)。
- **コントロールプレーン(制御面)**: PC上の管理側(設定注入と接続時のみの観測。
  第1段=MQTT)。**データ面**: 境界同期(自前40バイト+UDP直送。MQTTを通らない)。
  **ゲートウェイ役**: PCとの橋渡しを担う任意のノード(中央権限なし)。
- **ワイヤ形式v2**: メッセージ規約の現行版(種別: 界面スカラー/界面サンプル列(旧称「帯」)/位置/伝聞。
  crates/dyne-wireが単一定義)。**伝聞(gossip)**: 隣から隣へ多段に運ぶ情報共有。
- **定義域分割/テンソル分割**: 座標入力の関数の担当範囲を切る(本プロジェクト
  標準)/入力配列そのものを切る(CNN向き)。
- **乱れ/回復時間**: 構成変更直後の誤差(界面残差)の跳ね/元の水準に戻るまでの
  ステップ数(B-16の評価軸。本プロジェクトが定義した指標)。
- **RSSI(受信信号強度)/FTM(Wi-Fi測距)/I2C**: hardware.md 冒頭の定義どおり。
- **PINN(物理情報ニューラルネットワーク)**: 物理方程式を満たすよう学習するNN。
  **時刻離散化PINN(Rothe法)**: 時間を先にΔt刻みにし、各時刻の空間分布だけを
  NNで表す方式(T4)。**LM法(レーベンバーグ・マーカート法)**: 小規模NN向きの
  二次の最適化手法。
