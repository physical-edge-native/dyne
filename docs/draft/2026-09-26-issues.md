## C. 内容の食い違い(要確認・要追記)

1. **N3が予想のまま残っている**: 理論ノート(numeric-operation)のN3
   「残差評価点の中点追加で16ノード劣化は1桁以上回復」は、M-S1b 1(b)
   (2026-08-26)で sub=2により 2.1e-2→3.1e-5 と実証済み(STATUS.md・
   ms1b-reportに記録)。N9/N10/N11/N7には解消マークがあるのにN3だけ未更新。
   あわせて sub=4 の悪化(7.4e-2、原因未解明)が予想として番号化されていない。
2. **N2の記述の温度差**: math-briefing §3 は「乱れは参加界面の近傍に留まり、
   遠方の既存界面はほぼ平坦(局所性)」を実験事実として記すが、理論ノートのN2は
   「検証: 計画済み」の未解決予想のまま。系統計測(距離別スパイク)は未実施
   なので N2 を維持するなら briefing 側の表現が強すぎる。
3. **境界条件の優劣の見かけ上の逆転**: 発注8(nudging-report §2)は「同化あり
   では zero_grad が transparent より優位」(σ=0・解析場・観測領域Linf、γ=1で
   3.1e-2 vs 1.4e-1)。発注11後の部分観測比較リハーサル(po-analysis /
   n7-verify-exp1-po-report §B2)では transparent がわずかに良い(保留評価の比
   0.43 vs 0.47、合成勾配場)。設定(場・評価指標・観測構成)が違うため矛盾では
   ないが、並べて読むと食い違って見える。書き直しの理論ノートかレポートに
   「どの設定でどちらが優位か」の対応表を置く価値がある。
4. **S3推奨設定に条件が付いたのに order5-report §5 は未更新**: N7予言検証(i)
   (2026-09-22)で「N=16でsub=2の構成はNN初期値依存の劣化がありうるため複数
   シードでの事前確認を要する」が確定し理論ノートには追記済みだが、
   order5-report §5(S3推奨)にはこの条件が書かれていない。
5. **仕様書A-5内の新旧併存**: 2026-08-10改訂の「同期的なコマンド→各マイコンの
   軽量APIサーバー(存続)」と、2026-09-02改訂の「軽量APIサーバーは設けない
   方針に変更」が同一節内に併存(改訂追記の構造上の問題。API仕様の追記
   GET /metrics 等も撤回済み扱いか不明瞭)。
6. **learning-actor既知値の表記**: 「s12系 dirichlet:0 = 6.449e-3」という言い方が
   複数文書に出るが、s12を既定(zero_grad)で実行した値(4.612e-3系)とは別で
   あることの説明がどこにもない(check-baseline12 が dirichlet:0 固定で走る
   ことが根拠)。書き直しの検証規約に一行説明を置くとよい。
7. **exp1のセンサ構成の連鎖更新漏れの可能性**: experiment1-design §2の
   機材リスト(秋月調達分)はDHT20×3だが、§2表(1a)は「DHT20×2+BME280×2」
   から「4台ともDHT20」へ2段階で改訂された。runbook・design間は2026-09-22
   改訂で揃えたが、hardware.md(A-3)とroadmap v3(A-4)が残っている。
8. **形の格子型アクターの縮小版の記述(2026-11-13 追記)**: docs/2026-11-11-esp32-interp-bench.md は
   縮小版のスタックを 6KB とし、「スタックがあふれると静的領域が壊れて CRC がずれる」と書くが、
   (a) スタックは 2026-11-13 に 4KB にした(docs/2026-11-11-shape-speedup.md §7)、(b) Rust の wasm では
   スタックが線形メモリの先頭にあり、あふれると範囲外の書き込みで止まる(静的領域は壊れない)。
   また同文書 §1 の計測の読み方から「1ステップに距離の反復が約9回」と受け取られたが、反復は1ステップ1回で、
   重いのは光線の処理だった(shape-speedup §0)。
9. **CITATION.cff の license の書き方(2026-11-15 追記)**: CLAUDE.md の「リリースと Changelog」は
   「license は MIT と Apache-2.0 をリストで書く(`MIT OR Apache-2.0` の1行では Zenodo が読めない)」とするが、
   現在の CITATION.cff(2026-11-15 のコミット 0c9cbcd)は `license: "Apache-2.0"` の1値と、二重ライセンスである旨の
   コメントにしている。理由: リストで書くと、手元の検証(cffconvert)は通るが、Zenodo の GitHub 連携の取り込みが
   「Citation metadata load failed」で失敗するという報告がある(cff-initializer-javascript issue #872、2025-07)。
   Zenodo の説明の例も1値のみ。次のリリースの前に、リストにするか1値のままにするかをユーザーが決める。
   リストにする場合は、リリース後に Zenodo の記録の下書きでライセンスが読めているかを確かめる。
10. **STATUS.md の未決事項が古い(2026-11-15 追記)**: STATUS.md の「今ここ(2026-11-15)」は「未決: ライセンス」と
    書くが、同日に MIT OR Apache-2.0 に決まり、リポジトリは公開、Concept DOI は 10.5281/zenodo.24241009(CLAUDE.md)。
    → 同日 STATUS.md を更新済み。

## E. 用語の揺れ(軽微)

1. 「観測点ナッジング」「ナッジング」「データ同化最小形」が同義で混在
   (定義はどれも u←u+γ(y−u))。
2. 「保留ノード」「ホールドアウト」「抜き取り検証」が同義で混在(発注11以降)。
3. 「制御面」と「コントロールプレーン」、「データ面」と「シミュレーション
   プレーン(旧称)」が混在(旧称はM0〜A-5時代の文書に残る)。
4. 「学習型アクター」「NNアクター」「PINN型アクター」「S3ノード」が文脈により
   同じものを指す。
5. 単位の切り替え: シミュレータの基準問題は無次元(α=1、Δt=1e-4)、実験1は
   物理単位(α=1e-3 m²/s、Δt=1s)。同じ記号 r=αΔt/h² が別のスケールで出て
   くるため、書き直し仕様書では「無次元の基準問題」と「物理単位運転」を
   節として分けた(draft/2026-09-26-spec.md 8章)。
