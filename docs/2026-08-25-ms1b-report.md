## 0. この実験は何をしたのか(1分で分かる要約)

Dyneプロジェクトでは、細長い棒の温度が時間とともに変わっていく様子(1次元の熱伝導)を、
棒を何区間かに切って、区間ごとに別々の小さなコンピュータ(実機ではマイコン、今回は
シミュレータ上の仮想ノード)に計算させている。隣り合う区間は、境目(界面)の温度を
毎ステップ交換して協調する。

これまで各区間の計算には**差分法**(温度を格子点の数列として持ち、決まった算術式で
次の時刻の値を出す古典的な数値計算法)を使ってきた。今回(M-S1b)は、各区間の計算を
**小さなニューラルネットワーク**(以下 NN。入力から出力を計算する、学習可能な数式の
組み合わせ)に置き換えた。狙いは、B-16設計書で決めた「NNを実行中に組み替える」
(参加=ADD、大きくする=GROW、小さくする=SHRINK)をNNで実際に試すこと。

結果:
- NN版の区間計算部品(以下**学習型アクター**)を作り、差分法版と**そのまま差し替え可能**にした
  (通信の形式もシミュレータの中核も変えていない)。
- 1〜8ノードでは、NN版の答えの正しさ(厳密解との差)が差分法版と同程度だった。
- 16ノード(1ノードあたり格子点がわずか4〜5個)ではNN版の正しさが100倍以上悪化した。
  「区間を細かく切りすぎると学習が難しくなる」という、先行研究が警告していた現象を
  自分たちの数値で確認した。
- GROW(NNを大きくする)は、答えを1ビットも変えずに実行できた。SHRINK(小さくする)は
  答えが少し変わるが、小さな乱れで済み、時間とともに回復した。
- 途中で2つの大きな失敗を踏み、それぞれ原因を突き止めて設計を変えた(4章)。
  失敗の記録はこのプロジェクトでは一級の成果物として残す。

## 1. 背景: なぜNNで、なぜこの形か

### 1.1 プロジェクトの流れの中での位置づけ

- M-S0(2026-08-10): 差分法アクターを16ノードで動かすシミュレータが完成。通信の欠落や
  遅延を注入しても、答えが1台で計算した場合と**ビット一致**(2進数の全桁が完全に同じ)。
- M-S1a(2026-08-24): ノードの離脱・復帰(handover)と新規参加(ADD)の**仕組み**を
  差分法アクターで成立させた。
- **M-S1b(本レポート)**: アクターの中身をNNに置き換え、ADD/GROW/SHRINK を試す。
- M-S1c(次): NNの群が、界面の食い違いを自分で監視して自動的にGROWする実験。

### 1.2 「アクター」とは

このプロジェクトで**アクター**とは、「自分の担当区間の計算だけを行う独立した計算部品」
のこと。通信・時刻・同期は一切知らず、ホスト(アクターを動かす側のプログラム。今回は
シミュレータ)が次の関数を呼ぶことでやり取りする:

| 関数 | 役割 |
|---|---|
| dyne_init(点数, 区間の左端x0, 右端x1, 熱の伝わりやすさα, 時間刻みdt, 左端の境界の種類, 右端の境界の種類) | 初期化。初期温度は sin(πx) |
| dyne_set_neighbor(面, 値, 勾配) | 隣の区間の端の温度と傾きを受け取る |
| dyne_step() | 時間を dt だけ進める |
| dyne_boundary_value(面) / dyne_boundary_grad(面) | 自分の端の温度と傾きを渡す(隣へ送るため) |
| dyne_get(i) / dyne_set(i, 値) | 格子点 i の温度を読む / 書く(状態の観測と移送) |

アクターは **WASM**(WebAssembly。どのCPU・OSでも同じように動く中間形式のプログラム)
として作られ、PC・シミュレータ・マイコン(ESP32)で同じファイルを動かす。

### 1.3 「学習型アクター」とは

**学習型アクター**とは、上の関数群をそのまま備えつつ、中身の計算を差分法ではなく
NNの**学習**(NN内部の数値=重みを、目的の式を満たすように少しずつ調整すること)で
行うアクターのこと。本レポートでは差分法版を**差分法アクター**、NN版を**学習型アクター**と
呼び分ける。

### 1.4 PINN と 領域分解PINN

- **PINN**(物理情報ニューラルネットワーク): NNに「物理の方程式を満たせ」という条件を
  学習の目標として与える方式。普通のNNは「入力と正解の組」から学ぶが、PINNは
  「方程式の残差(方程式の左辺−右辺。満たしていれば0)をゼロに近づける」ことを学ぶ。
- **領域分解PINN**(DD-PINN): 空間を区間に分け、区間ごとに別のPINNを持たせ、区間の境目で
  値を合わせる条件(界面条件)で繋ぐ方式。B-16設計書で「最初のNN実装」として採用済み。
  理由は、境目で交換する情報(値と勾配)が既存の通信形式のままで済むこと。

### 1.5 今回の物理の題材

棒の温度 u(x, t) は**熱伝導方程式** ∂u/∂t = α ∂²u/∂x² に従う(時間変化率 = 熱の
伝わりやすさ α × 空間の曲がり具合)。両端は温度0に固定、初期温度は sin(πx)。
この設定では厳密な答え(**解析解**)が u(x,t) = exp(−απ²t)·sin(πx) と分かっている。
つまり「正解」が式で手に入るので、計算結果の良し悪しを正確に測れる。

## 2. 設計の決定(2026-08-25、ユーザー決定の3点)

### 2.1 決定1: 「1ステップ」の意味 = 時刻離散化PINN

問題: PINNは本来「空間と時間の両方を入力にした関数 u(x,t) を学習し終えてから使う」もので、
「1ステップごとに時間を dt 進め、境目の値を交換する」というシミュレータの同期方式
(**BSP**: 全員が1段階ずつ足並みを揃えて進む方式)と噛み合わない。

決定: **時刻離散化PINN**(Rothe法とも呼ばれる考え方)にする。
- NNは「いまの時刻の温度分布 u(x)」だけを表す(入力は位置 x のみ)。
- 1ステップ = 「前ステップの温度分布 u_prev を覚えておき、次の式(**後退オイラー型の残差**)
  が0に近づくようにNNを少し学習させる」:

  r(x) = [u(x) − u_prev(x)] − α · dt · u''(x)

  意味: 「温度の変化量 = α × 時間刻み × 空間の曲がり具合」という熱伝導方程式を、
  時間方向だけ dt 刻みで離散化した式。u'' は u の x に関する2階微分(曲がり具合)。
- あわせて境目の条件(両端の温度0、または隣から届いた値)も学習の目標に入れる。

利点: シミュレータの同期方式、通信形式(40バイトの固定長メッセージ)、dyne_step の意味を
まったく変えずに済み、差分法アクターと混在もできる。

### 2.2 決定2: 学習コードの置き場 = 共有Rustクレート+WASM化

決定: 学習のコード(NNの計算、微分、最適化)を、Rust言語の1つのクレート(Rustの
ソースコードのまとまり。`crates/heat1d-pinn-actor`)として書き、
(a) WASMにコンパイルしてアクターとして使い、(b) 同じソースをPC上でそのままテストする。

制約として、マイコンに載せる将来を見据え、標準ライブラリなし(no_std)、動的なメモリ
確保なし(全部固定長の配列)、外部の数値計算ライブラリなし(純Rustの数学関数ライブラリ
`libm` のみ)とした。微分の計算(NNの学習に必要)も自分で書いた。これにより、
どの環境で動かしても計算順序が同じ=結果が**ビット一致で再現できる**ことを自分で保証できる。

### 2.3 決定3: 合格基準

NNは差分法と「別の計算法」なので、これまでの合格基準「分割した答えが1台の答えと
ビット一致」は使えない(同じ計算法同士でしか一致しない)。そこで3段構えにした:

| 基準 | 内容 | 意味 |
|---|---|---|
| (i) 決定論はビット一致 | 同じ入力・同じ乱数の種なら、何度実行しても全出力が1ビットも違わない | 実験の再現性。通信の欠落や遅延を注入しても成立すること |
| (ii) 精度は解析解基準 | 計算結果と厳密解 exp(−απ²t)·sin(πx) との差を測り、差分法アクターの差と並べる | 「答えがどれだけ正しいか」 |
| (iii) 動的構成は乱れ・回復時間 | ADD/GROW/SHRINK を行った瞬間に誤差がどれだけ跳ね(乱れ)、何ステップで元の水準に戻るか(回復時間) | B-16設計書の評価軸そのもの |

**「誤差」という言葉の使い分け(重要)**: 本レポートで「誤差」「最大誤差」と書くときは、
特に断らない限り**(ii) の意味、つまり計算結果と正解(解析解や参照解)との差**を指す。
NNの学習で最小化する量(**損失**、loss)とは別物である。損失は「方程式をどれだけ満たして
いないか」の自己採点で、正解との差そのものではない(損失が小さくても正解から離れて
いることはあり得る。4章の失敗2がまさにその例)。

- **Linf(最大誤差)**: 全格子点の中で最も大きい |計算値 − 正解|。
- **L2(二乗平均平方根誤差)**: 全格子点の差の二乗を平均して平方根をとったもの。全体的な
  ずれの大きさ。

## 3. 実装したもの

### 3.1 学習型アクター(crates/heat1d-pinn-actor/src/lib.rs、約900行)

**NNの形**: 多層パーセプトロン(MLP: 入力→隠れ層→出力と、数値を掛けて足して
非線形関数を通す、を繰り返す最も基本的なNN)。
- 入力: 位置 x を [−1, 1] に正規化したもの(1個の数)。
- 隠れ層: 活性化関数 tanh(双曲線正接。滑らかなS字の関数。先行研究で「PINNには tanh が
  必須、ReLUは物理損失と相性が悪い」と示されている)。幅(1層のニューロン数)と層数は
  実行時に設定可能。上限は幅32×3層(固定長配列で確保)。
- 出力: 温度 u(1個の数)。
- **既定は幅16×1層、パラメータ(学習で調整する数値。重みと偏り)49個**。

**微分の計算**: 損失には u''(2階微分)が入るので、NNの出力を入力 x で2回微分した値が
要る。さらに学習には「損失をパラメータで微分した値」(勾配)が要る。入力が1個の数なので、
u, u', u'' は「ジェット」(値・1階微分・2階微分の3つ組)を層ごとに前向きに伝播させれば
1回の計算で得られる。パラメータ勾配は、そのジェット計算を手書きで逆向きに辿って求めた
(自動微分ライブラリは使っていない)。正しさは数値微分(微小に動かして差を取る)との
照合テストで確認した。

**最適化器**(損失を減らすようにパラメータを更新する手順)= **LM法**(レーベンバーグ・
マルカート法)を既定にした。これは「残差の二乗和を最小化する」問題(非線形最小二乗)の
標準手法で、残差のパラメータに対する変化率をまとめた行列(ヤコビ行列 J)から、
方程式 (JᵀJ + λ·diag(JᵀJ)) δ = −Jᵀr を解いてパラメータの修正量 δ を求める。
λ は減衰係数で、うまくいけば減らし、失敗すれば増やす。数反復で高精度に収束する。
パラメータ数の上限は256(行列を固定長で確保するため)。上限を超える構成では
Adam(勾配の大きさを正規化する一般的な最適化器)か慣性つき勾配降下法に自動で落ちる
(なぜLM法にしたかは4章の失敗1)。

**状態の持ち方と移送**: アクターの「状態」として外から読める(dyne_get)・書ける(dyne_set)
のは、**格子点上の温度の標本 u[]** だけ。NNの重みは外に出さない。これは M-S1a で得た
原則「移送するのは物理状態のみ」の延長で、B-16設計書付録の「場の標本を共通通貨とする
知識の持ち運び」の実装になっている。dyne_init 直後の重みは乱数で、最初の dyne_step の
冒頭に「標本 u[] に出力を合わせる」学習(**温め**、warm-up)を予約する(既定50反復)。

**界面条件**(隣との境目で何を学習の目標にするか。既定 iface=1):
自分の端点の「次の時刻の温度」を、差分法アクターとまったく同じ式
u_end_new = u_end + r·(隣の端の温度 − 2·u_end + 自分の1つ内側の温度)(r = α·dt/h²、
h は格子間隔)で先に計算し、NNの出力 u(x_end) がそれに一致することを目標にする。
使う情報は差分法と同一(隣の**前ステップ**の端の温度だけ)。初版の方式(iface=0)は
4章の失敗2で説明する。

**追加の関数**(差分法アクターにはない。ホストは「あれば使う」):
| 関数 | 役割 |
|---|---|
| dyne_cfg(キー, 値) | 学習の設定(反復回数、幅、層数、温め回数、界面条件の方式など)。dyne_init の前に呼ぶ |
| dyne_set_bc(面, 種類) | 境界の種類(温度0固定 / 隣との界面)を、重みを保ったまま切り替える |
| dyne_resize(幅) | 隠れ層の幅を変える = GROW / SHRINK |
| dyne_eval(i) | 時間を進めずに、いまのNNを格子点 i で評価する(機能保存の検査用) |

**GROW / SHRINK の実装**:
- GROW(幅を増やす): 新しいニューロンを足すとき、「新ニューロンから出力への重み」と
  「既存ニューロンが新ニューロンから受ける重み」を 0 にする。すると新ニューロンは出力に
  何も寄与しないので、**NNが表す関数(x を入れたときの出力 u)は変更前後で1ビットも
  変わらない**。新ニューロン自身が受ける重みだけ小さな乱数にし、以後の学習で役割を持てる
  ようにする。
- SHRINK(幅を減らす): 末尾のニューロンを落とす。落としたニューロンは出力に寄与して
  いたので、関数は変わる。埋め合わせとして「変更直前の出力(標本 u[])に合わせる温め」を
  次ステップ冒頭に予約する(既定50反復、0で無効)。

### 3.2 シミュレータの拡張(crates/dyne-sim/src/main.rs)

シミュレータ(dyne-sim)は、N個のノードとその間の通信を1つのプロセス内で仮想時刻で
再現するプログラム。今回の追加:

| 追加 | 内容 |
|---|---|
| 任意の関数のバインド | 3.1の追加関数がWASMに存在すれば使い、無ければ従来動作。差分法アクターの動作は不変 |
| `--pinn key=val,...` | 学習の設定を全インスタンスに適用(例: `--pinn width=8,iters=3`) |
| `--add-warm N` | ADDで参加するインスタンスだけ温め回数を上書き(白紙=0 との比較用) |
| `--resize node@t_ms:width` | 仮想時刻 t にそのノードの幅を変更(GROW/SHRINK)。変更前後で dyne_eval を全格子点で比較し、何点がビット一致したかを記録 |
| `--error-csv path` | ノードごと・ステップごとの誤差を書き出す。参照は ADDなし=解析解、ADDあり=複合参照解(後述) |
| 境界切替の在り方 | 隣にADDが起きたノードは、dyne_set_bc があれば**重みを保ったまま**境界の種類だけ切り替える(差分法アクターは従来どおり再初期化+状態復元) |
| 報告の形式 | 学習型では「bit-exact: n/a(該当なし)」とし、参照解との最大誤差とノード別誤差を出す。終了行は `RESULT: DONE (learning actor, ...)` |

**参照解**(比較の相手)は2種類:
- **single**: 同じアクターを、分割せず全域1ノードで動かした答え。差分法ならこれと
  ビット一致するはず。学習型では「別のNNが別の区間を学習した結果」なので一致は
  期待できず、差の大きさを見る。
- **composite(複合参照解)**: ADDのように途中で領域が広がる場合、1ノードの答えが
  定義できないので、「同じ参加イベントの時系列を、1本の配列上で差分法で逐次計算した答え」を
  参照にする(M-S1a で導入)。学習型に対しては「差分法ならこうなる」という比較相手。

### 3.3 テストと実行方法

ネイティブ(PC上、WASMにせず)の単体テスト4本:
ジェット vs 数値微分 / 損失の勾配 vs 数値微分 / GROW のビット保存 / 単一区間で解析解に追従。
`cargo test --release -- --ignored --nocapture` で最適化器の収束の診断も出せる。

```
cd crates\heat1d-pinn-actor
cargo test --release
cargo build --release --target wasm32-unknown-unknown
cd ..\dyne-sim && cargo build --release
# ワークスペース直下で
target\release\dyne-sim.exe --wasm crates\heat1d-pinn-actor\target\wasm32-unknown-unknown\release\heat1d_pinn_actor.wasm --nodes 4 --points 65 --steps 1000 --ram-cap-kb 4096
```

`--ram-cap-kb 4096` が必要な理由: シミュレータは「アクターが使うメモリがマイコン
(ESP32)の実効上限 250KB に収まるか」を検査して超えたら拒否する。学習型アクターは
LM法の行列(256×256×8バイト×2=1MB)を固定長で確保しているため、この検査に通らない。
つまり**現在の学習型アクターはそのままではESP32に載らない**(6章)。

## 4. 途中で踏んだ失敗と、そこから変えた設計(限界レポート)

### 失敗1: Adam でも素朴な勾配降下法でも、時間に追従できなかった

最初は先行研究の定番どおり Adam(学習率1e-3)で学習させた。温め(標本への当てはめ)は
できるが、その後ステップを進めると誤差が 2e-2〜2e-1 で頭打ちになり、改善しなかった。

原因: Adam は勾配を正規化して「勾配の大きさに関係なく、毎回ほぼ学習率ぶん動く」性質が
ある。時刻離散化PINNでは1ステップで温度分布が動くべき量がごく小さい(相対で約1e-3)ため、
Adam の「毎回動く量」がそれより大きく、正しい変化が雑音に埋もれた。
そこで「勾配に比例して動く」素朴な勾配降下法(SGD)を試したが、こちらは方程式残差の
u'' の項が**硬い**(パラメータをわずかに変えると損失が急激に変わる=曲率が大きい)ため、
学習率を上げると発散(値が無限大やNaNになる)、下げると全く動かなかった。

対処: パラメータ数が49個と小さいことを活かし、二次の情報を使う **LM法** に切り替えた。
温めは20〜30反復で損失1e-9以下、時間追従は5反復/ステップで十分になった。
副作用として、LM法の行列を確保する分メモリが増えた(3.3、6章)。

### 失敗2: 界面条件の初版は、多ノードで誤差が時間とともに蓄積した

初版の界面条件(iface=0)は「自分の区間の端から格子1つ外側の点(ゴースト点。隣の端の
位置)で、NNの出力が**隣の前ステップの温度**に一致すること」だった。これは差分法アクターが
使うゴースト点の考え方をそのまま移したもの。

結果: 4ノードで1000ステップ後の最大誤差が 1.9e-2 と、1ノード(2.5e-4)より2桁悪く、
誤差CSVで見ると時間に比例して単調に増えていた。隣との傾きの一致も目標に加える
(lambda_g)とさらに悪化した(0.1で4.9e-2、1で3.2e-2)。

原因: この条件は「**次の時刻**の自分の関数」に「**前の時刻**の隣の値」を押し付けている。
時間が1ステップずれた拘束なので、界面付近の温度の減衰が毎ステップわずかに遅れ、
それが蓄積した。差分法では同じ「前の時刻の隣の値」でも、更新式の中で自分の前の時刻の
値と組み合わせて使うので、時間のずれが生じない。

対処(iface=1、現在の既定): 差分法と同じ更新式で「自分の端点の次の時刻の値」を先に
計算し、それをNNの目標にする。**使う情報(隣の前ステップの端の温度)は同じで、
使い方(時間の整合)だけを変えた**ところ、4ノードの誤差が 1.9e-2 → 5.4e-5 と
350倍改善し、差分法と同等になった。

教訓: 「界面で何を交換するか(値+勾配という**フォーマット**)」より、「交換した値を
どの時刻の条件として使うか(**時間整合性**)」の方が精度を左右した。B-16設計書2章で
標準化した交換フォーマット(値+勾配、40バイト)は変更不要で、勾配の欄は学習型でも
界面残差センサー(後述)専用のままでよい。

### 失敗3: 想定していたNNの大きさ(2〜3層×16〜32)は、LM法と両立しなかった

STATUS.md には先行研究から「幅16〜32×2〜3層」と書いていたが、幅16×2層のパラメータ数は
16 + 16×16 + 16 + 各層の偏り = **321個**で、LM法の行列上限256を超える(当初 65個と
数え間違えていた)。幅を落として2層にした構成(幅8×2層=97個)は誤差 2e-2 と悪く、
幅16×1層(49個)が誤差 3.7e-4 で最良だったため、これを既定にした。
1次元の熱伝導は滑らかで簡単な問題なので、1層で足りる。

### 失敗4(性能上の制約): 通訳実行のWASMは遅い

シミュレータ内のWASM実行エンジン(wasmi。命令を1つずつ解釈する通訳方式)では、
65点1ノードで約40ミリ秒/ステップ。16ノード×2000ステップ+参照解で数分かかる。
実験は複数を並列に走らせて対処した。

## 5. 検証結果

共通条件: 格子点65、乱数の種42、1ステップの計算時間79.5ms(実機M1の校正値)。
参照解の記号: **analytic**=解析解(厳密な正解)、**single**=同一アクターの全域1ノード解、
**composite**=差分法の複合参照解。「誤差」はすべて 2.3 の意味(正解との差)。

### 5.1 ノード数を増やしたときの精度(2000ステップ、界面条件 iface=1)

| ノード数 | 1ノードの格子点数 | 最大誤差 vs analytic | 最大誤差 vs single | 補足 |
|---|---|---|---|---|
| 差分法・16 | 4〜5 | 8.0e-5 | 0(ビット一致) | 従来の回帰試験、変更なし |
| 1 | 65 | 2.5e-4 | 0 | 2つのインスタンスの出力が全桁一致(決定論) |
| 2 | 32〜33 | 3.3e-4 | 5.0e-4 | |
| 4 | 16〜17 | 6.1e-5 | 1.9e-4 | 小さい区間の方が当てはめが易しい |
| 8 | 8〜9 | 8.4e-5 | 1.7e-4 | |
| **16** | **4〜5** | **2.1e-2** | **2.1e-2** | **精度が100倍以上悪化**。中央付近のノードほど悪い(3.7e-3〜2.1e-2) |

読み方: 1〜8ノードでは学習型は差分法(8.0e-5)と同じ桁の正しさ。16ノードになると、
1ノードが持つ格子点(=方程式残差を評価する点)が4〜5個しかなく、49個のパラメータを
持つNNを決めるには情報が足りず、精度が崩れる。

**先行研究との対応**: 古典的な領域分解法(1つの大きな問題を区間に分けて解く数値計算の
理論)では、「区間の数Nを増やすと、全域を見渡す**粗い補正**(全体を粗く近似した解で
区間ごとの解を修正する仕組み)がない限り、収束がNとともに悪くなる」ことが知られている。
AB-PINNs のリサーチ記録(docs/2026-08-22-research-ab-pinns.md 2.5節)は、私たちの構成には
全域を見るNNが存在せず界面交換だけで情報を運ぶため、同じ劣化が起きる可能性が高いと
警告していた。今回の16ノードの結果は、その現象を**中央のサーバを持たない分散構成で、
自分たちの数値として**初めて確認したもの(「分散版」とはこの意味)。

参考(旧界面条件 iface=0 の同じ系列): 1: 2.5e-4 / 2: 7.8e-3 / 4: 1.4e-2 / 8: 2.8e-2 /
16: 6.7e-1。全ノード数で劣化し、時間とともに単調に増えた(失敗2)。

### 5.2 ADD(新規参加)— 4ノード、1000ステップ、ノード3が仮想時刻20秒(ステップ252)に右端へ参加

前提の用語: **解釈β**とは、M-S1a で決めた「不在の隣は『まだ存在しない領域』とみなし、
その面を温度0の外部境界として計算を止めずに進め、参加したときに界面へ切り替える」意味論。
参加ノードは初期温度 sin(πx) で編入される(引き継ぐ過去はない)。

| 条件 | 最終の最大誤差 vs composite | 参加ノードの誤差: ピーク → 最終 | 隣接ノード2の回復時間(誤差が参加前の2倍未満に戻るまで) | 界面残差のピーク / 回復 |
|---|---|---|---|---|
| 温め50反復(既定) | 5.1e-3 | 1.4e-1 → 5.1e-3 | 未回復(1.2e-3 → 3.7e-3) | 7.3 / 3ステップ |
| **温めなし(白紙、--add-warm 0)** | **1.3e-3** | 1.8e-1 → 1.1e-3 | 395ステップ | 9.5 / 4ステップ |
| 中間参加(ノード1が参加、温め50) | 1.2e-1 | 2.6e-1 → 9.6e-2 | — | 12, 19 / 6ステップ |

**界面残差**とは、界面の両側のノードが送り合う「端の傾き」の食い違い |grad_A − grad_B|。
追加の通信なしで計れる「界面のずれ」の指標で、M-S1c で自動トリガーの入力にする予定。
平常時は 0.3〜0.5、参加直後に 7〜19 まで跳ね、数ステップで戻った。

**注意(この試験の限界)**: 参加ノードの誤差ピークが 1e-1 台と大きいこと、中間参加の最終誤差が
大きいことは、ADDの仕組みの乱れではなく、**試験設定に由来する**。解釈βでは参加前の
不在面の温度が0に固定され、その隣の格子点は sin ≈ 0.7〜1 なので、参加した瞬間の温度分布に
**段差(不連続)**がある。差分法の複合参照解は段差をそのまま扱えるが、滑らかな関数しか
表せないNNは段差を表現できず、その付近で大きく外れる。温めが白紙より悪いのも、段差のある
標本に無理に合わせるため。この分離ができない点は6章の未解決事項に回した。

### 5.3 GROW / SHRINK / handover — 4ノード、1000ステップ、ノード1、仮想時刻20秒(ステップ251)

**機能保存**とは、「NNを変形する前と後で、NNが表す関数(位置 x を入れたときの出力温度)
が変わらないこと」。検査は、変形の直前と直後に全格子点(このノードは16点)で dyne_eval を
呼び、出力が何点ビット一致したかで行った。

| 操作 | 機能保存(16点中のビット一致点数) | 最終の最大誤差 vs analytic | 乱れ(誤差のピーク) | 補足 |
|---|---|---|---|---|
| なし(基準) | — | 5.4e-5 | — | 各ノードの定常誤差 1〜2e-5 |
| GROW 幅16→24 | **16/16** | 3.0e-5 | 7.7e-5(350ステップ後、緩やか) | 乱れは実質なし |
| SHRINK 幅16→8(温め50) | 0/16 | 2.4e-4 | 緩やかに 3.7e-4 まで上昇 | 幅8の表現力不足が主因 |
| SHRINK 幅16→8(温めなし) | 0/16 | 1.1e-4 | 直後に 1.0e-3 → 110〜540ステップで回復 | 温めなしの方が最終誤差は小さい |
| handover(ノード2が30秒で離脱、31秒で復帰) | 再初期化(重みを失い、標本から温め直し) | 1.1e-4 | 定常誤差が 2e-5 → 1e-4 | 重みを失う代償は約5倍の誤差 |
| 同上+通信欠落10%+遅延4±5ms | 同上 | 9.7e-5 | 同上 | 2回実行して全出力が一致(決定論) |

**handover**とは M-S1a の機構で、ノードが離脱するときに温度の標本 u[] を取り出し、
復帰時に新しいインスタンスへ書き戻すこと。学習型ではNNの重みは運ばれないので、
復帰後のNNは乱数から標本への温めで再構成される。

## 6. 知見と、次への引き継ぎ

### 6.1 知見

1. **「状態=格子点上の標本、重みは運ばない」は学習型でも成立した**。handover・ADD・
   境界切替のすべてが差分法と同じホスト側の機構で動いた。重みを失うコストは誤差5倍程度で、
   温めで回復する。
2. **GROWは設計どおりビット単位の機能保存**を達成した。B-16設計書の「機能保存の原則」を、
   NNで初めて「ビット一致」という厳密な形で検査できた。
3. **精度の劣化は「1ノードあたりの残差評価点が4〜5点」で顕在化する**。界面の通信形式を
   変えずに打てる手として、格子点の中点も残差評価点に加える(アクター内部だけの変更)がある。
   AB-PINNs記録2.5節の対策候補(観測者PCが粗い全域モデルを配る/階層的アクター/用途を
   局所現象に限定)より先に試す価値がある。
4. **温めは、標本が滑らかならほぼ無害、段差があれば有害**。先行研究(ADD-PINN)の
   「200エポック・2,000点」はLM法では過剰で、既定50反復(実測では20〜30で収束)にした。
5. **界面条件は時間整合性が決め手**(失敗2)。

### 6.2 未解決・次への引き継ぎ

- **解釈βのADD試験は初期状態に段差があり、NNの誤差とADD機構の乱れが分離できない**。
  対策候補: (a) 参加ノードの初期温度を「隣接の端点値からの補間」など連続なものにする
  (仕様の意味論の変更なのでユーザー判断)、(b) 解釈α(不在の隣を『まだ来ていない参加者』
  とみなし界面で待つ)のADDを実装して比較する。
- **16ノード時の劣化への対策**(知見3の中点追加を第一候補に)。
- **ESP32に載る構成**(メモリ250KB以内)の検討はM4の項目へ。行列を持たない反復解法に
  するか、幅を落とすか。
- **M-S1c(自動トリガー)へ**: 学習型でも界面残差は記録できている。ADD時のピークと平常値の
  比(20〜40倍)は差分法より大きく、閾値を「界面ごとの平常値に対する相対値」で決める設計
  (M-S1a知見)の材料になる。

## 7. 用語集(五十音順)

- **アクター**: 自分の担当区間の計算だけを行う独立した計算部品。通信は知らない。
- **Adam(アダム)**: NNの学習で広く使われる最適化器。勾配の大きさを正規化して更新する。
- **解析解**: 方程式を式変形だけで解いた厳密な答え。今回は exp(−απ²t)·sin(πx)。
- **界面**: 隣り合う担当区間の境目。ここで値と勾配を交換する。
- **界面残差**: 界面の両側が送り合う傾きの食い違い |grad_A − grad_B|。ずれの指標。
- **界面条件**: 学習の目標のうち、界面で「隣とどう繋がるべきか」を表す条件。
- **解釈α / 解釈β**: 不在の隣の扱い方。α=まだ来ていない参加者(界面で待つ)、β=まだ存在
  しない領域(温度0の外部境界として進める)。M-S1a で決定。
- **学習**: NNのパラメータを、目標(損失)が小さくなるよう少しずつ調整すること。
- **学習型アクター**: 中身をNNの学習で計算するアクター(本レポートの主役)。
- **格子点**: 棒を等間隔に区切った点。温度はこの点の上の数列として扱う。
- **機能保存**: NNを変形する前後で、NNが表す関数(入力→出力の対応)が変わらないこと。
- **GROW / SHRINK**: NNの隠れ層の幅を増やす / 減らす操作(B-16設計書のオペレータ)。
- **決定論**: 同じ入力なら必ず同じ出力になる性質。ここでは「ビット一致で再現」の意味。
- **勾配**: (1) 温度の空間的な傾き。(2) 損失をパラメータで微分したもの(学習の方向)。
- **後退オイラー法**: 時間を進めるとき、次の時刻の値を使って変化率を評価する離散化法。
  安定性が高い。今回の残差 r(x) はこの形。
- **誤差**: 計算結果と正解(解析解や参照解)との差。損失とは別。
- **差分法**: 微分を格子点の差で近似して方程式を解く古典的な数値計算法。
- **参照解**: 比較の相手。single(全域1ノード)/ composite(差分法の複合参照解)。
- **残差(方程式の)**: 方程式の左辺−右辺。方程式を満たしていれば0。
- **時刻離散化PINN(Rothe法)**: 時間を先に dt 刻みにし、各時刻の空間分布だけをNNで表す方式。
- **ジェット**: 関数の値・1階微分・2階微分の組を一緒に前向きに計算する手法。
- **状態移送**: ノード間・インスタンス間で格子点上の温度の標本を運ぶこと。
- **損失(loss)**: 学習で最小化する量。方程式残差や境界条件のずれの二乗和。
- **粗い補正**: 領域分解法で、全域を粗く近似した解を使って各区間の解を修正する仕組み。
  これがないと区間数Nの増加とともに収束が悪くなることが理論的に知られている。
- **DD-PINN(領域分解PINN)**: 区間ごとに別のPINNを持ち、界面条件で繋ぐ方式。
- **tanh**: 双曲線正接。−1〜1の滑らかなS字関数。NNの活性化関数として使用。
- **handover**: 離脱時に状態を取り出し、復帰時に新インスタンスへ書き戻す機構(M-S1a)。
- **PINN**: 物理情報ニューラルネットワーク。物理方程式を満たすように学習するNN。
- **BSP**: 全ノードが1ステップずつ足並みを揃えて進む同期方式。
- **幅 / 層数**: NNの隠れ層1つあたりのニューロン数 / 隠れ層の数。
- **複合参照解**: 参加イベントの時系列を1本の配列上で差分法で再現した参照解(M-S1a)。
- **ホスト**: アクターを動かし、通信・同期を担う側のプログラム。今回はシミュレータ。
- **ヤコビ行列**: 各残差を各パラメータで微分した値を並べた行列。LM法の中核。
- **LM法(レーベンバーグ・マルカート法)**: 非線形最小二乗の標準的な最適化手法。
  ガウス・ニュートン法に減衰項を加え、安定と速さを両立する。
- **温め(warm-up)**: 乱数初期化されたNNを、まず与えられた標本に合わせて学習させること。
- **wasmi**: シミュレータが使うWASMの実行エンジン(通訳方式)。
- **WASM(WebAssembly)**: CPUやOSに依存しない中間形式のプログラム。アクターの配布形式。
- **libm**: 純Rustで書かれた数学関数(tanh, sqrt など)のライブラリ。環境によらず同じ結果。
- **Linf / L2**: 最大誤差 / 二乗平均平方根誤差(2.3参照)。
- **no_std**: Rustの標準ライブラリを使わないモード。マイコン向けの制約。
- **乱れ / 回復時間**: 構成変更の直後に誤差が跳ねる大きさ / 元の水準に戻るまでのステップ数。
