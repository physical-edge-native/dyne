# 2026-08-16-M2完了レポート(docs\2026-08-16-m2-report.md)— 限界レポート第4号

## 目的と結果

M2の目的: 実機ESP32を2台、Wi-Fi直結(ノードAがアクセスポイント)で接続し、
M0で確立した境界同期プロトコルを本物の無線上で成立させ、シミュレータ校正用の
無線実測値を採取する。

**結果: 合格(2026-08-16)。** 両ノードのCRC32が期待値と一致
(A=0x3CC6AD26 / B=0x8AC47DE7、いずれもMATCH)。すなわち**無線越しの2台協調
推論が、単一ノード解とビット完全一致**した。M0(PC・2プロセス)→M-S0(シミュレータ
・16ノード)→M2(実機・無線)と、3つの実行形態すべてで同一の解が得られたことになる。

USBデータケーブル1本での運用も成立: ノードBは終了後に自分のレポートを
Wi-FiでAへ送り、Aのモニタが両ノードぶんを表示した(観測の中継の最小形。
A-5の観測者設計の先取り)。

## 知見

1. **至近距離の直結Wi-Fiは事実上無損失**。2000回の境界交換で再送0・CRC誤り0。
   ロス率の上限はおよそ0.05%未満。プロトコルの再送機構は今回出番がなかったが、
   起動順の吸収(Aの12秒待ち→Bの初着信で自然合流)はプロトコルどおり機能した。
2. **1往復あたりの実効遅延は中央値6〜7ms、95%点で18ms**。ただし最大は
   94〜99msで、タイムアウト設定(100ms)の直下に張り付く事象が稀にある。
   Wi-Fiの下位層の再送やビーコンとの干渉と推定。タイムアウトを100msより
   詰める場合は無駄な再送が増えることを意味する(B-3の設計材料)。
3. **計算時間はM1実測と一致**(79.4〜79.9 vs 79.5ms/ステップ)。通信を積んでも
   計算速度は不変で、M1の校正値の再現性が確認された。
4. **メモリの綱渡りは渡り切った**。懸念だった「アクセスポイント役+線形メモリ
   128KB」はA側で最小空き26KBを残して成立。軽量版wasmへの切替は不要だった。
   AP役は子機役よりヒープを約6.5KB余分に食う(非対称性の初の実測値)。
5. **シミュレータ校正の初回ループが閉じた(B-17)**。実測遅延(中央値6.5ms相当)を
   M-S0に注入したところ、予測オーバーヘッド11.8% vs 実測9.5%。初回の校正と
   して十分な一致であり、「シミュレータで設計→実機で校正」の往復が実証された。

## 開発過程の記録(再発防止)

- **fast-interp既定値の罠(再発)**: 新規プロジェクトのためWAMRの通訳モードが
  既定のFastに戻り、M1と同一の「allocate memory failed」が再発。Classicへの
  切替で解決し、`CONFIG_WAMR_INTERP_CLASSIC=y`を**両プロジェクトの
  sdkconfig.defaultsに恒久化**した(以後、環境を作り直しても再発しない)。
- 実機コンパイラの整数型幅差によるprintf書式エラー1件(uint32_tのキャスト漏れ)。
- COMポート占有(モニタの閉じ忘れ)による書き込み失敗1件。いずれも手順書の
  トラブルシューティングでカバー済みの事象。

## M-S0への校正値(確定)

| シミュレータ引数 | 注入値 | 根拠 |
|---|---|---|
| --step-ms | 79.5 | M1/M2実測(79.4〜79.9) |
| --lat-ms / --lat-jitter-ms | 4 / 5 (平均約6.5ms、上振れ考慮) | 同期待ち分布(中央値6-7ms、p95=18ms) |
| --loss | 0.0(直結・至近) | 再送0/2000。距離・干渉条件を変えた再測定は将来課題 |
| --timeout-ms | 100 | 実測最大待ち99msの直下。これ未満に詰めると偽タイムアウト増 |
